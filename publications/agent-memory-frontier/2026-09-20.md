## 1. Correct Now, Insufficient Later: Auditing Update Sufficiency in Context Compression

**中文译名：** 当前正确，未来不足：审计上下文压缩应对后续更新的充分性

**方向：** Agent Memory

**排名：** #1

- **日期：** 2026-09-17
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 直接检验压缩记忆在未来更新、撤销和历史回退中的状态充分性。
- **入选理由：** 提出可复现的配对历史审计，并严格区分存储错误、读取错误与输出格式错误。

### 一句话概述

长会话压缩可能保留当前答案却丢失未来更新所需的历史差异，该工作通过“当前等价、未来可区分”的配对历史审计来检测这种不足。

<details>
<summary>论文摘要翻译</summary>

一份记忆可以正确回答当前查询，却丢弃后续更新所需要的差异。我们使用配对历史审计研究这种失效：两段历史具有相同的当前答案，接收相同的未来更新，之后却需要给出不同答案。一项试验在六种合成机制、十二种记忆条件、两次重复和两个模型后端上评估了二十四对历史。确定性的 frontier 选择器在 DeepSeek 上取得 96/96 的严格揭示准确率，在 GLM 上取得 82/96；结构化写入器分别获得 62 次成功（另有一次未解决结果）和 56/96。预设的四结果联合对比得到 [0.521, 0.542] 与 [0.292, 0.313] 的有限样本识别区间，而非置信区间。记录级审计区分了保留状态是否充分、响应是否成功送达以及答案是否符合模式，同时不改变原始分数。审计发现，结构化揭示记忆中分别有 26 和 25 条格式正确但语义错误；GLM 上 frontier 的 14 次揭示失败则都包含正确值，只是包装格式错误。移除墓碑记录会在目标机制中造成 16/16 的精确重放失败。随后，标识符重命名暴露出另一缺陷：原始 frontier 的延迟引用充分性从 8/8 降至 320 个变换实例中的 94 个。我们提供并测试了一个标签等变修复，但它只保住了 8 个原始延迟引用答案中的 2 个：消除命名捷径并不能解决未来相关性未知的问题。这些结果支持一种范围受限的评估方法和可复现的故障分析，而不证明修复算法具有普遍优越性。付费试验的证据、回顾性诊断和新的离线测试被分别报告；论文不声称拥有独立留出集或自然任务验证。

</details>

<details>
<summary>现存问题</summary>

多数压缩评估只检查压缩当下能否回答问题，无法发现旧值、撤销标记或依赖关系在未来事件到来后才变得必要的情况。

</details>

<details>
<summary>已有方法的不足</summary>

最近值保留、尾部截取和模型生成摘要可能在当前答案上表现正常，却碰撞为相同的压缩状态；论文也明确说明其本地基线并未复现 ACON、TRACE 或 MEMAUDIT 的最佳配置，不能据此宣称全面优越。

</details>

<details>
<summary>当前方法为什么可行</summary>

配对构造先固定当前查询输出，再向不同隐含历史施加同一未来事件，使被压缩掉的差异成为可观察错误；事件解释器和记录级交叉分类进一步将错误定位到保存内容、响应送达或答案包装。证据来自小型符号开发集，尚无自然长程 Agent 任务验证。

</details>

<details>
<summary>未来展望</summary>

作者提出冻结评估契约后进行前瞻性确认，并强调需要独立留出和自然任务验证。编辑推断：该审计可扩展到生产记忆的撤销、过期与依赖闭包测试，但论文当前证据不足以确认其在开放式轨迹和真实工具调用中的外部效度。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.20045)

## 2. RAFT: A Stateful Retrieval-Augmented Framework for Troubleshooting Agents

**中文译名：** RAFT：面向故障排查 Agent 的状态化检索增强框架

**方向：** Agent Memory

**排名：** #2

- **日期：** 2026-09-18（北京时间提交）
- **状态：** 已接收 EMNLP 2026 Industry Track；arXiv v1
- **Agent Memory 相关性：** 把历史案例轨迹结构化为可按当前调查状态检索的情景记忆。
- **入选理由：** 正式接收、问题定义清楚，并同时提供合成受控评测与真实 Jira 方向性验证。

### 一句话概述

传统 RAG 无法按排障进程匹配多阶段历史案例，RAFT 将案例抽象为状态转移时间线并从匹配的中间状态返回连贯的父案例轨迹。

<details>
<summary>论文摘要翻译</summary>

企业客户支持中的有效故障排查 Agent 依赖从相似历史案例中检索可执行指导，但现有检索增强生成系统把支持案例视为静态文档，忽略了其多阶段、状态化的性质。我们提出 RAFT（Retrieval-Augmented Framework for Troubleshooting Agents），一种状态化 RAG 框架：它把每个已关闭历史案例抽象为由时间线条目组成的有向链，在条目层进行检索，找出中间状态与当前案例匹配的案例，并返回以匹配状态为锚点的父案例轨迹；一个可选的案例级图通过可配置的相似性表示连接案例。我们直接评估这一检索层，因此不同于完整 Agent 系统评估，不需要生产部署。由于公开的多阶段故障排查数据极少，我们将一个基于 Microsoft Learn Windows Server 文档构建的合成基准，与带有人类创建重复标签的真实 Apache Jira 问题结合使用。RAFT 在案例进展的每个阶段都比普通 RAG 和 GraphRAG 基线获得更高的 Case Hit，对最强基线的提升具有统计显著性；Jira 结果提供了该优势可迁移到真实案例历史的方向性证据。我们发布基准、实现和 Apache Jira 评测集。

</details>

<details>
<summary>现存问题</summary>

排障案例由症状、假设、日志、诊断动作和修复结果逐步演化；静态文档检索难以匹配当前阶段，也容易返回噪声片段、不可执行案例或含敏感信息的原始内容。

</details>

<details>
<summary>已有方法的不足</summary>

普通 RAG 直接切分原始案例，片段缺乏轨迹连贯性；通用 GraphRAG 主要围绕实体关系建图，不能保证保留调查状态转移及形成完整排障路径所需的证据。

</details>

<details>
<summary>当前方法为什么可行</summary>

增量抽取器把案例整理为有审阅状态、时间线、根因和修复步骤的结构，再以当前调查条目匹配历史中间状态并回传完整轨迹，从而让检索上下文同时具备阶段相关性和过程连贯性；受控基准及小规模真实 Jira 数据支持检索层改进，但未验证最终诊断或工程师生产力。

</details>

<details>
<summary>未来展望</summary>

作者明确指出需要在更大生产语料、更多真实重复组以及端到端诊断和解决结果上继续验证。编辑推断：这种按状态检索的情景记忆可迁移到运维、代码修复和多轮客服，但敏感信息过滤与抽取错误传播仍需独立审计。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.20754)

## 3. An Empirical Study of Harness Design for Coding Agents

**中文译名：** 编码 Agent Harness 设计的实证研究

**方向：** 相邻研究

**排名：** #3

- **日期：** 2026-09-18（北京时间提交）
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 直接测量工作记忆压缩、外部召回和持久计划在长程 Agent 中的条件性作用。
- **入选理由：** 在固定执行循环下完成大规模组件消融，能区分上下文管理与规划、工具接口的作用。

### 一句话概述

编码 Agent 的长程表现常被整套 Harness 掩盖，该研究固定执行循环并分别改变上下文管理、规划与动作空间，以识别各组件在不同模型和预算下解决的瓶颈。

<details>
<summary>论文摘要翻译</summary>

编码 Harness 决定自主编码 Agent 如何把模型能力转化为长程软件工程表现，但现有研究通常把 Harness 作为整体评估，使各组件的有效性不清楚。为进行组件级比较，我们使用一个执行循环固定、但规划、动作空间和上下文管理三个组件可变的轻量编码 Harness 研究这一问题。我们在 SWE-Bench Verified 和 Terminal-Bench 2.1 上评估四个模型，共覆盖 176 个匹配设置，包括五种上下文管理策略、四种上下文窗口预算，以及针对规划和动作空间的定向消融。我们发现：（1）上下文窗口预算越紧，上下文管理越有价值，其大部分收益来自防止上下文溢出失败；（2）先进行基于规则的省略，再进行基于 LLM 的摘要，在上下文管理策略中具有最佳总体效率，而让被省略内容可恢复会增加模型很少使用的机制，且没有带来准确率提升；（3）规划会从较弱模型的准确率支架转变为较强模型的成本节省器，而准确率变化很小；（4）预定义工具可提升 bash 能力较弱模型的表现，而具备 bash 能力的模型使用纯 bash 接口也能有效工作，并能显著降低成本，尤其是在以命令行为中心的任务上。轨迹级分析解释了这些效应：上下文管理延长执行轨迹，却基本不改变 Agent 行为；规划改变轨迹在何处停止；动作空间改变代码写入的粒度。这些发现为按模型和预算设计 Harness 提供依据，也提供了评估未来 Harness 组件的模块化框架。

</details>

<details>
<summary>现存问题</summary>

Agent 的工作历史持续膨胀，而规划、工具接口和压缩策略相互耦合；整套系统对比无法判断失败究竟来自上下文溢出、过早停止还是动作接口不匹配。

</details>

<details>
<summary>已有方法的不足</summary>

既有 Harness 研究多把整套架构作为单一处理，动态上下文管理方法也常只在单一模型上作为增强项评估，因而没有刻画其对窗口预算和模型能力的依赖。

</details>

<details>
<summary>当前方法为什么可行</summary>

研究固定 ReAct 循环和辅助组件，只改变规划、动作空间与五档上下文策略；其中分级策略先将大型工具输出替换为存根并外存，达到更高阈值后再摘要旧事件。跨窗口、模型和任务的匹配消融与轨迹分析将收益定位为避免溢出、延长执行或改变停止行为。

</details>

<details>
<summary>未来展望</summary>

作者要求在更多模型家族、Harness 实现、非软件工程任务和完整组件组合上验证，并指出当前动作空间干预仍捆绑了工具、提示、状态跟踪与诊断。编辑推断：未来 Agent Memory 评测应把压缩策略与模型能力、窗口预算联合报告，而不能只给单点成绩。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.20804)

## 4. LIMBO: Lifelong Inference-Time Memory and Budget Optimization for LLM Agents

**中文译名：** LIMBO：面向 LLM Agent 的终身推理时记忆与预算优化

**方向：** 历史高价值回填

**排名：** #4

- **日期：** 2026-09-13（北京时间提交）
- **状态：** 已接收 ICTAI 2026；arXiv v1
- **Agent Memory 相关性：** 把经验回放选择与推理预算联合建模为在线记忆资源分配。
- **入选理由：** 近期唯一项不足后的高质量回填；正式接收且提出区别于记忆表示的新控制层问题。

### 一句话概述

终身 Agent 的经验回放会与推理和工具使用争夺有限预算，LIMBO 用在线上下文 bandit 按任务联合选择记忆策略和推理资源。

<details>
<summary>论文摘要翻译</summary>

随着 LLM Agent 被集成进日益复杂的工作流，它们必须持续获得新能力，同时保留对先前已学任务的胜任能力。终身 Agent 通过经验回放解决这一问题，即在推理时把过去交互注入提示以利用既有经验。然而，回放并非免费：每条被回放的轨迹都与检索、推理、工具使用和验证争夺同一份有限的提示与计算预算，因此有效的资源分配至关重要。现有方法使用固定回放策略分配这些资源，而不考虑回放对当前任务是否有益。我们把这识别为“推理时记忆分配”这一终身 Agent 的独立问题类别，并提出 LIMBO；据我们所知，这是首个把记忆作为可控推理时资源、并为每个到来的任务联合优化记忆策略和推理预算的在线框架。不同于固定回放策略或需要模型权重、教师监督和离线再训练的方法，LIMBO 以单遍在线方式学习这种分配，在不修改底层 Agent 的情况下显式平衡任务表现与推理成本。在 LifelongAgentBench 的三个 LLM 骨干上，LIMBO 获得了优于先进记忆增强基线的成本—准确率权衡，并能以最高约低 83%、平均约低 53% 的推理成本接近所有最强基线。LIMBO 无需再训练即可让策略适配不同模型和环境，表明有效分配可以在线学习，而不必手工指定。

</details>

<details>
<summary>现存问题</summary>

成功轨迹不断积累时，固定经验回放会线性增加注入内容；某段经验是否有用又取决于当前任务、模型和环境，造成记忆价值与上下文成本不匹配。

</details>

<details>
<summary>已有方法的不足</summary>

固定回放不按任务分配资源；压缩可能破坏交互轨迹的动作结构；选择性回放或部分记忆方法需要模型权重、离线训练，或只优化“检索什么”而不决定“是否值得回放以及配多少预算”。

</details>

<details>
<summary>当前方法为什么可行</summary>

LIMBO 在执行前用提示形态、运行状态和上一任务结果构成特征，由双头 LinUCB 分别估计正确性与成本，再选择无回放、完整、压缩或检索回放及对应预算；任务结束后的真实正确性与成本立即更新控制器，因此能随任务流适配而不改模型权重。

</details>

<details>
<summary>未来展望</summary>

作者指出更好的记忆表示可以作为新的回放动作接入 LIMBO，并把结果概括为对其他推理时资源进行成本感知在线控制的机会。编辑推断：后续应检验非平稳任务流、更丰富记忆操作以及成本权重变化下的稳定性；论文没有单列系统性局限章节，因此不宜外推为通用最优分配器。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.14138)

## 5. How Do Agent Harnesses Create Value? Planning Information and Release Control in Stateful LLM Agents

**中文译名：** Agent Harness 如何创造价值？状态化 LLM Agent 中的规划信息与放行控制

**方向：** 相邻研究

**排名：** #5

- **日期：** 2026-09-17
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 量化持久规划状态和终态验证如何影响长程执行及错误状态的放行。
- **入选理由：** 用字数匹配的 Sham 对照隔离规划内容，并把执行正确性与接受决策分开衡量。

### 一句话概述

Agent Harness 各组件的真实价值常被额外上下文和计算混淆，该研究用匹配的规划对照与只读终态验证分别测量执行指导和放行控制。

<details>
<summary>论文摘要翻译</summary>

Agent Harness 提供规划指导、组织执行并检查完成情况。我们研究这些组件如何影响 τ²-bench 中两项 Retail 实验和一项 Airline 试验的成功、错误接受与成本。主要比较将预先编写的任务专用计划（Fixed）与字数匹配的打乱政策文本（Sham）配对，从而隔离指导内容的贡献。在 265 个匹配单元中，Fixed 将经 oracle 验证的成功率提高了 7.17 个百分点（90% 按任务聚类的 bootstrap 区间为 1.15 至 13.36 个百分点），收益集中在复杂度较高的任务上。一个只读终态验证器拒绝了 61% 的 Retail oracle 无效 episode，同时拦下了 17% 的正确 episode，每个 episode 的额外成本低于一美分。哪个组件更重要取决于对错误接受赋予的损失：责任较低时，规划收益占主导；责任较高时，验证器避免错误放行的收益占主导；而独立验证器以完整“规划加验证”栈的一小部分成本，获得了几乎全部错误放行控制收益。

</details>

<details>
<summary>现存问题</summary>

规划、修复、记忆和完成检查共同塑造 Agent 行为，系统级成绩无法说明哪一组件改善执行、哪一组件只是阻止错误结果被接受，也无法反映它们的资源成本。

</details>

<details>
<summary>已有方法的不足</summary>

把带计划配置与最小配置直接比较会同时改变指导内容和上下文长度；只看任务成功还会把实际环境正确性、Agent 自称完成和系统最终放行混为一谈。

</details>

<details>
<summary>当前方法为什么可行</summary>

Fixed 与 Sham 在字数和包装上匹配，使主要差异落在任务专用指导内容；终态验证器只读取执行结果并单独决定是否放行，因此可将执行正确性与接受控制拆开。任务配对和按任务聚类的不确定性估计支持该归因，但 Airline 仅含少量任务。

</details>
