## 1. Memory Compression for High-Fanout Agent Sandboxes

**中文译名：** 面向高扇出代理沙箱的内存压缩

**方向：** 系统内存

**重要性排名：** #1

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 支撑并发轨迹沙箱的运行时状态承载与扩展。
- **入选理由：** 把代理生命周期和沙箱间冗余引入系统内存设计，机制完整且证据充分。

### 一句话概述

面向并发代理沙箱因共享模板与相近轨迹产生的内存瓶颈，AgentZip通过跨沙箱字典压缩、模板差分、恢复预取和生命周期感知调度压缩运行时内存。

<details>
<summary>论文摘要翻译</summary>

高扇出代理工作负载造成日益严重的内存瓶颈，因为单个任务可能生成许多并发沙箱会话；然而这些沙箱并非相互独立，它们源自共享模板并执行相关轨迹，因而存在大量相对于模板和跨沙箱的内存冗余。传统内存压缩在三个基本维度上不适合这一场景：在如何压缩方面，它们不能利用非完全相同沙箱页面之间的相似性；在压缩什么方面，它们通过保守的页面选择控制缺页开销；在何时压缩方面，它们要么由内存压力触发，要么不了解代理执行阶段。本文提出首个专为人工智能代理沙箱设计的内存压缩系统 AgentZip。它同时利用模板相对冗余和跨沙箱冗余，把压缩范围扩展到任何具有收益表示的页面，将开销控制从压缩时页面选择转移到恢复时预取，并把昂贵压缩安排在等待大语言模型期间，以免干扰前台工具执行。在大语言模型训练与推理工作负载上，AgentZip 将沙箱自有内存最多压缩至原来的八点七分之一，而 Linux 配置为二点一分之一；恢复预取和执行感知调度将激进压缩造成的最严重减速从三点一倍降至一点四倍，同时保留了几乎全部内存节省收益。

</details>

<details>
<summary>现存问题</summary>

高扇出训练和多代理推理会同时保留大量兄弟沙箱；共享模板、依赖与相近轨迹形成可压缩冗余，但常规系统仍按单页和通用冷热度管理，内存往往先于计算资源耗尽。

</details>

<details>
<summary>已有方法的不足</summary>

论文比较的主要类别包括 Linux 的 KSM、zswap、zram 以及基于冷热度的压缩策略。KSM 依赖页面完全相同，页内压缩看不到模板或兄弟沙箱间的近似相似性，冷热筛选又会放弃大量可能再次访问但仍值得压缩的页面。

</details>

<details>
<summary>当前方法为什么可行</summary>

AgentZip 先用共享字典、模板差分和页内编码为页面选择最省空间的表示，再允许压缩所有具有正收益的页面；恢复侧通过步幅、时序关联和请求热集预取降低缺页代价，调度器则在工具执行时轻量发现候选、在等待模型时完成重压缩。全文的工作负载测量、消融和开销分解共同支持这条机制链。

</details>

<details>
<summary>未来展望</summary>

作者将系统定位为高扇出代理基础设施，并提供与 E2B 风格接口的兼容设计。编辑推断：下一步应在更多沙箱实现、真实在线调度、不同兄弟轨迹相似度和更长运行周期下验证收益边界；论文现有证据不足以证明该策略能直接改善代理语义记忆质量。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.11294)

## 2. 2AM: Grounding Agent-Side Memory as Guidance for Steerable Action Models in Long-Horizon Manipulation

**中文译名：** 以代理侧记忆引导可控动作模型完成长程操作

**方向：** 具身记忆

**重要性排名：** #2

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 明确拆分任务记忆持有者与动作执行器，并定义跨时间尺度读取接口。
- **入选理由：** 直接回答具身代理的记忆应放在哪里以及如何进入动作控制。

### 一句话概述

针对长程机器人操作中动作模型难以同时承载任务记忆与精细控制的问题，该工作让多模态代理保管历史并把子任务语言和空间提示传给无状态动作模型。

<details>
<summary>论文摘要翻译</summary>

长程机器人操作需要记忆，但记忆不一定必须位于动作策略内部。为处理这类任务，现有代理系统经常把视觉语言动作模型与规划器和几何工具结合，有时还使用额外深度信息或标定几何；这些系统混淆了贡献归因，因为收益可能来自更丰富的观测或替代运动工具，而失败也可能源自动作策略或定义不足的语言接口。本文通过一个有意受限的设计隔离这一问题：减少工具广度，但增加接口带宽。该方法让多模态代理成为任务记忆的唯一持有者，让一个仅使用彩色图像、在回合间无状态的动作模型成为任务相关运动的唯一执行器。代理把交互历史编译为子任务语言，并可附加二维抓取、放置和移动提示，从不同时间尺度绑定其物理意图。为使视觉语言动作模型学会接受这种引导，作者为示范补充结构化提示标签，并在条件丢弃、空间噪声和时间抖动下训练，以容忍代理输出的不完美。在 LIBERO-Mem 上，该方法不使用深度、在线几何或基于规划器的物体运动，平均完成率达到百分之七十六点三，相比已报告最强基线的百分之十四点八增加六十一点五个百分点，同时取得百分之六十三的宽松成功率和百分之十一点八的严格成功率。这些结果表明，任务记忆可以保留在代理侧；它们还表明，动作模型能力不仅取决于策略学到了什么，也取决于代理能以多高精度引导它。

</details>

<details>
<summary>现存问题</summary>

长程操作要求持续记住目标、已完成步骤、当前物体关系和后续子任务，但把这些职责与低层运动控制混入同一策略，会使失败究竟来自记忆、接口还是动作能力难以判定。

</details>

<details>
<summary>已有方法的不足</summary>

论文针对把视觉语言动作模型与规划器、深度信息或在线几何工具组合的系统进行讨论。此类系统增加观测和运动工具后虽然可能完成任务，却无法隔离任务记忆本身的作用；单纯语言指令又可能不足以表达抓取点、放置点和移动方向。

</details>

<details>
<summary>当前方法为什么可行</summary>

多模态代理读取完整交互历史并负责保持任务状态，再把历史压缩成子任务语言以及可选的抓取、放置和移动提示；无状态动作模型只消费当前图像与这些提示。结构化提示监督使动作模型理解接口，条件丢弃、空间噪声和时间抖动使其能承受代理提示误差，消融与受限工具设置为这条归因链提供支持。

</details>

<details>
<summary>未来展望</summary>

作者强调任务记忆可停留在代理侧，以及接口精度会限制动作模型能力。编辑推断：可继续研究代理何时更新记忆、何时发出哪类提示，以及错误记忆如何传播到运动执行；当前证据来自特定模拟操作任务，尚不足以外推到开放世界机器人或长期真实部署。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.11308)

## 3. Mr.LHDR: A Benchmark for Multimodal Real-World Long-Horizon Deep Research Agents

**中文译名：** 面向多模态真实世界长程深度研究代理的评测

**方向：** 长程评测

**重要性排名：** #3

- **日期：** 2026-09-11（v2）
- **状态：** arXiv 预印本 v2；代码与数据已发布
- **Agent Memory 相关性：** 检查代理能否沿长依赖链维护证据状态和中间结论。
- **入选理由：** 提供过程级依赖标注，避免只用最终答案掩盖记忆与状态维护失败。

### 一句话概述

针对深度研究代理难以持续整合长依赖链与多模态证据的问题，该工作用隐藏节点关系图构造必须逐步完成中间结论的真实研究任务并按依赖检查过程。

<details>
<summary>论文摘要翻译</summary>

深度研究代理在网页搜索、工具使用、多模态证据分析和信息综合方面的能力不断增强，但现有评测主要覆盖中等长度的探索，很少检验代理能否维持漫长且依赖密集的研究过程。本文提出 Mr. LHDR，即多模态真实世界长程深度研究评测，覆盖八个类别，用于检验代理处理由相互依赖证据构成、无法缩短的长链条。每个问题都由一个隐藏的节点关系图构造，在得到简短、唯一且可验证的答案前，平均需要十二点一个必要中间结论，平均依赖深度为十点四。问题包含图像、地图、PDF、标志、图表、表格和视频帧等多模态证据，并至少包含一个会改变推理状态的非文本元素。Mr. LHDR 同时检查最终答案以及带标注依赖关系的中间结论是否正确。作者使用总体准确率、严格准确率、检查表得分和依赖感知检查表得分，评测通用模型、深度研究系统与代理框架。结果表明，即使最强系统的总体准确率也只有百分之四十三点一，严格准确率为百分之三十四点三，说明只看最终答案会明显高估完整研究成功率。移除图像会使依赖感知检查表得分下降十二点六个百分点，严格准确率也会随推理链变长而持续下降。这些发现揭示，持续且依赖一致地整合证据，而非孤立事实检索，是当前深度研究代理的关键瓶颈。

</details>

<details>
<summary>现存问题</summary>

长程研究必须跨网页、文档和视觉材料保存来源、实体关系、已验证结论及未解决依赖；只判最终答案无法识别代理是在何处丢失证据状态、跳过必要节点或偶然猜中。

</details>

<details>
<summary>已有方法的不足</summary>

论文指出现有深度研究评测多为中等长度探索，并主要依赖最终答案或扁平检查表。它们较少提供不可约依赖链、会改变推理状态的非文本证据，以及对每个中间结论与前置依赖的联合检查。

</details>

<details>
<summary>当前方法为什么可行</summary>

隐藏节点关系图先规定答案所需的证据节点和依赖顺序，题目再把这些依赖分散到真实多模态来源中；标注的中间结论让评分器同时检查局部正确性与依赖一致性。按链长、模态移除和不同评分口径进行的分析支持其确实暴露了持续状态维护问题。

</details>

<details>
<summary>未来展望</summary>

作者通过发布代码和数据为后续长程研究代理比较提供了基础。编辑推断：可进一步加入来源随时间变化、证据撤销、冲突更新和跨会话恢复，以直接测量记忆新鲜度与失效传播；当前材料不足以把该评测中的失败全部归因于记忆模块。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.11318)

## 4. SWRouter: Similarity-Contractive Window Routing for Multi-Turn Large Language Model Conversations

**中文译名：** 面向多轮大模型对话的相似度收缩窗口路由

**方向：** 上下文路由

**重要性排名：** #4

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 影响工作记忆的历史切分、保留和注入策略。
- **入选理由：** 把上下文构造质量与模型路由质量分离，便于诊断多轮记忆读取。

### 一句话概述

针对多轮对话路由中历史切分不当导致信息丢失或混淆的问题，SWRouter按语义相似度收缩上下文窗口并分离评估提示构造与模型选择。

<details>
<summary>论文摘要翻译</summary>

大语言模型具有互补优势，这推动了把每个查询分派给最合适模型的路由方法。现有路由器在单轮场景中有效，但不能直接迁移到多轮对话，因为路由表现关键取决于历史上下文如何切分、保留并纳入当前提示。这带来两个基本挑战：在上下文构造期间避免信息丢失与信息混淆，以及在不把模型选择与提示构造质量混为一谈的情况下评估路由质量。本文提出 SWRouter，一种用于多轮大语言模型路由的相似度收缩窗口路由器。SWRouter 将基于相似度的上下文切分机制用于提示构造，并采用双指标评估框架，把构造准确性与路由器表现解耦。多轮对话评测表明，SWRouter 持续超过强基线，相比最佳单个大语言模型的评估准确性增加百分之十六点二六，并在 Conv-ID Context 基线之上再增加百分之八点二二。结果强调，多轮大语言模型路由需要联合设计上下文构造与评估，而不能直接延伸单轮路由方法。

</details>

<details>
<summary>现存问题</summary>

多轮路由既要决定调用哪个模型，也要决定向该模型提供哪些历史；上下文过短会丢失依赖，过长或主题混杂则会引入干扰，使路由失败与记忆构造失败难以区分。

</details>

<details>
<summary>已有方法的不足</summary>

论文比较的相关类别包括单轮路由器、固定窗口历史和 Conv-ID Context 等多轮构造方式。单轮方法没有显式解决历史组织问题，固定或粗粒度上下文则无法随当前查询收缩到语义一致的对话片段；来源未声称覆盖所有代理记忆系统。

</details>

<details>
<summary>当前方法为什么可行</summary>

SWRouter 根据相邻对话内容与当前请求的相似关系构造收缩窗口，使保留历史围绕当前语义需求聚合；双指标框架再分别测量提示构造是否保留答案信息、路由器是否选对模型。对多轮任务的比较与分析支持联合设计而非直接复用单轮路由。

</details>

<details>
<summary>未来展望</summary>

作者主张多轮路由必须联合设计上下文构造与评估。编辑推断：这一框架可扩展到代理外部记忆的分段和检索路由，并加入时间、新鲜度与来源可信度信号；现有证据只覆盖多轮模型路由，尚未证明其适用于跨会话持久记忆。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.11414)

## 5. T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks

**中文译名：** 面向长程任务的终端代理强化学习

**方向：** 长程训练

**重要性排名：** #5

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 提供长轨迹训练、过程信用与精确策略回放能力。
- **入选理由：** 虽属相邻方向，但其长程训练稳定性和语料隔离直接影响经验内化研究。

### 一句话概述

针对终端代理在长程任务中训练不稳定且容易把能力迁移与题目记忆混淆的问题，该工作结合验证器过程奖励、精确令牌回放与隔离任务语料进行强化学习。

<details>
<summary>论文摘要翻译</summary>

代理使用正转向编码和科学发现等长程任务，其中终端任务尤其重要。本文提出 T1，这是一个总参数量为一千二百二十亿的混合专家模型，通过强化学习训练，可在云端沙箱的真实 shell 中为每个任务执行三百余轮工具调用，并由任务自身的验证器提供奖励。作者给出完整训练方案：首先，以激进热启动稳定演员—评论家训练，并使用密集过程奖励，按照通过验证器的绝对数量为轨迹评分。其次，通过 TITO 构造实现稳定优化：使用采样时的确切令牌标识训练，在轮次边界修复漂移，并回放展开阶段的路由选择，即记录采样器在每个混合专家层对每个令牌所选的专家并在训练时重放。第三，构造完全分布外的训练语料：隔离种子并合成与 Terminal-Bench 2.1 不相交的任务，以确保收益反映能力迁移而非对评测题目的过拟合。TITO 与 R3 共同把训练到推理的对数概率差从零点零二一降至零点零一三，并在损失区域实现令牌零漂移对齐。在 Terminal-Bench 2.1 上，该后训练流程把初始基础模型从百分之四十三点八提高到 T1 的百分之六十四解决率。在 Long-Horizon Terminal Bench 上，T1 达到百分之二十七点九，并超过 GPT-5.4 和 GLM-5.1。

</details>

<details>
<summary>现存问题</summary>

真实终端任务需要数百轮工具调用，强化学习必须跨长轨迹分配信用；混合专家模型还会因采样与训练时的令牌或专家路由不一致产生策略漂移，训练语料泄漏又可能掩盖真实迁移能力。

</details>

<details>
<summary>已有方法的不足</summary>

论文针对稀疏终局奖励、采样与训练不一致以及评测污染三类问题组织比较。只按最终通过与否奖励难以定位长轨迹中的有效步骤，普通重新计算无法复现采样时的专家路由，而未隔离训练任务会把记忆题目误当成能力迁移。

</details>

<details>
<summary>当前方法为什么可行</summary>

任务验证器把可执行结果转为过程奖励，热启动缓解长轨迹演员—评论家训练的不稳定；TITO 保留采样令牌并重放逐层专家选择，缩小训练与推理策略差异；隔离种子和合成任务则控制题目重合。概率差、令牌漂移和跨终端任务测试共同支撑这条训练链。

</details>

<details>
<summary>未来展望</summary>

作者提供的是面向长程终端代理的完整训练配方。编辑推断：可研究如何把外部轨迹记忆、技能库或失败摘要接入该训练过程，并检验经验内化后是否仍需部署期检索；论文当前没有隔离比较不同外部记忆结构，因此不足以判断最佳记忆生命周期方案。

</details>
