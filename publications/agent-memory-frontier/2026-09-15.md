## 1. LifeMem: Enabling Lifelong Experience Reuse for LLM Agents

**中文译名：** LifeMem：让大语言模型智能体实现终身经验复用

**方向：** 终身记忆

**重要性排名：** #1

- **日期：** 2026-09-11
- **状态：** EMNLP 2026 主会已接收；arXiv v1；代码与数据已发布
- **Agent Memory 相关性：** 覆盖轨迹写入、工作流聚类、技能抽取、增量演化与双层检索。
- **入选理由：** 直接处理跨环境经验迁移与长期积累干扰，机制覆盖完整记忆生命周期。

### 一句话概述

跨环境持续积累经验会使智能体难以迁移可复用知识并发生灾难性遗忘，LifeMem 按底层工作流聚类轨迹、局部蒸馏技能，并在新任务中联合召回技能与轨迹。

<details>
<summary>论文摘要翻译</summary>

大语言模型智能体被期望通过复用过去经验，在其生命周期中持续适应新任务和新环境；然而，现有基于记忆的智能体难以跨环境迁移可复用经验，并会随着经验累积遭受灾难性遗忘。为解决这些挑战，作者提出 LifeMem，一种让智能体能够在多个环境间迁移知识的终身学习框架。

在学习期间，LifeMem 根据底层工作流对累积的交互轨迹进行聚类，以抽取可复用技能。在推理时解决新任务时，智能体召回相关技能和轨迹来指导行动。作者在十个环境、超过一万三千个任务以及两千条新标注交互轨迹上开展实验。

结果显示，LifeMem 能够在终身学习中有效复用经验，既减少已学习任务上的遗忘，也改善跨任务迁移。进一步分析表明，任务流会影响学习，而在记忆中整合结构相似的轨迹有助于提升表现。

</details>

<details>
<summary>现存问题</summary>

异构环境具有不同的观察与动作空间，原始轨迹难以直接迁移；随着经验库增长，检索干扰又会降低旧任务经验的可达性，形成跨环境迁移不足与灾难性遗忘。

</details>

<details>
<summary>已有方法的不足</summary>

论文比较的相关类别包括参数内持续学习、基于语义相似度的轨迹检索和全局技能抽象。参数内方法成本高且依赖预设环境；轨迹检索难以跨动作空间复用；从未组织的全局经验池抽象技能则容易混入跨环境噪声。

</details>

<details>
<summary>当前方法为什么可行</summary>

LifeMem 先按功能工作流而非表层语义组织轨迹，再依据聚类规模和几何多样性细分记忆，并从每个局部簇蒸馏与环境无关的技能；推理时同时提供同环境轨迹和关联技能，使具体动作格式与可迁移原则分别发挥作用。跨环境、消融和任务流分析支持这条机制链。

</details>

<details>
<summary>未来展望</summary>

作者指出，大规模工业部署需要面向海量经验优化存储与检索，并提出轻量本地模型和近似检索等方向。编辑推断：还应检查聚类漂移、错误轨迹污染、技能版本冲突和记忆淘汰；当前证据尚不足以证明其在开放式长期部署中的稳定性。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.12655)

## 2. K-Bench: A Benchmark for LLM Unlearning in Agentic Deployments

**中文译名：** K-Bench：面向智能体部署的大语言模型遗忘评测

**方向：** 记忆安全

**重要性排名：** #2

- **日期：** 2026-09-11
- **状态：** arXiv 预印本 v1；评测已发布
- **Agent Memory 相关性：** 检查参数、提示与检索记忆的撤销是否覆盖代理全部可观察通道。
- **入选理由：** 揭示模型级遗忘证书无法直接保证部署态记忆撤销，定义了更严格的观察边界。

### 一句话概述

模型级遗忘检查忽略了秘密经推理、工具或检索通道继续泄露的问题，K-Bench 将秘密置于不同记忆载体并联合观察代理的推理、工具、检索、回答与摘要通道。

<details>
<summary>论文摘要翻译</summary>

TOFU 和 MUSE 等遗忘评测通过读取模型的最终答案来认证遗忘，其中模型只要拒绝回答就会被视为已经遗忘。作者表明，一旦模型被部署为智能体，这种模型级证书便不能直接迁移。为此，作者提出 K-Bench，用于衡量智能体部署中的大语言模型遗忘。

K-Bench 检查 ReAct 智能体暴露的全部六个通道，包括思维链、工具调用、工具观察和诱导生成的摘要。只要秘密出现在任一通道中，该查询就被计为泄漏。每次实验只把秘密放入智能体的三个来源之一，即模型权重、提示或检索存储。K-Score 针对每个来源分别计算，并且只有在智能体仍保持可用时才认可遗忘。

清除答案通道并不会使秘密变得不可恢复。在结构化检索中，秘密仍逐字存在于工具观察通道，总体泄漏率没有改变。当秘密位于提示或检索存储中时，TOFU 和 MUSE 报告没有泄漏，但部署后的智能体仍会在百分之二十二至百分之八十六的查询中泄漏秘密。

当秘密位于模型权重中时，所评估的二十种已发表方法没有一种被证明真正移除了它，只有一种输入破坏干预在既定观察器下达到选择性遗忘。排名最高的方法会随基础模型变化。一种拒答微调方法能够抵抗所评估的提取方式，但没有证据证明知识已被移除。

</details>

<details>
<summary>现存问题</summary>

Agent Memory 的敏感信息可能同时通过参数、系统提示或外部检索库进入推理，并沿思维、工具结果或摘要等非最终答案通道泄漏；只检查回答无法确认撤销是否真正生效。

</details>

<details>
<summary>已有方法的不足</summary>

论文针对 TOFU、MUSE 等最终答案导向评测及多类权重遗忘方法。前者把拒答视为遗忘且忽略代理中间通道，后者可能只是压制提取或损害代理可用性；论文明确不把受控权重案例外推为整个方法类别的结论。

</details>

<details>
<summary>当前方法为什么可行</summary>

K-Bench 把秘密分别写入参数、提示、文本检索和结构化检索载体，在同一 ReAct 执行链上观察六类通道，并以可用性门控的 K-Score 防止把系统崩溃误判为遗忘。载体隔离、多通道泄漏检查、保留集和退化控制共同建立了从秘密来源到部署行为的归因链。

</details>

<details>
<summary>未来展望</summary>

作者计划研究预训练记忆形成、多个载体同时保存同一秘密，以及攻击者跨通道拼接碎片的情形。论文也明确限制于合成个人信息、英语查询和特定写入方式；因此现有证据不足以证明结论覆盖真实多语言企业记忆系统。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.12808)

## 3. SAS: Simple Attention Sparsification via End-to-End Optimization of Context Ranking

**中文译名：** SAS：通过端到端上下文排序优化实现简单注意力稀疏化

**方向：** 上下文选择

**重要性排名：** #3

- **日期：** 2026-09-11
- **状态：** arXiv 预印本 v1；代码已发布
- **Agent Memory 相关性：** 改进有限注意力预算下对历史上下文单元的读取排序。
- **入选理由：** 虽属相邻方向，但直接改变长上下文工作记忆的选择目标与训练信号。

### 一句话概述

稀疏注意力的上下文选择器常按原模型注意力而非预测效用分配有限预算，SAS 把连续门控分数注入注意力并用语言建模目标端到端学习上下文排序。

<details>
<summary>论文摘要翻译</summary>

后训练注意力稀疏化通过为每个查询选择少量上下文单元，即词元或块，来降低预训练 Transformer 随序列长度二次增长的累计注意力成本。现有可训练方法通常使用轻量选择器为上下文单元评分，再执行阻断语言建模损失梯度的硬 Top-K 选择，因此这些方法通常蒸馏逐层稠密注意力分布。

这种做法会鼓励选择器按照原模型的稠密注意力权重排列上下文单元，但该排序并未直接对齐这些单元在固定注意力预算下对预测的影响，可能把有限预算浪费在较少有用的单元上。

为解决这种错位，作者提出简单注意力稀疏化 SAS，这是一种使用语言建模损失端到端优化上下文排序的门控稀疏注意力机制。其关键是在训练期间把选择器的连续分数注入注意力 logits，使损失可以通过标准反向传播更新选择器。

作者识别出让这一简单设计有效工作的若干关键选择：以对数形式把门放在注意力 softmax 内部；使用归一化 softmax 门校准历史上下文与始终保留的当前块；保留连续选择器分数，使模型学习相对优先级而非只有硬选择。为支持长序列训练，作者实现了把 SAS 集成进 FlashAttention 风格计算的内存高效 Triton 内核。

在推理、长上下文理解和智能体任务中，SAS 在不同注意力预算下持续超过可训练稀疏注意力基线，尤其在预算紧张时优势更大，表明其能为下游任务学习更有效的上下文排序。

</details>

<details>
<summary>现存问题</summary>

长上下文代理无法持续对全部历史进行稠密注意力计算，但稀疏读取若选错历史块，会在有限预算下丢失支撑当前预测的关键信息。

</details>

<details>
<summary>已有方法的不足</summary>

固定窗口、启发式 KV 选择与逐层稠密注意力蒸馏是主要比较类别。硬 Top-K 阻断任务损失梯度，逐层蒸馏只模仿原模型在哪里关注，忽略值向量贡献及跨层互补，也不直接优化预算约束下的最终预测。

</details>

<details>
<summary>当前方法为什么可行</summary>

SAS 将连续选择分数以对数门形式加入 softmax 内，使语言建模损失直接训练上下文选择器；归一化门处理历史块与当前块的尺度关系，连续排序保留相对优先级，融合 Triton 内核避免物化完整注意力矩阵。匹配骨干、选择器和训练资料的对照以及多类任务分析支持该机制。

</details>

<details>
<summary>未来展望</summary>

作者指出，超长上下文中的块级汇聚会丢失细粒度局部信号，而且选择器扫描和 Top-K 排序会逐渐成为主要瓶颈，因此更有表达力的块摘要和更高效的选择内核是明确方向。编辑推断：若用于外部 Agent Memory，还需加入时间、新鲜度和来源可信度；本文没有验证持久记忆生命周期。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.13141)

## 4. Tasks over Application Manuals: Revealing Gaps in Long-Horizon Procedural Reasoning for Language Models

**中文译名：** 应用手册任务：揭示语言模型长程程序推理的能力缺口

**方向：** 长程状态

**重要性排名：** #4

- **日期：** 2026-09-11
- **状态：** arXiv 预印本 v1；评测、数据与代码已发布
- **Agent Memory 相关性：** 检查代理能否跨长规则链维护全局状态、约束和完成进度。
- **入选理由：** 真实手册任务暴露了检索成功后仍会发生的状态漂移、漏步与无法回退问题。

### 一句话概述

现实任务要求模型在长篇权威手册中跨章节执行相互依赖的规则链，TAM 从临床编码和联邦量刑流程构造带人工核验答案的长程程序推理任务。

<details>
<summary>论文摘要翻译</summary>

大语言模型已在广泛的自然语言任务上取得强劲表现，近期评测也显示其越来越擅长多跳推理。然而，这些评测通常属于短程任务，只要求少量检索或推理步骤，对于模型在现实任务中的可靠性提供的证据有限；现实任务往往需要遵循长达数百页、包含复杂相互依赖规则的手册。

本文提出应用手册任务 TAM，用于评估长程程序推理。作者从两个领域整理真实任务：ICD-10-CM 临床编码，即把医疗状况映射为诊断代码，以及美国联邦量刑，即计算犯罪量刑指南结果，具体为犯罪等级，并提供经过人工核验的标签。

每项任务都要求遵循包含数万条规则的权威手册，跨不同章节执行一系列相互依赖的步骤，以产生精确答案。作者评估了通用提示方法，包括检索增强生成、ReAct 风格提示，以及基于 GPT-5 的智能体运行框架；最佳精确匹配表现仍然很低，ICD-10-CM 编码为百分之一，量刑任务为百分之十五点五。

这些结果表明，当前评测可能高估了大语言模型的推理能力，并遗漏了一个关键挑战：可靠遵循长程、基于规则的程序。完整 TAM 数据和代码已公开。

</details>

<details>
<summary>现存问题</summary>

真实程序任务要求代理记住已经采用的规则分支、累积变量、必做步骤和全局约束；早期锚点错误会沿后续步骤传播，而局部检索正确并不保证最终流程完整一致。

</details>

<details>
<summary>已有方法的不足</summary>

论文评估单次 RAG、代理式 RAG、ReAct 和 Agent Harness 等通用方案。这些方法能够找到局部相关材料，却缺少稳定的全局状态检查、完成性验证和错误回退；作者也说明比较未穷尽领域专用或经过训练的系统。

</details>

<details>
<summary>当前方法为什么可行</summary>

TAM 选取规则明确且答案可精确核验的临床编码与联邦量刑手册，由领域流程构造跨章节依赖任务并进行人工复核，再保存执行轨迹以区分全局不一致、未完成和遗漏必要元素。任务结构因此能把长程程序执行与普通短链检索区分开来。

</details>

<details>
<summary>未来展望</summary>

作者明确提出加强状态跟踪、最终提交前验证、早期错误后的修订或回退，并扩展到领域专用和微调系统。当前对象只覆盖两个规则明确、输出精确的领域，且检索与推理失败尚未完全解耦，因此不能把所有失败都归因于记忆模块。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.13005)

## 5. Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents

**中文译名：** 技能难题：为编码智能体优化仓库技能文档的经验教训

**方向：** 程序记忆

**重要性排名：** #5

- **日期：** 2026-09-11
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 涉及程序知识抽取、技能文档优化、版本一致性和真实效用测量。
- **入选理由：** 对技能记忆自动演化给出罕见的测量审计，并明确否定超出统计证据的增益结论。

### 一句话概述

仓库技能文档缺少能区分其实际效用的高难度任务，本文把合并请求回退到统一代码版本，并比较同一代理在有无候选文档时完成这些任务的差异。

<details>
<summary>论文摘要翻译</summary>

编码智能体越来越多地从 SKILL 中读取仓库知识；SKILL 是与代码一起进行版本管理的纯 Markdown 文件。近期工作通过针对评测优化文档来自动合成这些文件。裸仓库本身没有评测，而既有工作构造的合成任务又足够简单，以至于能力较强的智能体在没有任何文档时就已接近饱和。

作者挖掘更困难的任务：把仓库已经合并的拉取请求回退到一个统一冻结的基础提交，并根据同一智能体在使用候选文档时是否优于不使用文档来评分。在三个 Kotlin 仓库上，GEPA 找到的文档平均把该分数提高四点九个百分点，而 SkillOpt 找到的文档几乎回到起点，只比种子高零点一个百分点。

GEPA 的增益与既有工作使用同一优化器时报告的幅度相当，但在单个仓库所能提供的数据规模下，无法把它与智能体自身的运行间方差区分开来；要解决这一问题，需要的任务数量超过单个仓库历史所能提供的规模。文档本身看起来比得分更有说服力：一位仓库维护者在其中发现了只有实际参与项目工作才能获得的知识。

</details>

<details>
<summary>现存问题</summary>

自动优化技能文档需要任务分布和效用指标，但新仓库通常没有现成评测；若任务过于简单、版本分散或评分只看文档表面质量，优化器就无法判断知识是否真正帮助代理。

</details>

<details>
<summary>已有方法的不足</summary>

论文针对合成缺陷任务、二元通过率、轨迹裁判和直接文档打分等方案。简单任务会被强代理在空文档条件下解决；文档打分可能改善文本却不改变代理；按历史父提交构造任务还会把已过时的路径、命令和接口写入技能。

</details>

<details>
<summary>当前方法为什么可行</summary>

作者在同一冻结提交上反向应用真实合并变更，以失败测试作为任务规格，并固定模型、工具和限制，只改变 SKILL；候选轨迹再与同一任务的空文档轨迹配对，减少任务难度差异的混淆。结果同时显示文档可能包含专有知识，也诚实表明小样本增益无法与代理方差分离。

</details>

<details>
<summary>未来展望</summary>

作者界定的关键限制是：仓库历史经反向应用和测试验证后常不足以形成稳定的训练、验证与测试划分，单次代理运行成本又很高。编辑推断：后续需要更低方差的配对重复、跨语言仓库复现和知识时效检查；当前证据不足以声称任何优化器能稳定提升编码代理。

</details>
