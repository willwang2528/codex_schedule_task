## 1. Efficient Test-Time Adaptation through Human-AI Interaction

**中文译名：** 通过人机交互实现高效测试时适应

**方向：** 个性化记忆

**重要性排名：** #1

- **日期：** 2026-09-03
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 跨会话偏好记忆、程序技能与参数化长期适应
- **入选理由：** 把真实交互中的多通道人类信号转成可编辑记忆、技能、权重更新和个体化评估标准。

### 一句话概述

开放式专业任务中的个体标准往往难以预先写明，TAHI把跨会话的人类修改、反馈与评估标准持续整合进显式上下文记忆、技能、模型权重和演化量规。

<details>
<summary>论文摘要翻译</summary>

AI 智能体在群体规模的数据上训练，以编码横跨众多从业者的广泛能力。然而，它们生成的产物很少达到专业人士愿意以个人声誉担保的个性化标准。在成功标准异质且记录不充分的现实开放式任务中，个人专长恰恰体现在高于并偏离平均水平之处。实践中，反复的人机交互会显露用户无法预先完整说明、却会在多个任务中重复采用的标准。我们认为，这些跨会话交互数据是缩小智能体与个人专长差距的一种丰富而未充分利用的信号。本文提出通过人机交互进行测试时适应（TAHI），把这些信号整合进智能体上下文与权重，并通过持续演化的量规模块固化每位用户的训练和评估标准。我们在写作和视觉创作两个高实用价值领域、共 600 项任务上，让智能体适应 30 位个体。仅经过数十个任务，智能体的独立任务成功率提高了 4.5% 至 20.9%。同时，演化量规模块可作为可扩展的标注工具，所创建的评估量规比仅由语言模型或人类创建的量规多发现 16.0% 至 22.3% 的失败。尽管智能体按个体进行适应，作者还发现这些个性化智能体带来了最高 8.8% 的跨用户成功率提升。

</details>

<details>
<summary>现存问题</summary>

专业用户的判断标准常常是隐性的，并会在多次任务中通过改计划、改文件、纠正评价或补充反馈才逐步显露；当前智能体通常不会把这些跨会话信号稳定转成后续任务可用的个体专长。

</details>

<details>
<summary>已有方法的不足</summary>

仅靠智能体自我反思会因缺少外部新信号而趋于停滞，单次文本反馈也遗漏计划编辑、产物直接修改和量规纠正等信息；只增长上下文会占用窗口，而一次性生成的评价量规又难覆盖开放任务的真实标准。论文的比较集中于写作和视觉创作，尚不能代表所有专业场景。

</details>

<details>
<summary>当前方法为什么可行</summary>

TAHI先把每次人机协作产生的多通道轨迹流式归纳为事实或偏好记忆与程序技能，同时可用最终产物相对初始产物构造偏好对，对 LoRA 权重执行 DPO；另一条量规演化链把用户行为转成可检查标准并允许用户纠错。30 位个体、600 项任务以及同类留出任务支持其跨会话适应能力，但证据仅来自两个产物型领域和有限交互轮次。

</details>

<details>
<summary>未来展望</summary>

作者明确主张继续研究更先进的测试时适应方法，并系统记录和评测社区级与个体级专长。编辑推断：若用于长期 Agent Memory，还需要研究偏好遗忘、冲突合并、隐私治理和用户纠错后的可逆更新；本文尚未验证这些能力。

</details>

**原始来源：** [arXiv 2609.04141](https://arxiv.org/abs/2609.04141)

## 2. SimSkill: A Lifelong Learning AI Agent for Autonomous Mastery of Traffic Simulation

**中文译名：** SimSkill：面向交通仿真自主掌握的终身学习 AI 智能体

**方向：** 终身技能记忆

**重要性排名：** #2

- **日期：** 2026-09-03
- **状态：** arXiv 预印本 v1；代码与实验数据已发布
- **Agent Memory 相关性：** 情景、程序和语义记忆的写入、整合、检索与修订闭环
- **入选理由：** 给出从环境探索到可审计持久能力的完整终身记忆闭环，并如实报告模型依赖和成本边界。

### 一句话概述

智能体难以把一次次环境交互积累成可复用能力，SimSkill通过自动发现能力缺口、执行并校验任务，再把经验整合为情景、程序和语义记忆来形成持续演化的技能库。

<details>
<summary>论文摘要翻译</summary>

随着大型语言模型能力不断增强，AI 系统的长期价值不仅取决于解决单个请求，也取决于把经验和累积知识转化为持久、可复用的能力。作者提出 SimSkill，一个围绕城市交通仿真器 SUMO 构建的自我演化智能体。SimSkill 识别能力缺口，生成并解决有环境依据的任务，通过动作—批评者循环验证解决方案，并在不更新骨干模型的情况下把经验整合为情景、程序和语义记忆。通过自主探索，它建立了覆盖交通仿真工作流的可复用库。作者使用三个骨干大模型，在两个留出基准上进行评测，并采用独立的、基于产物的验证。SimSkill使经验证的完成率最高提高 25 个百分点，消融实验显示程序记忆与语义记忆具有互补贡献。其收益依赖骨干模型与预算：记忆并非改善每个模型，也不会一致降低推理成本。更广泛地说，SimSkill展示了一种设计范式：用自然语言保存并组合计算能力，同时以可执行工具和代码提供精确、可复现的执行。所有代码和实验数据均已公开。

</details>

<details>
<summary>现存问题</summary>

多数智能体把每次复杂工具任务当作孤立请求，成功和失败轨迹在会话结束后无法沉淀为可检查、可修订、可跨任务组合的长期能力。

</details>

<details>
<summary>已有方法的不足</summary>

面向单次请求的深度研究流程不以长期能力积累为目标；仅做参数更新难以局部检查、归因和修订，仅保留情景记录又不足以形成程序与领域规律。论文把 Voyager 式探索扩展为三类显式记忆，但系统比较局限于 SUMO，尚未证明跨仿真器迁移或长期抗遗忘。

</details>

<details>
<summary>当前方法为什么可行</summary>

系统保存完整、带批评证据的情景记录，再把成功和失败经验压缩成可组合的程序技能及带来源的语义页面；检索把相关产物交给行动智能体，独立批评者依据可执行证据决定接受、修订或继续尝试，随后再写回和合并记忆。两个留出基准和消融支持程序与语义记忆的互补作用，但收益具有骨干模型依赖，检索与编排还可能增加成本。

</details>

<details>
<summary>未来展望</summary>

作者明确提出用重复运行评估连续记忆快照，改进课程选择、整合和大规模检索，并测试跨仿真器及科学领域的迁移与遗忘；还建议把显式记忆与参数适应结合。编辑推断：其可审计情景层适合进一步研究错误技能的定向失效，但本文未进行此类实验。

</details>

**原始来源：** [arXiv 2609.03753](https://arxiv.org/abs/2609.03753)

## 3. Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments

**中文译名：** Terminal-Universe：将智能体轨迹转化为可扩展的终端环境

**方向：** 轨迹复用

**重要性排名：** #3

- **日期：** 2026-09-03
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 从历史轨迹恢复可交互经验环境，扩展经验重放与训练
- **入选理由：** 把冻结的单次轨迹提升为可反复查询、验证和扩展的环境资产，为经验记忆提供新的复用单位。

### 一句话概述

终端智能体虽积累了大量冻结轨迹却缺少可反复训练的真实环境，Terminal-Universe通过回放文件操作并补全缺失工作区，把轨迹恢复为可重新查询和扩展的可执行环境。

<details>
<summary>论文摘要翻译</summary>

随着基于终端的代码智能体日益普及，智能体轨迹已大规模积累，而真实且可执行的环境仍然稀缺。然而，智能体后训练真正需要的是环境：每个环境都可被重新查询以产生许多可验证任务并提供执行反馈，而一条轨迹只是一次冻结的示范。作者没有从零生成环境，而是观察到现有轨迹中的工具执行历史暴露了其运行环境的结构和内容，因此可以从轨迹本身重建环境。由此，作者提出 Terminal-Universe：把每条轨迹转成可复用环境，并探索该环境以合成新任务和持续交互。具体而言，Terminal-Universe 回放轨迹记录的文件操作，把每个文件恢复到智能体修改之前的状态，从而得到部分工作区；随后由补全智能体提供缺失文件和依赖。在恢复后的工作区上，系统既重建原始意图任务，也合成全新的任务。此外，系统沿广度和深度两个互补方向扩展任务。广度方面，它挖掘相关环境之间的有向依赖关系，并合成横跨多个代码库的跨工作区查询，以贴近开发者的真实工作方式。深度方面，它借助用户智能体把初始单轮查询扩展为多轮会话，以体现迭代反馈和需求细化。应用于公开终端智能体轨迹后，Terminal-Universe 产生了 3.73 万个足以支持任务的环境。在该语料上对 Qwen3.5-27B 进行监督微调后，Terminal-Bench 2.1 的单轮表现提高 11.9 分，EvoCode-Bench v2 的多轮 MT@4 表现提高 13.8 分。

</details>

<details>
<summary>现存问题</summary>

可执行环境是长期智能体训练和经验重放的稀缺资源，而历史轨迹通常只被当作一次性示范，无法重新执行、改变问题或获得新的环境反馈。

</details>

<details>
<summary>已有方法的不足</summary>

基于 Git 历史的方法依赖真实仓库和既有修复，扰动方法多局限于缺陷修复，从任务规格直接合成则容易产生小而整洁、缺乏真实工程结构的工作区；直接模仿原始轨迹还会继承冻结示范的覆盖边界。

</details>

<details>
<summary>当前方法为什么可行</summary>

工具轨迹中的读取、写入和编辑操作泄露了工作区状态，确定性逆向回放可先恢复修改前文件，补全智能体再补齐任务必需但未被观察到的依赖；系统随后在单工作区、跨工作区和多轮维度生成新任务，并用容器内测试筛选轨迹。大规模恢复结果、下游训练与消融支持这条链路，但并不保证每个重建环境都具备原仓库的完整保真度。

</details>

<details>
<summary>未来展望</summary>

作者明确提出使用更丰富的源轨迹、合并同一工作区的多会话，并扩大领域、语言和工具链覆盖；还建议使用多个教师及独立模型构造验证器。编辑推断：Agent Memory 可把“轨迹库”升级为“可重放环境库”，但跨时间依赖和环境版本失效仍需单独研究。

</details>

**原始来源：** [arXiv 2609.04148](https://arxiv.org/abs/2609.04148)

## 4. KC-Bench: A Dynamic Interactive Benchmark for Evaluating Knowledge Conflicts in LLM Agents

**中文译名：** KC-Bench：评测大模型智能体知识冲突的动态交互基准

**方向：** 记忆冲突评测

**重要性排名：** #4

- **日期：** 2026-09-03
- **状态：** arXiv 预印本 v1；基准发布
- **Agent Memory 相关性：** 参数记忆、对话历史和动态观察之间的冲突检测与时序校验
- **入选理由：** 把记忆冲突从静态问答推进到多轮工具执行，并连接认知错误与下游动作风险。

### 一句话概述

工具型智能体必须在用户指令、参数知识和动态环境证据互相冲突时安全决策，KC-Bench通过多轮模拟、状态化工具和轨迹级断言评测冲突发现、核验与执行行为。

<details>
<summary>论文摘要翻译</summary>

随着大型语言模型越来越多地通过工具采取行动，它们必须在行动前协调用户指令、参数知识和动态环境观察。作者提出 KC-Bench，一个受控的多轮基准，用于衡量智能体处理世界知识冲突、输入不一致和多来源时序冲突的能力。其 238 项任务从一千多个生成候选中经过人工筛选，并结合用户模拟器、状态化工具、确定性环境断言、开源自然语言评估器和人工轨迹核验。对九个模型的评测表明，不同领域间存在显著差异，没有模型能在所有场景中可靠处理事实纠正、身份一致性检查和时序冲突消解；所评模型包括 DeepSeek-V4-Flash、GLM-5.2 和 MiniMax-M3。在模拟环境中，遗漏的冲突可能传播到工具调用或合成的受保护数据流。KC-Bench 隔离的是这种模型级行为，而非对完整智能体框架进行排名，并提供可复现的诊断工具，用于开发冲突感知推理与执行防护。

</details>

<details>
<summary>现存问题</summary>

智能体同时读取用户陈述、模型参数知识、对话历史、数据库记录和工具反馈时，过时或互相矛盾的证据可能在未被发现的情况下进入外部动作。

</details>

<details>
<summary>已有方法的不足</summary>

传统知识冲突基准主要评测静态生成或检索上下文与参数知识的冲突，交互式智能体基准则多看任务完成率、工具使用或对抗鲁棒性；两类评测都难追踪冲突是否被发现、核验、消解并安全落实到动作。作者明确表示，用户模拟、状态化工具和断言本身并非各自的新发明。

</details>

<details>
<summary>当前方法为什么可行</summary>

KC-Bench把冲突分为世界知识、输入不一致和多来源冲突三类，在多轮环境中以状态化工具暴露证据，再用确定性断言、自然语言评估器和人工轨迹核验同时检查推理与动作。跨九个模型的领域差异支持其诊断价值，但对象仍是模拟环境中的模型级行为，不能直接外推到完整生产系统安全性。

</details>

<details>
<summary>未来展望</summary>

作者将基准定位为评估冲突消解干预、追踪模型弱点和开展部署前风险评估的测试床。编辑推断：长期记忆系统可在此基础上加入来源、时间和失效状态作为显式检索特征，但 KC-Bench 尚未验证具体记忆架构。

</details>

**原始来源：** [arXiv 2609.03588](https://arxiv.org/abs/2609.03588)

## 5. DRACO: Fine-Grained Credit Assignment with Dynamic Rubrics for Long-Horizon Agent Training

**中文译名：** DRACO：通过动态量规为长期智能体训练进行细粒度信用分配

**方向：** 长期智能体训练

**重要性排名：** #5

- **日期：** 2026-09-03
- **状态：** arXiv 预印本 v1；代码已发布
- **Agent Memory 相关性：** 长期轨迹中的步骤归因，可用于学习记忆写入、检索和修订策略
- **入选理由：** 在没有程序化终局验证器时仍为长轨迹提供细粒度训练信号，对学习记忆管理策略具有直接方法价值。

### 一句话概述

缺少程序化验证器的长期任务难以判断长轨迹中哪些步骤应受奖励，DRACO用随策略演化的动态量规评估完整轨迹，再把量规判断重新分配到相关步骤。

<details>
<summary>论文摘要翻译</summary>

可验证奖励强化学习在任务具有程序化检查器时表现良好，但多数长期智能体领域没有这种检查器。作者研究结果盲设定，即训练时无法获得真实成功信号。多标准量规是提供这类奖励的常用方式；量规通常对每条轨迹只评分一次，但单个标量对于包含数十个步骤的轨迹而言是贫乏信号。作者提出 DRACO，即用于信用优化的量规优势分配方法。它在训练期间动态生成量规以跟踪策略不断演化的能力，对每条完成轨迹只评一次这些量规，再把判断重新分配给对带标注量规负责的步骤，从而在 GRPO 中产生有差异的逐步优势。该重新分配采用闭式形式，不引入任何训练得到的归因模块。在 AppWorld 上，DRACO 相对基础模型提高 15.9 分，相对使用稀疏真实奖励训练的 GRPO 提高 5.3 分，而自身不使用任何验证器。在分布外的 Tau-Bench 上，即使没有前沿评审模型，它仍相对基础模型提高 5.3 分，并超过真实奖励训练和其他量规训练设置。DRACO 的代码已经公开。

</details>

<details>
<summary>现存问题</summary>

很多长期工具任务不存在可靠终局检查器，而把一条轨迹的单个量规分数均匀赋给所有步骤，会把幸运、冗余或正确步骤与真正导致成败的步骤混在一起。

</details>

<details>
<summary>已有方法的不足</summary>

静态量规无法预见长轨迹不断变化的失败方式；逐位置调用评审成本高且依赖任务分解；训练归因器又引入额外模型和监督。多数既有细粒度信用方法仍以真实终局结果、金标准答案或特定动作结构为锚点。

</details>

<details>
<summary>当前方法为什么可行</summary>

DRACO根据任务说明和同组轨迹动态提出、合并并筛选判别性量规，由一次完整轨迹评审得到各标准的判断及相关步骤，再以保持总优势大小与符号的闭式规则把 GRPO 轨迹优势分配到步骤。AppWorld、Tau-Bench 和消融支持动态量规与步骤信用的组合价值，但研究只以最终任务表现间接验证归因，不能证明信用确实落在正确步骤。

</details>

<details>
<summary>未来展望</summary>

作者明确提出研究所需评审质量，并用人工评审验证量规及步骤归因，同时测量训练阶段由动态标准筛选引入的方差。编辑推断：同类信用机制可用于训练记忆写入、检索和遗忘动作，但本文没有把记忆操作作为独立动作进行实验。

</details>
