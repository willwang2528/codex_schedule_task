## 1. Grounding Agent Memory: Environment-Probing Curation for Enterprise Agents

**中文译名：** 扎根智能体记忆：面向企业智能体的环境探测式整理

**方向：** arXiv 预印本 v1

**重要性排名：** #1

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 写入阶段的证据核验、作用域约束、陈旧记录刷新与异步整理
- **入选理由：** 直接补上“轨迹不足以证明记忆正确且仍然有效”的写入盲区，并在生产式 Agent 流程中隔离验证效果。

### 一句话概述

仅依据已完成轨迹整理长期记忆会保留错误、扩大未经证实的适用范围或写入陈旧知识，该方法让异步整理智能体用最小权限的只读环境工具在提交前探测并核验候选记忆。

<details>
<summary>论文摘要翻译</summary>

持久记忆正在进入面向生产的智能体平台，以帮助长时程智能体跨会话积累经验；然而，只能查看已完成轨迹的任务后整理智能体可能保留错误、从局部证据作出过度概括，或留存陈旧知识。作者提出环境探测式整理：一种与部署兼容的扩展，它为现有异步整理智能体提供最小权限、只读的世界工具，以检查候选记忆、限定其作用域并刷新内容。

该方法不需要重新训练模型，并保持任务智能体、检索器、记忆表示及生产写入权限不变。作者在基于 GitHub Copilot SDK 构建的生产式运行框架中，于 CLBench 数据库探索任务和 90 个改编自 APEX 的管理咨询任务上，对比无状态执行、完整上下文学习、GHCP + Mem 以及带环境探测的 GHCP + Mem。

在 CLBench 上，环境探测将通过率从 39% 提升至 73%，将通过折扣奖励从 8.60 提升至 22.60，同时把每题查询次数从 8.8 降至 4.7，并把任务智能体成本从 3.38 美元降至 1.68 美元。在六个 APEX 环境中，18 项记忆系统与基线的平均奖励比较全部为正，任务智能体工具调用减少 16% 至 75%；环境探测在五个环境中取得最高的单位成本任务奖励增益。它在 Sonnet 4.6 和 Opus 4.7 上的平均奖励也都高于 GHCP + Mem，且没有发生模式漂移。

因此，环境探测把现有智能体记忆整理转化为环境知情、可审计的过程，同时保留紧凑的任务时接口。

</details>

<details>
<summary>现存问题</summary>

任务轨迹只是对环境的一次局部且可能带错的观察，无法独立证明抽取出的事实或程序在未访问状态中仍成立，也不能判断环境变化后记录是否已经失效。

</details>

<details>
<summary>已有方法的不足</summary>

完整轨迹回放会让上下文随部署时间增长；Mem0、ACE、ReasoningBank、ReMe 等任务后整理方法主要依赖既有记录、轨迹、评分和使用信号，再强的反思也无法恢复未观察状态或主动验证漂移后的事实。

</details>

<details>
<summary>当前方法为什么可行</summary>

整理智能体先提出候选记录，再通过只读工具检查连接键、字段、文档位置、程序前置条件或遗漏状态，最后创建、收窄、更新、删除或跳过记录；任务智能体、检索接口和写权限保持不变，使对照实验主要测量写入证据质量，CLBench、APEX、跨模型实验及组件一致性共同支持这条机制链。

</details>

<details>
<summary>未来展望</summary>

论文没有列出专门的未来工作清单。编辑推断：下一步应在更多持续变化的生产环境中检验探测成本、只读表面缺失时的回退、恶意环境证据和跨重启刷新；现有证据不足以证明这些工程与安全属性。

</details>

## 2. Memory as Plans: World-Action Modeling with Memory-Grounded Planning

**中文译名：** 将记忆转化为计划：基于记忆扎根规划的世界—动作建模

**方向：** arXiv 预印本 v1

**重要性排名：** #2

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1；项目页发布
- **Agent Memory 相关性：** 具身情节记忆的多模态压缩、计划时读取与固定上下文执行
- **入选理由：** 把长视觉历史转换为可执行计划，同时保留细粒度证据并控制执行时上下文成本，机制与消融较完整。

### 一句话概述

长时程机器人任务需要早期视觉证据，但摘要会丢失细节、增长窗口又会拖慢执行，MaP-WAM 将稀疏多模态情节记忆转化为语言与视觉计划，再由进度感知执行器以固定上下文完成动作。

<details>
<summary>论文摘要翻译</summary>

主流机器人策略通常采用马尔可夫式建模，但许多复杂的现实操作任务本质上是非马尔可夫的，需要超出当前观察的长时程记忆。现有记忆机制通常依赖语言摘要、不断增长的视觉窗口或两者组合，因此可能丢失细粒度视觉证据，或陷入历史覆盖范围与执行效率之间的权衡。

作者提出 MaP-WAM，一个“记忆即计划”框架：它把依赖记忆的世界—动作建模分解为记忆扎根规划和计划条件化执行，并把长期多模态情节上下文作为规划时证据，而不是让执行器反复接收完整历史。

MaP-WAM 将记忆表示为包含语言指令和稀疏视觉上下文的已完成分段记录，并把情节记忆转换为紧凑计划，其中包括下一段语言计划及对应的视觉引导。

世界—动作—进度模型在推理时联合预测动作块和相应执行进度，在持续时间未知的情况下执行每项计划；它通过计划—观察对齐校准进度预测，从而自适应切换分段并闭环更新上下文。MaP-WAM 保持执行器上下文长度固定，结构化注意力还允许规划和执行阶段使用键值缓存。

MaP-WAM 在 RMBench 上取得 83.3% 的成功率，并在真实机器人任务上取得 78.0% 的成功率，同时在任务历史增长时维持近似恒定的执行器推理延迟。

</details>

<details>
<summary>现存问题</summary>

机器人当前画面可能无法确定目标对象、早先位置或所处语义阶段，关键证据可能位于很久以前；系统既要保存这些视觉事实，又要避免执行器在每个动作块中重读全部历史。

</details>

<details>
<summary>已有方法的不足</summary>

语言摘要会丢失颜色、对象身份和空间位置等视觉证据；固定视觉窗口截断远期历史，增长窗口则增加延迟与显存；现有世界—动作模型虽预测未来，但通常没有把长期情节证据压缩为独立的计划时接口。

</details>

<details>
<summary>当前方法为什么可行</summary>

系统按已完成分段保存语言指令和稀疏视觉帧，由因果世界模型生成下一段语言及视觉计划；WAP 联合生成动作块和执行进度，并以当前观察对齐计划轨迹来修正进度漂移。RMBench、真实机器人试验、视觉记忆与进度组件消融，以及历史增长下的延迟对照，分别支持记忆内容、执行控制和效率链条。

</details>

<details>
<summary>未来展望</summary>

作者明确指出当前方法依赖基准已有的分段结构，下一步是从未分段示范中自动发现分段；作者还提出用学习得到的相似度替代轻量、免训练的像素匹配，以提高复杂视觉场景中的进度校准稳健性。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.11561)

## 3. UniMPA: A Unified Memory-Prediction-Action Model via Action-Grounded Transition Modeling

**中文译名：** UniMPA：通过动作扎根的转移建模统一记忆、预测与动作

**方向：** TPAMI 审稿中／arXiv v1

**重要性排名：** #3

- **日期：** 2026-09-10
- **状态：** TPAMI 审稿中；arXiv 预印本 v1
- **Agent Memory 相关性：** 具身经验记忆的跨模态索引、转移条件检索与动作原型适配
- **入选理由：** 不再把预测、经验检索和动作生成当作松散模块，而是以可执行状态转移统一三者并覆盖仿真与真实机器人。

### 一句话概述

视觉上相似的机器人状态可能需要不同转移，预测出的未来也未必可执行，UniMPA 以动作扎根的状态转移连接未来预测、双向视觉—动作记忆检索和当前场景中的动作原型修正。

<details>
<summary>论文摘要翻译</summary>

视觉—语言—动作模型的近期进展提升了机器人操作能力，但从观察到动作的学习仍受一个根本性的“转移可实现性缺口”限制，具体表现为三个紧密耦合的问题：第一，转移歧义——视觉上相似的当前观察可能属于不同操作阶段，并暗示不同的后续转移；第二，预测—执行不匹配——视觉上合理的预测未来不一定对应物理上可实现的转移；第三，经验—实现不匹配——历史上可执行的动作模式未必能在当前场景实现预期转移，因此需要根据上下文调整。为此，作者提出 UniMPA，通过共享的动作扎根转移接口统一记忆、预测与动作。

首先，UniMPA 引入持久—选择性未来预测，通过建模预期的未来状态演化解决转移歧义：持久潜在流持续追踪任务级进展，转移关键像素流则通过记忆扎根预测有选择地解析细粒度交互变化。其次，为评估预期转移的物理可执行性，预测转移会查询时间化视觉—动作记忆库；该记忆库检索历史上实际发生的视觉—动作经验，使未来预测扎根于可执行证据。最后，为使可执行经验适应当前场景，动作—视觉记忆库从历史动作演化中检索视觉扎根的动作原型，原型偏置流再把流的起点移向历史支持的动作流形，以进行上下文感知的细化。

这些组件共同形成从预期转移到可执行动作的“预判—扎根—细化”统一过程。大量实验显示，该方法只使用 π0.5 基线 25% 至 50% 的训练轮次，便在 LIBERO、LIBERO-Plus、RoboTwin 2.0 Hard 和真实任务上分别超过基线 1.7、11.7、18.5 和 12.6 个百分点。

</details>

<details>
<summary>现存问题</summary>

当前观察既不能稳定表示任务阶段，也不能保证预测未来具有物理可执行路径；即使检索到过去成功的动作，当前几何、接触和机器人状态也可能使其失效。

</details>

<details>
<summary>已有方法的不足</summary>

一般 VLA 将预期转移隐含在观察到动作的映射中；像素预测偏重静态外观，潜在预测可能丢失接触约束；既有记忆方法多按观察、关键帧或地图检索，没有显式保存转移与动作的对应关系，也常把预测和记忆作为相互分离的辅助模块。

</details>

<details>
<summary>当前方法为什么可行</summary>

持久潜在流编码任务级进展，触发门只在接触等关键时刻启用像素监督；未来监督的转移表示查询视觉—动作库获得已执行证据，动作历史反向查询动作—视觉库形成原型，原型偏置流再根据当前观察细化。跨四类仿真与真实设置的实验、组件消融和定性恢复案例支持该机制，但论文仍处于审稿中。

</details>

<details>
<summary>未来展望</summary>

作者明确提出四项扩展：在当前执行过程中同步写入新经验、按任务阶段采用自适应多时间尺度预测、用不确定性连续分配像素预测计算，以及保留多个阶段条件化动作原型；当前系统只能让本次轨迹产生的经验服务后续轨迹，并使用固定时间尺度和单一原型。

</details>

**原始来源：** [arXiv v1／TPAMI 审稿中](https://arxiv.org/abs/2609.11875)

## 4. COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization

**中文译名：** COBRA-Skills：上下文多臂老虎机引导的智能体技能演化优化

**方向：** arXiv 预印本 v1

**重要性排名：** #4

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 程序记忆的经验抽取、候选评估、保留与持续演化
- **入选理由：** 把技能库优化形式化为有限预算下的动态候选搜索，并用执行反馈同时治理评测资源和技能演化。

### 一句话概述

从历史任务提炼出的程序技能需要昂贵执行评测且候选空间会持续变化，COBRA-Skills 用上下文多臂老虎机选择值得评测的技能，并依据成功与失败轨迹不断生成和修订候选。

<details>
<summary>论文摘要翻译</summary>

大型语言模型智能体可以从既往任务经验中提炼可复用技能并从中受益，但现有技能优化方法通常依赖昂贵的执行式评测和大量任务数据。作者提出 COBRA-Skills，一个高效框架，将技能优化表述为动态演化候选空间上的预算受限序贯优化。

COBRA-Skills 把上下文多臂老虎机引导的优先级分配与证据扎根的技能演化结合起来：它把评测有选择地分配给有希望或信息量高的候选，同时依据执行反馈持续改进技能种群。

在六个异构智能体基准和三个目标模型上，COBRA-Skills 的平均表现持续优于所比较的方法；相较 SkillOpt，它将优化成本降低 55% 至 58%，且每个基准只使用 50 个不同的优化样本。进一步分析显示，该方法能适应智能体运行框架的变化，而且在由目标模型自身生成和改进技能时仍然有效。

</details>

<details>
<summary>现存问题</summary>

技能的真实效用必须通过目标智能体执行才能获知，而技能生成、改写和组合会不断改变候选空间；在评测预算有限时，系统必须同时决定测哪些、保留哪些以及如何继续演化。

</details>

<details>
<summary>已有方法的不足</summary>

轨迹到技能方法通常一次性提炼经验，固定候选池搜索不能利用新执行证据扩展空间，SkillOpt 式迭代优化又需要大量目标智能体评测；单纯增加候选数量并选最优项并未解决评测资源分配问题。

</details>

<details>
<summary>当前方法为什么可行</summary>

系统用技能嵌入、神经奖励预测和 LinearUCB 不确定性构成优先级，在每轮选择候选执行；再以无技能轨迹重生成、成功与失败轨迹变异及高低质量技能交叉来演化种群，新技能不继承旧奖励而重新进入评测循环。六类基准、三种目标模型、外部运行框架、跨模型迁移及去除老虎机或演化组件的消融支持两部分的互补性。

</details>

<details>
<summary>未来展望</summary>

论文未提供专门的局限与未来工作章节。编辑推断：仍需检验任务分布持续变化时的技能失效、技能库规模增长后的检索与淘汰，以及错误执行反馈诱发的程序记忆漂移；现有受控基准不足以证明在线生产环境中的长期稳定性与安全性。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.11682)

## 5. MAPLE: Memory-Augmented Planning with Language and Evolution

**中文译名：** MAPLE：结合语言与演化的记忆增强规划

**方向：** arXiv v1／代码发布

**重要性排名：** #5

- **日期：** 2026-09-10
- **状态：** arXiv 预印本 v1；代码发布
- **Agent Memory 相关性：** 可执行状态的版本化更新、历史决策绑定、候选复用与提交验证
- **入选理由：** 把长期记忆从文本回忆推进为经过验证后才能提交的程序、计划、事件和搜索状态，且提供连续修订基准。

### 一句话概述

动态业务规划中的连续自然语言修改容易破坏早先决策或浪费已有搜索结果，MAPLE 持久保存可执行优化程序、已接受计划、更新事件和候选解，并按变更风险选择修复复用或重新初始化。

<details>
<summary>论文摘要翻译</summary>

领域从业者了解业务约束，但可能缺乏运筹学专业知识或专门支持。基于大型语言模型的优化智能体把自然语言需求转化为模型或求解器程序，再由成熟优化工具执行。这一进展提高了优化的可及性，但现实运营是动态的：需求、资源和优先级变化时，数据、约束与目标都需要更新。

以孤立请求为中心的方法难以支持快速适应，同时保留早先决策并复用有价值的搜索结果。作者提出 MAPLE，即结合语言与演化的记忆增强规划智能体，用于通过连续自然语言请求维护优化问题。MAPLE 将语言式问题构建、数学规划和演化搜索结合起来。

它为后续请求保留优化程序、已接受计划、早先更新和候选解。作者还提出 NLDO，一个包含 15 条轨迹和 180 次更新的基准，覆盖选择、调度、排班、路径规划及云资源放置。在主要评测中，MAPLE 完成全部轨迹，在线标量质量达到 0.951，帕累托超体积比达到 0.875。

受控比较进一步表明，维护可执行状态可以提高更新有效性，并在大幅修改后保留有用的搜索信息。

</details>

<details>
<summary>现存问题</summary>

连续修改不仅改变数据，还可能引用早先实体、已接受分配或旧候选解；若没有版本化的可执行状态，智能体难以判断应局部修改、迁移搜索种群还是彻底重启。

</details>

<details>
<summary>已有方法的不足</summary>

现有优化智能体主要针对单次描述生成模型或程序，并用执行错误修补当前输出；普通 ReAct 历史虽然保留文本和代码，却缺少受约束的编辑面、历史引用绑定、候选迁移规则及提交前的结构化验证。

</details>

<details>
<summary>当前方法为什么可行</summary>

TSS 将模型声明的决策类型绑定到固定搜索操作和求解器，LPD 定位修改面，LSM 从已接受事件与计划解析历史引用，重启选择器再按变更决定 Warm 修复复用或 Full 重建；编译、接口、示例执行和输出检查全部通过后才提交新状态，否则保留上一版本。NLDO 连续轨迹、基线比较、TSS 消融和候选复用对照支持这条机制链。

</details>

<details>
<summary>未来展望</summary>

作者明确指出目前依赖固定的决策类型、求解器路径和重启动作目录，含糊历史引用仍需用户澄清，有限搜索预算也使复用与重建存在延迟权衡；生产部署还需隔离生成代码、文件、凭据和网络访问，并为高影响决策提供人工审批与回滚。

</details>
