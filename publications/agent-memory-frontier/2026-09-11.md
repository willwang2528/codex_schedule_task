## 1. PRAGMA: Evaluating Personalized Guidance with Memory Alignment in Lifelong Conversations

**中文译名：** PRAGMA：评测终身对话中与记忆对齐的个性化指导

**方向：** EMNLP 2026 已接收／代码与数据发布

**重要性排名：** #1

- **日期：** 2026-09-09
- **状态：** EMNLP 2026 已接收；arXiv 预印本 v1
- **Agent Memory 相关性：** 评测记忆保存、检索与生成利用的端到端对齐
- **入选理由：** 把评测目标从事实回忆推进到跨会话证据整合和纠错式个性化指导，并提供可复用的标注数据。

### 一句话概述

长期个性化对话中的事实回忆评测无法覆盖跨会话证据整合与变化偏好推理，PRAGMA 通过带证据标注的纵向对话和指导场景评测从记忆保存、检索到生成利用的完整链条。

<details>
<summary>论文摘要翻译</summary>

大型语言模型越来越多地被部署为与用户长期交互的个性化助手。随着对话变长，依赖完整交互历史会变得低效且不可靠：长上下文带来显著计算开销，也使模型难以持续识别并利用与当前请求最相关的信息。

这些挑战推动了用于组织和检索用户特定信息的记忆系统。在真实交互中，用户经常寻求推荐、规划和决策支持等实用指导。与事实回忆任务不同，个性化指导要求模型整合多次既往对话的信息，并推理不断变化的用户偏好与经历；然而，现有对话记忆评测主要关注检索和事实回忆。

为研究这一问题，作者提出 PRAGMA，一个面向长期对话中个性化指导的评测基准。PRAGMA 包含经整理的纵向对话历史、证据标注，以及基于变化用户情境和用户错误假设构建的指导场景。

对检索系统、记忆系统和长上下文模型的实验表明，当前系统既难以恢复恰当的对话证据，也难以有效利用这些证据生成个性化指导。结果强调，记忆架构需要支持超越证据回忆的稳健对话检索与记忆扎根推理。

</details>

<details>
<summary>现存问题</summary>

现有长期记忆评测通常把成功等同于找回事实，却没有充分检查模型能否跨多次会话整合分散证据、适应偏好变化，并在用户前提错误时给出有依据的纠正性建议。

</details>

<details>
<summary>已有方法的不足</summary>

长上下文方法保留原始证据但把筛选与综合负担留给生成模型；RAG 和现有记忆系统又可能在压缩、检索或生成利用阶段丢失信息。论文的分阶段分析显示，高保存率并不保证证据会被检索或反映到最终回答中。

</details>

<details>
<summary>当前方法为什么可行</summary>

PRAGMA 将事件级与轨迹级场景分别设计为对齐式和纠错式指导，并提供会话级证据标注，使研究者能够沿存储、检索和回答利用三个阶段定位失败。论文比较了 RAG、专用记忆系统与长上下文模型，代码和数据已由作者公开；证据仍主要来自受控的合成纵向对话。

</details>

<details>
<summary>未来展望</summary>

作者明确提出三项方向：用更自然的真实长期对话检验迁移性，把单轮指导扩展为可追问和恢复的多轮交互，并以更细粒度的推理轨迹替代仅按证据会话评测。编辑推断：该基准适合成为记忆检索与生成对齐的联合训练信号，但论文尚未验证这种训练用途。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.09664)

## 2. What Should an Agent Forget? Separating What Is Stored from What Is Used

**中文译名：** 智能体应该遗忘什么？区分存储内容与实际使用内容

**方向：** arXiv 预印本 v1

**重要性排名：** #2

- **日期：** 2026-09-09
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 读取阶段的版本控制、历史保留与查询条件化遗忘
- **入选理由：** 把“遗忘”重新定义为控制当前证据影响，而非删除历史，直接处理新旧事实对不同查询意图的双重价值。

### 一句话概述

旧事实对当前问题可能有害却仍需供历史查询使用，RD-Forget 保留完整来源档案并按查询意图构造带语义槽位和替代关系的临时证据视图。

<details>
<summary>论文摘要翻译</summary>

持久化语言智能体需要让已存经验长期保持可用，但每次回答又需要适合特定问题的证据。被更新替代的事实可能误导当前状态问题，却仍是历史查询不可缺少的证据。作者提出 RD-Forget，一个无需训练、将智能体存储内容与使用内容分离的框架：保留来源档案保存观察，而查询条件化的记忆视图控制这些观察对当前回答的影响。

一个冻结的语言模型整理器提取相关证据，将事实归入语义槽位，并保留多跳推理需要的关系。同槽位替代链接会在当前状态上下文中抑制已被替代的值，而意图感知检索允许早期证据在需要时重新具备资格。率失真形式化在记忆预算内指导回答时证据视图的构建。

实验在统一回答管线下覆盖对话记忆、知识更新、事实整合、长上下文推理和个性化。结果把准确回答与查询相关证据构建及过时备选项控制联系起来；不使用遗忘或查询条件化的配置出现最大性能缺口，而槽位分组、历史访问和关系保留发挥互补作用。

在保留历史的同时选择性控制其使用，为适应变化事实和未来查询提供了一条实用途径。

</details>

<details>
<summary>现存问题</summary>

同一条旧记录对“现在是什么”可能是干扰，对“过去是什么”却是必要证据；直接删除会损失历史可回答性，全部保留并共同注入又会让过时事实影响当前判断。

</details>

<details>
<summary>已有方法的不足</summary>

编辑式记忆更新容易把旧值永久覆盖，累积式记忆则把版本消歧交给回答模型；普通相关性检索也不能区分同槽位的竞争值与跨槽位的互补关系。论文未提供覆盖所有记忆架构的系统性理论比较。

</details>

<details>
<summary>当前方法为什么可行</summary>

RD-Forget 先保留不可破坏的来源档案，再由冻结模型抽取证据、建立语义槽位和替代链接；查询意图区分当前与历史问题，资格规则恢复必要旧证据，率失真目标则在预算内保留关联链。跨多类记忆任务的统一管线和组件消融支持这些机制的互补性，但评测仍以问答场景为主。

</details>

<details>
<summary>未来展望</summary>

论文没有给出系统性的未来工作清单。编辑推断：下一步应检验槽位错误和查询意图误判的传播风险，并把只读证据视图扩展到会执行工具或写回记忆的智能体；现有证据不足以证明其适用于开放环境中的长期自主行动。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.10263)

## 3. Kernel-Managed Shared Memory for System-Wide Personalization

**中文译名：** 面向系统级个性化的内核托管共享记忆

**方向：** arXiv 预印本 v1

**重要性排名：** #3

- **日期：** 2026-09-09
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 跨智能体记忆共享、权限治理、写入一致性与提示注入
- **入选理由：** 把共享记忆从单个 Agent 的提示工程提升为系统内核服务，并同时定义可见性与写入顺序约束。

### 一句话概述

多智能体系统中单个智能体学到的用户信息难以在共享与隐私之间一致复用，该方法把带标签记忆的检索、权限过滤和提示注入统一交给智能体系统内核管理。

<details>
<summary>论文摘要翻译</summary>

人工智能系统在能够适应使用者时会更有用，但在多智能体系统中，一个智能体学到的有用上下文往往无法被其他智能体获得。作者提出内核托管共享记忆：专用智能体写入结构化、带标签的记忆，而检索、隐私执行和提示注入由智能体系统内核而非各个智能体负责。

作者在 AIOS 上实现并评测该设计，使用三个助手模型进行共 1,800 次试验，并与三种替代方案比较。相对于采用相同底层存储的非托管外部记忆后端 Mem0，内核托管检索与注入在五分制个性化评分上提高 2.4 至 4.0 分，所有比较均达到显著性。

相对于标准检索增强注入，三个模型上的提升同样较大且一致。

相对于完整、未过滤的上下文拼接这一“可用上下文”的软上限，内核托管注入在三个模型中的两个上统计持平，在第三个模型上存在小幅、模型特定的差距，同时使用显著更短的提示；三个模型的端到端延迟降低 15% 至 61%，每次调用的 token 用量和推理成本也相应降低。

这些结果表明，与其让各智能体自行处理检索和隐私执行，不如在智能体系统内核中集中管理记忆，从而以较低成本获得无约束上下文的大部分个性化收益。

</details>

<details>
<summary>现存问题</summary>

跨智能体共享用户信息需要同时解决谁能看、何时可读、写入何时生效以及怎样注入提示；把这些责任分散给每个智能体会造成策略不一致、竞态和隐私遗漏。

</details>

<details>
<summary>已有方法的不足</summary>

普通个性化 RAG 假定单一应用路径，非托管外部记忆依赖调用方正确过滤；完整上下文拼接缺乏权限和预算控制。已有共享记忆治理方法使用更复杂的权限图或漂移门控，而本文选择静态元数据和顺序屏障，未证明该简化能覆盖动态授权。

</details>

<details>
<summary>当前方法为什么可行</summary>

内核为记忆绑定所有者、作用域和共享标签，统一执行身份解析、等待未完成写入、检索、权限过滤、去重、排序、格式化和预算截断；静态可见性规则约束隐私，带序号写屏障约束读取时序。论文在相同存储后端和多模型设置下比较替代方案，并实测两个共享端点；其保证仍依赖正确的身份解析，且覆盖可见性而非记忆完整性。

</details>

<details>
<summary>未来展望</summary>

作者指出完整上下文在一个模型上的质量差距尚未解释，并把更精确的机制分析留给未来工作。编辑推断：还需验证动态权限撤销、恶意写入、多用户并发和跨框架迁移，因为当前静态可见性规则与受控试验不足以覆盖这些生产风险。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.10144)

## 4. Fortunate Recall: Ontology-Driven Memory Lifecycle Management for Persistent Coherence in LLMs

**中文译名：** Fortunate Recall：以本体驱动的记忆生命周期管理维持 LLM 持久一致性

**方向：** 审稿中／代码与基准发布

**重要性排名：** #4

- **日期：** 2026-09-09
- **状态：** 审稿中；arXiv 预印本 v1／代码与基准发布
- **Agent Memory 相关性：** 事实写入后的分类、衰减、替代、有效期与检索路由
- **入选理由：** 覆盖完整生命周期并公开基准、代码和运行记录，但因缺少人工验证与基准共设计风险而降低排名。

### 一句话概述

个人事实具有不同的替代、时效和衰减规律，Fortunate Recall 先按行为本体标注事实，再以类别特定的生命周期策略决定保留、替换与检索。

<details>
<summary>论文摘要翻译</summary>

当前 LLM 记忆系统把所有个人事实一视同仁，以统一保留策略存入扁平向量库或知识图谱，导致存储无界增长并降低检索精度。核心挑战是生命周期管理：应根据每类事实的行为类型，决定哪些记忆应持续保留、哪些应被替换，以及以何种速率变化。

Fortunate Recall（FR）是一个可组合策略层，它把个人事实划分到“10+1”行为本体，并把差异化时间衰减、槽位键替代、事件时间有效性和类别感知检索路由作为作用于 LLM 所抽取元数据的确定性函数。生命周期策略层由数学规则构成；LLM 只用于摄取阶段和检索时一次轻量候选选择。

其与基础设施无关的实现 FR-Bank 在新提出的 516 题时间消歧基准 LifecycleBench 上达到 76.9% 通过率，高于 Mem0、A-MEM、Memory-R1 和 MemoryOS 的 61% 至 70.5%；在采用标准评审协议的完整 LongMemEval-S 上达到 75.2%，表明生命周期策略没有给标准检索任务带来可测的总体损失。

预注册消融定位了收益来源：用三个通用生命周期原语替代类型化层后，正确性差异在统计上不显著，因此正确性优势主要来自通用生命周期元数据；行为本体的作用是校准，使下游虚构率从 24.2% 降至 12.0%，因为它支持无法由单一全局权重实现的分类参数化。

端到端评测中，FR-Bank 相对 Mem0 降低了已回答查询及全部查询上的虚构，同时回答了更多问题；这一排序在开放权重 Kimi K2.5 上复现。该分解还迁移到独立构建的 BEAM 基准，收益集中于矛盾消解，并在约七个策略簇附近趋于饱和。

作者公开了本体、基准和代码。

</details>

<details>
<summary>现存问题</summary>

不同个人事实的更新规律并不相同：偏好可能缓慢漂移，日程会到期，地址会被新值替代，撤回内容应失效；统一保留与统一相关性排序无法表达这些差异。

</details>

<details>
<summary>已有方法的不足</summary>

扁平向量库和一般知识图谱主要优化语义相关性，认知型分类也不直接决定事实的生命周期策略。论文比较了多个已发布系统的默认配置，但没有构建经最大化调优的对手，因此外部系统比较不能单独证明本体设计优越。

</details>

<details>
<summary>当前方法为什么可行</summary>

摄取时为事实附加行为类别、槽位键、生命周期状态、事件时间和置信度；检索时先生成候选，再由确定性评分组合衰减、替代、有效期和类别路由。预注册消融把通用生命周期元数据与本体校准效应分开，并在独立基准上做迁移检查；但绝对结果依赖 LLM 评审，尚无人类标注验证。

</details>

<details>
<summary>未来展望</summary>

作者已明确计划进行盲审的人类标注切片，并承认尚未评测更多框架、多智能体并发写入及必须始终回答的部署条件。编辑推断：若要支持生产级 Agent Memory，还需验证类别误判、动态策略校准和高承诺生成模型下的软替代失效；现有证据不足以安全外推到这些场景。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.10413)

## 5. Subagents vs Agent Skills: Executing Reusable Knowledge for Long-Horizon Agentic Tasks

**中文译名：** 子智能体与 Agent Skills：在长程智能体任务中执行可复用知识

**方向：** arXiv 预印本 v1

**重要性排名：** #5

- **日期：** 2026-09-07
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 过程记忆的封装、调用边界与长上下文管理
- **入选理由：** 从“存什么技能”推进到“如何调用过程记忆”，揭示独立上下文和输入输出契约对技能复用的作用。

### 一句话概述

长程任务把技能说明和执行轨迹持续堆入主上下文会造成信息过载，该方法把具有明确输入输出契约的过程技能交给独立子智能体执行并仅回传结果。

<details>
<summary>论文摘要翻译</summary>

语言模型智能体怎样才能有效利用可复用知识库来解决长程任务？近期研究越来越关注 Agent Skills：以技能包表示的可复用能力，即包含指令、脚本和其他资源的多文件组合，用来帮助智能体执行特定任务。Agent Skills 通常通过把技能说明载入智能体上下文，并依赖智能体遵循这些说明来执行。

然而，随着任务跨度增加，这种方法会变得越来越脆弱，因为上下文窗口累积的信息越多，推理质量越容易下降。作者研究一种替代方法：把技能包作为子智能体调用。子智能体执行不会把技能说明载入主上下文，而是创建专用于单个子任务的新上下文窗口。

研究表明，当技能包具有清晰的输入输出契约，且说明编码了履行契约所需的过程知识时，子智能体执行优于 Agent Skill 执行；代价是主智能体与子智能体协调需要额外 token，从而增加通信开销。结果说明，可复用知识的效用不仅取决于内容，也取决于组织方式与调用方式。

</details>

<details>
<summary>现存问题</summary>

Agent Skills 虽能保存可复用过程知识，但把说明和后续执行轨迹全部展开在主上下文中，会让长程任务的峰值上下文持续增长，并使技能知识与无关工具信息相互干扰。

</details>

<details>
<summary>已有方法的不足</summary>

普通 Skill 调用只返回说明，仍由主智能体在同一上下文中完成整个过程；既有子智能体通常用于并行化，而不是封装过程记忆。论文也发现，缺乏明确输入输出契约的现成技能并不适合直接隔离执行。

</details>

<details>
<summary>当前方法为什么可行</summary>

技能包用自然语言输入契约规定可调用条件，以过程说明承担子策略，再用输出契约限制返回内容；子智能体在独立上下文中执行，主智能体只接收最终结果，从而隔离内部轨迹。作者在 SkillsBench 的长程任务上比较同一技能包的两种执行方式，并测试干扰技能、峰值上下文和总 token 成本；证据目前集中于单一基准与改造后的 OpenHands 管线。

</details>

<details>
<summary>未来展望</summary>

作者明确提出两条方向：降低主智能体与子智能体的通信成本，以及随着技能库增长，对过程知识进行分层抽象、拆分和重构；更深层的树与图结构也留待系统研究。编辑推断：这可形成过程记忆的分层调度层，但论文尚未验证跨任务持续更新或技能失效后的安全回退。

</details>
