## 1. When Malicious Instructions Persist: Persistent Memory Poisoning Attack on Harness-Based Agents

**中文译名：** 恶意指令何以长存：面向 Harness 型智能体的持久记忆投毒攻击

**方向：** arXiv 预印本 v1；代码发布

**重要性排名：** #1

- **日期：** 2026-09-12
- **状态：** arXiv 预印本 v1；代码发布
- **Agent Memory 相关性：** 写入阶段的来源信任、跨会话持久性与记忆安全
- **入选理由：** 以低权限外部内容串起“写入—持久化—后续触发”攻击链，直接暴露生产 Harness 的长期状态攻击面。

### 一句话概述

外部来源中的恶意指令可能越过临时上下文写入持久记忆并在后续会话触发隐私泄露，PMPA 通过两阶段攻击流程系统刻画并复现这一路径。

<details>
<summary>论文摘要翻译</summary>

Harness 设计通过整合记忆、工具使用和运行时控制，改变了基于大语言模型的智能体开发方式；然而，这种设计也带来了安全与隐私风险，因为来自外部来源的恶意指令可能被写入持久记忆并跨会话留存。为研究这一风险，作者提出针对 Harness 型智能体的持久记忆投毒攻击 PMPA。

PMPA 将恶意指令嵌入看似正常的外部来源，并在不直接访问智能体框架的情况下诱使受害智能体把它们写入持久记忆。一旦存入，投毒记忆便可能在后续会话中被检索，触发额外的恶意动作并导致隐私泄露。作者在 OpenClaw 和 Claude Code 上，跨不同基础大模型、输入模态和触发场景评测 PMPA。

在全部设置中，PMPA 在 OpenClaw 上取得平均 73.7% 的注入成功率和 55.5% 的跨会话攻击成功率，在 Claude Code 上分别为 66.9% 和 81.7%，同时保持两个系统的正常任务表现。作者还评测了一种定向的提示级防御，发现它能在许多设置中减少记忆注入，但在持久记忆已经被投毒后提供的保护有限。

</details>

<details>
<summary>现存问题</summary>

Harness 会把外部资料、用户偏好和任务经验转化为跨会话状态，但临时输入与长期记忆之间缺少足够强的信任边界，导致一次间接提示注入可能获得持续影响力。

</details>

<details>
<summary>已有方法的不足</summary>

AgentDojo、InjecAgent 等间接提示注入研究主要关注当前交互；AgentPoison 等记忆投毒工作通常假设攻击者可直接操作记忆、知识库或受害智能体，未覆盖“只发布外部内容”这一更受限的攻击者模型。

</details>

<details>
<summary>当前方法为什么可行</summary>

PMPA 把攻击拆成外部来源注入和新会话触发两个阶段：来源中的写入指令先被误认作用户要求或偏好，条件规则随后由记忆检索带入邮件、日历、文档或表单操作；文本、图像和 PDF、多种基础模型及两套 Harness 的实验共同支持这条因果链，而提示防御在记忆已污染后几乎不能降低跨会话攻击率。

</details>

<details>
<summary>未来展望</summary>

作者明确提出扩大到更多设置和基础模型，并研究更有效的持久记忆投毒与隐私泄露防御；现有实验使用本地模拟工作区，尚不足以证明真实生产权限、人工确认和不同记忆实现下的攻击率。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.13889)

## 2. MemRiskBench: Trace-Aware Risk-Preserving Evaluation for Long-Horizon LLM Agents

**中文译名：** MemRiskBench：面向长时程大模型智能体的轨迹感知风险保真评测

**方向：** arXiv 预印本 v1；基准发布

**重要性排名：** #2

- **日期：** 2026-09-14
- **状态：** arXiv 预印本 v1；基准与代码发布
- **Agent Memory 相关性：** 长期记忆风险分类、轨迹级检测与低成本安全评测
- **入选理由：** 把陈旧、冲突、越权、撤销失效和约束衰减从平均能力分数中独立出来，并提供无需 LLM 裁判的可复现检查。

### 一句话概述

汇总分数会掩盖稀有却高危的长期记忆失效，MemRiskBench 以风险分类、完整轨迹和确定性检查保留并单独衡量这些失败。

<details>
<summary>论文摘要翻译</summary>

长时程大模型智能体会跨会话积累记忆，由此产生稀疏但影响重大的风险：陈旧事实、冲突更新、跨用户泄露、已撤销记忆的再次使用以及约束衰减。标准汇总分数会隐藏各类风险的失败率——一个平均准确率达到 78% 的模型仍可能在 4% 的回合中泄露数据——而基准压缩又会优先丢弃那些罕见的高严重度事件，无法区分“多数时候正常”的模型与“偶尔造成伤害”的模型。作者提出 MemRiskBench。

首要贡献是一套包含五类风险、外加一类已记录但不计分风险的分类体系，并以确定性的轨迹落地检查实现；它被实例化为一个含 120 个脚本化回合、记录完整轨迹且通过或失败判定路径不使用 LLM 裁判的基准，并在五个本地运行的量化指令微调模型上评测。

第二项贡献是风险保真的子集选择器：它在确定性轨迹特征上采用覆盖约束的贪心选择，在只保留 20% 子集时保持完整排序、1.0 的风险覆盖率和 1.0 的高风险模型检出率，并将计算量降低五倍。

不同于只保持排序的子集选择器，该方法还利用无需 LLM 裁判的轨迹确定性特征，保持风险类型覆盖和高风险检出。作者发布了全部回合、轨迹、评分实现和选择器，以支持对已部署大模型智能体开展可复现评测和风险分析。

</details>

<details>
<summary>现存问题</summary>

长期记忆系统的平均问答或检索分数无法说明某种低频高危失败是否存在，常见的基准裁剪还可能恰好删掉越权泄露、撤销失效等关键样本。

</details>

<details>
<summary>已有方法的不足</summary>

LongMemEval、LoCoMo、MemBench 和 MemoryAgentBench 主要测量检索或回答能力；通用长上下文基准不建模有状态工具调用和约束生命周期，而只优化排行榜相关性的子集选择也不保证保留风险类型。

</details>

<details>
<summary>当前方法为什么可行</summary>

基准把陈旧依赖、冲突误解、跨作用域泄露、撤销记忆复用和约束衰减分别编码为脚本回合，并从工具调用与完整轨迹进行确定性判定；覆盖约束选择器再以轨迹特征保留风险类别、模型区分度和高风险检出，发布的双重评分与重评分审计使结果可复查。

</details>

<details>
<summary>未来展望</summary>

作者明确提出转向真实浏览器、邮箱或办公环境，扩大到前沿模型，并用更多留出模型检验子集泛化；当前证据仅来自合成脚本、五个八十亿参数以下的量化模型，且拒答计分和量化差异仍会影响解释。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.14976)

## 3. CoMem: Collective-Individual Memory Synergy for Evolutionary Multi-Agent Systems

**中文译名：** CoMem：面向演化式多智能体系统的集体—个体记忆协同

**方向：** AAAI 2027 投稿审稿中

**重要性排名：** #3

- **日期：** 2026-09-14
- **状态：** arXiv 预印本 v1；AAAI 2027 投稿审稿中
- **Agent Memory 相关性：** 多智能体记忆的写入治理、跨主体共享和污染抑制
- **入选理由：** 不再把所有经验写入同一平面存储，而是给私人探索、跨主体验证和共享读取建立明确的晋升路径。

### 一句话概述

多智能体共享平面记忆容易积累噪声并抹平角色差异，CoMem 通过私有经验沉淀、集体智慧筛选和双流检索分离个体学习与群体共识。

<details>
<summary>论文摘要翻译</summary>

设计有效的记忆机制对于推进大模型驱动的多智能体系统至关重要，它能帮助智能体共同学习并随时间改善表现；尽管近期工作已经带来较强的协作能力，多数方法仍使用扁平、无结构的记忆，容易被噪声填满并抹去智能体之间的差异。

为解决这一问题，作者提出集体—个体记忆协同概念及 CoMem 架构，把私人经验与共享知识统一到多智能体学习中。

CoMem 包含三部分：（一）私有经验沉淀，使每个智能体能够持续保存和更新自身有用记忆；（二）集体智慧筛选，只把经过广泛验证的思想共享给其他智能体；（三）并行双流检索，使智能体同时利用自身记忆与群体智慧，并通过聚类保持多样性。

在 ALFWorld 和 PDDL 基准上的实验表明，CoMem 获得较强的整体表现，并能稳健地避免记忆污染。

</details>

<details>
<summary>现存问题</summary>

多智能体把试错轨迹无差别写入共享库时，低质量经验会持续稀释有效知识，角色专属策略也会在反复交叉写入中趋于同质化。

</details>

<details>
<summary>已有方法的不足</summary>

Voyager、MemoryBank 等单智能体记忆适配到多智能体后缺少跨主体治理；MetaGPT、ChatDev 和 G-Memory 等共享方案仍以平面读写为主，未把私人验证、组织级晋升和集体知识淘汰组成完整生命周期。

</details>

<details>
<summary>当前方法为什么可行</summary>

经验先由各智能体私下反思并按使用情况滚动淘汰，只有达到调用次数门槛且表现高于移动基线的条目才能晋升共享池；共享条目再由任务反馈和智能体评价更新效用，读取时分别检索私人层与集体层并聚类去重，跨四种多智能体框架的对照、组件消融和阈值敏感性实验支持这条机制链。

</details>

<details>
<summary>未来展望</summary>

论文没有给出独立的未来工作清单。编辑推断：应进一步检验开放动态环境中的错误共识、恶意智能体、跨团队访问控制和阈值自适应；当前证据集中于 ALFWorld、PDDL 和有限模型，尚不足以证明真实组织中的长期治理效果。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.15009)

## 4. AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems

**中文译名：** AIM：面向多智能体多用户大模型系统的隐私感知可互操作记忆框架

**方向：** arXiv 预印本 v1；基准发布

**重要性排名：** #4

- **日期：** 2026-09-11
- **状态：** arXiv 预印本 v1；MUMBench 基准发布
- **Agent Memory 相关性：** 多租户记忆的可见性、生命周期操作与访问控制
- **入选理由：** 把私人隔离与公共知识共享纳入同一索引和创建、读取、更新、删除协议，并提供专门的多用户评测对象。

### 一句话概述

单用户记忆架构无法在多人多智能体场景中同时共享公共知识并隔离私人信息，AIM 通过可见性分类、索引级访问控制和受约束的记忆生命周期统一管理两类记忆。

<details>
<summary>论文摘要翻译</summary>

传统大语言模型被限制在单个用户会话中，其知识局限于一段对话，也无法学习随时间变化的用户偏好。现有智能体记忆系统解决了这一限制，但通常只在单用户层面运行，因而限制了可跨用户共享、用于改善后续回答的公共知识。

作者提出 AIM（Agentic Interoperable Memory），这是一个统一、隐私感知的记忆框架，使多智能体、多用户大模型系统能够持久管理私人记忆和共享记忆。AIM 动态地把信息划分为私人信息或公共信息：私人信息仅限一个用户且其他用户不可访问，公共信息则可供所有用户访问。

它实施索引级访问控制，使私人记忆只能由其所有者检索，从而在保护敏感数据的同时，让有益的共享知识改善协调性与一致性。作者还提出 MUMBench（Multi-User Memory Benchmark），这是一个跨四个领域、同时包含私人信息和可共享信息的多用户交互数据集。

据作者所知，MUMBench 是首个用于评测多用户环境中多种记忆操作的公开数据集，覆盖检索、创建、更新和删除。在 MUMBench 的三次独立运行中，AIM 的可见性分类准确率为 96.0%，严格操作准确率为 58.8%，状态感知操作准确率为 70.5%。

</details>

<details>
<summary>现存问题</summary>

现有持久记忆大多默认一个用户或一个主体，进入共享组织环境后，公共知识复用、私人数据隔离、所有权和并发更新会同时出现。

</details>

<details>
<summary>已有方法的不足</summary>

Mem0、MemoryBank、LOCOMO 和 MemoryAgentBench 主要面向单用户或单智能体；既有多智能体共享方法缺少统一的用户级可见性谓词，也没有系统评测创建、读取、更新、删除和跨会话同步。

</details>

<details>
<summary>当前方法为什么可行</summary>

AIM 在写入路径中依次执行多标签操作识别、结构化抽取、公开或私人分类和作用域内去重，在读取路径中先以所有权谓词过滤，再进行语义检索、标签重排和基于时效性的重排；MUMBench 的顺序交互与多领域操作标注支持生命周期评测，但检索相关性仍明显弱于可见性分类。

</details>

<details>
<summary>未来展望</summary>

作者明确提出改进标签抽取和混合检索、在创建时加入事实核验、把公共记忆限定到用户子集，并继续验证冲突解决与用户审计；论文同时承认公共记忆仍可被错误信息污染，LOCOMO 对照也未覆盖其核心多用户能力。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.12320)

## 5. The Router Within: Eliciting Native Skill Routing from a Frozen LLM

**中文译名：** 内生路由器：从冻结大模型中引出原生技能路由能力

**方向：** arXiv 预印本 v1；基准发布

**重要性排名：** #5

- **日期：** 2026-09-14
- **状态：** arXiv 预印本 v1；SkillTraj 基准发布
- **Agent Memory 相关性：** 程序性记忆与技能库的检索路由、触发时机和上下文预算
- **入选理由：** 将技能选择视为程序性记忆访问问题，覆盖任务中途触发、错误技能恢复及真实 Harness 集成。

### 一句话概述

大规模技能库要么占用智能体上下文要么把选择权交给外部检索器，Gavel 从冻结模型的中间层状态读取路由信号并用两阶段判定选择技能。

<details>
<summary>论文摘要翻译</summary>

技能可以把大模型智能体扩展到其参数知识之外，但这种收益取决于能否选中正确技能。已部署的 Harness 通常把每项技能的元数据预载入上下文来路由，这会分散智能体注意力并限制技能库规模；检索流水线则把选择过程移出上下文，却也移出了智能体自身的能力范围。

作者表明，冻结的智能体大模型在自身前向传播中已经携带路由信号，只需两个线性映射即可在不把技能文本放入上下文的情况下读出该信号。Gavel（Glance And Verdict from a frozen LLM）分两步完成读取：glance 将任务和各技能的中间层状态通过仅有的两个可训练映射进行投影，并用安装技能时一次前向传播建立的紧凑技能向量库为完整技能库评分。

随后，verdict 继续运行入围技能的前向传播，读取模型自身的似然和是或否判断，并以专家乘积方式与 glance 融合。Gavel 训练一次后，可零样本迁移到三个公开基准以及新的 SkillTraj 基准；SkillTraj 包含 372 条模拟智能体轨迹。

在 Qwen3-32B 上，它相较渐进式披露以及额外引入 12 亿至 160 亿参数的检索再重排流水线，在书面任务上最高提升 13.4 个百分点，在技能需求于执行中途出现时最高提升 21.9 个百分点。路由准确率会随基础模型能力提高；在一个 Bash 智能体 Harness 中，同一个 32B 模型在 Skill-Use 上正确触发技能的次数也多于运行在 Codex 中的更大前沿模型。

</details>

<details>
<summary>现存问题</summary>

程序性记忆库扩大后，智能体既要知道“何时需要技能”，又要从长轨迹中识别“需要哪项技能”，但把全部描述塞入上下文会消耗窗口并稀释注意力。

</details>

<details>
<summary>已有方法的不足</summary>

渐进式披露依赖名称和短描述，难以利用完整技能体中的执行条件；外部嵌入检索和重排则需决定输入整条嘈杂轨迹还是最后一条消息，并使路由器与最终执行技能的模型认知分离。

</details>

<details>
<summary>当前方法为什么可行</summary>

glance 用冻结模型中间层的逐 token 表示扫描压缩后的技能向量库，verdict 再让同一模型结合完整技能体读取任务似然和相关性判断，最终融合三类信号；公开基准、组件替换实验、含工具证据和错误恢复的 SkillTraj，以及 mini-swe-agent 集成共同支持路由链，但终端指标主要是选中或触发正确技能而非完整任务成功。

</details>
