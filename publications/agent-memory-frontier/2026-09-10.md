## 1. Procedural Graphs: Self-Evolving Execution Structures for LLM Agents

**中文译名：** 过程图：面向 LLM 智能体的自演化执行结构

**方向：** arXiv 预印本 v1

**重要性排名：** #1

- **日期：** 2026-09-08
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 过程记忆的表示、局部检索与离线演化
- **入选理由：** 把零散经验升级为显式可编辑的步骤依赖图，并以独立验证门控演化；跨七类任务和多模型的证据范围最完整。

### 一句话概述

长程工具智能体容易在累积轨迹中丢失步骤依赖并重复失效动作，本文以可定位当前进度且能从执行反馈持续修订的过程图，为每一步生成受结构约束的行动指引。

<details>
<summary>论文摘要翻译</summary>

大型语言模型日益被部署为能够进行长程规划并通过外部工具行动的智能体。大多数智能体基于不断累积的历史，通过无约束生成选择动作，使“该做什么、按什么顺序做、在什么条件下做”的过程知识保持隐式。随着轨迹变长，智能体可能偏离目标、以错误顺序调用工具，并重复无效动作。

作者提出过程图：正如知识图谱用“实体—关系—实体”三元组组织用于回答“是什么”的事实知识，过程图用“过程—关系—过程”三元组组织用于回答“该做什么”的过程知识。在每个决策步骤，框架定位智能体所处的活动节点，指导模型再把周围子图转化为步骤级情境指引，在不替智能体作出硬性决定的情况下影响求解器的下一动作。

该图可以自我演化：LLM 精炼器对比失败轨迹与成功轨迹，编辑图的拓扑和属性；只有保持或提升留出验证集表现的修改才会提交，被拒绝的修改则被保留以阻止重复尝试。从最小骨架开始，这一循环能够构建达到或超过人工设计图的过程图，也能修复有缺陷的专家先验。

在多个数据集、任务类型和 LLM 上，过程图相对于记忆类基线带来一致改进，自演化还能在无需人工工程设计的情况下进一步改善表现。

</details>

<details>
<summary>现存问题</summary>

自由生成式智能体需要从长轨迹中反复重建当前进度、剩余步骤和动作依赖，轨迹越长越容易发生目标漂移、工具乱序和无效循环。

</details>

<details>
<summary>已有方法的不足</summary>

自由文本经验和检索式轨迹仍要求求解器自行恢复步骤关系；状态条件规则没有连接连续过程；工作流和状态机虽显式，却通常依赖人工设计，离线工作流搜索也不直接结合当前执行进度。

</details>

<details>
<summary>当前方法为什么可行</summary>

过程图把工具动作、推理步骤和任务状态编码为带条件、指引与陷阱属性的有向转换；运行时先定位当前节点，只检索局部连通邻域生成指引，离线再用成败轨迹提出拓扑修改，并通过留出集门控和拒绝记忆阻止退化。论文在七个任务族、四个模型及同求解器对照下评估，并报告局部化、构建方式、演化与成本分析；证据仍来自受控基准。

</details>

<details>
<summary>未来展望</summary>

作者明确提出复用或按需生成步骤指引以降低额外 token 成本，并检验过程图跨求解器和工具接口的迁移性。编辑推断：过程图可作为技能记忆与在线执行状态之间的中间层，但论文尚未证明其能跨工具模式变化长期保持有效。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.09153)

## 2. Revoked but Still Authoritative: An Empirical Study of Revocation Enforcement in Agent-Memory Systems

**中文译名：** 已撤销却仍具权威性：智能体记忆系统撤销执行的实证研究

**方向：** arXiv 预印本 v1／代码发布

**重要性排名：** #2

- **日期：** 2026-09-08
- **状态：** arXiv 预印本 v1／代码发布
- **Agent Memory 相关性：** 记忆生命周期中的撤销、检索有效性与执行安全
- **入选理由：** 直接测量五种主流记忆系统从软撤销到不安全行动的完整传播链，并把缺失控制定位到检索时有效性。

### 一句话概述

智能体记忆中的失效标记并不必然阻止旧策略被再次检索和执行，本文通过跨系统受控测量定位这一撤销缺口，并在记忆后端与智能体之间加入检索时有效性防护。

<details>
<summary>论文摘要翻译</summary>

长时间运行的语言模型智能体依赖持久记忆。许多智能体记忆系统通过软撤销保存历史：一条被矛盾信息推翻的事实会被标记为无效并继续保留，而不是被删除。然而，这一标记是否会在检索时真正执行，尚未得到研究。

本文测量了五种此类系统：向每个系统写入一项已撤销策略及其替代策略，在九种策略场景和九个模型上追踪已撤销事实是否会被检索返回，以及智能体是否随后据此行动，并在六种防御条件下为每次试验评分。研究发现，没有一个系统会默认在所有情况下执行撤销：只要撤销标签对检索层可见，已撤销事实仍可能被返回、排序高于替代事实，并使智能体采取不安全行动。

基于这些发现，作者开发了一个位于智能体与任意记忆后端之间的防护器，用来屏蔽已撤销或与替代记录冲突的记录，并开源了代码。

</details>

<details>
<summary>现存问题</summary>

软撤销保留了审计历史，却可能只写入“无效”元数据而不改变普通检索路径，使旧策略继续作为权威上下文影响写回、后续查询和工具行动。

</details>

<details>
<summary>已有方法的不足</summary>

记忆投毒防御和来源追踪主要处理恶意写入或来源可信度；它们没有回答一个更基础的问题：后端已经知道记录失效时，普通读取接口是否真的执行该状态。

</details>

<details>
<summary>当前方法为什么可行</summary>

研究把暴露率与暴露后的不安全行动率分开，在五个记忆系统、九个策略场景、九个执行模型和六个防御条件中进行配对测量；同一系统仅切换读取过滤标志即可在安全与不安全结果间切换，支持问题位于检索层的判断。所提防护器先使用显式撤销状态，再检测旧新记录冲突；它在有可靠状态标记时效果最稳。

</details>

<details>
<summary>未来展望</summary>

论文没有单列普适部署路线。编辑推断：记忆系统应把撤销状态作为检索接口的强制约束，并把过滤结果带到写回和工具执行边界；但现有证据来自固定场景网格，且缺少可靠标记时的冲突启发式会漏检或误屏蔽当前事实。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.08258)

## 3. MeClear: Cooperative Game-Theoretic Attribution and Risk-Aware Memory Clearance for Long-Horizon LLM Agents

**中文译名：** MeClear：面向长程 LLM 智能体的协作博弈归因与风险感知记忆清理

**方向：** arXiv 预印本 v1／代码发布

**重要性排名：** #3

- **日期：** 2026-09-08
- **状态：** arXiv 预印本 v1／代码发布
- **Agent Memory 相关性：** 读取阶段的有害记忆归因、抑制与恢复验证
- **入选理由：** 超越单条删除，把多条记忆的替代与联合伤害纳入因果归因，并保持底层持久记忆不被破坏。

### 一句话概述

语义相关的旧记忆、冲突记忆或冗余记忆可能共同损害当前任务，本文用采样式协作归因识别负效用组合，并通过查询范围内的最小可逆屏蔽验证任务恢复。

<details>
<summary>论文摘要翻译</summary>

长程大型语言模型智能体依靠外部记忆系统，在延续的交互中保存用户偏好和任务知识。传统检索机制优化语义匹配而不是下游效用，因此经常把过时、误导或互相冲突的证据引入活动上下文。

作者提出 MeClear，这是一种任务条件化的记忆清理框架，通过协作归因识别具有负面下游效用的记忆，并有选择地阻止它们进入智能体执行。MeClear 把留一法筛查与采样式协作 Shapley 归因结合起来，在相互作用的证据之间分配效用，从而解决单条删除评估无法发现的冗余冲突遮蔽。

利用归因排序，MeClear 在嵌套过滤序列上执行查询范围内的最小清理；它先在清理后的上下文中验证任务是否恢复，同时不永久改变持久记忆库。针对十个长对话记忆池的综合实验表明，MeClear 的目标召回率达到 85.9%，总体任务恢复率达到 82.3%，比留一法基线高 25.5 个百分点。

</details>

<details>
<summary>现存问题</summary>

高语义相似度并不等于对当前任务有用；多条过时或冲突记录还可能相互替代、共同致害，使单条记录的局部删除看不出任何改善。

</details>

<details>
<summary>已有方法的不足</summary>

相似度检索和准入过滤不测量下游行为影响；留一法与单记录反事实会被冗余伤害遮蔽；永久删除或改写又可能破坏同一记录在其他查询中的合法用途。

</details>

<details>
<summary>当前方法为什么可行</summary>

MeClear 固定已检索上下文，先用留一法排除明显有益记录，再通过不同证据联盟中的边际效用估计 Shapley 贡献；随后按负贡献构建嵌套屏蔽集合，只接受经任务恢复谓词验证且干预最小的上下文。论文还证明单条删除对冗余伤害的盲点，并在由 LoCoMo 对话合成、经因果核验的故障样例上与多种归因基线比较；因此证据尚不能直接代表自然生产流量。

</details>

<details>
<summary>未来展望</summary>

来源未给出系统性的未来工作清单。编辑推断：下一步应在自然产生的长期记忆冲突、不同任务代理和低调用预算下验证协作归因，并研究如何复用估值以降低多次重执行成本；现有实验不足以证明其适合实时大规模部署。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.09115)

## 4. Closing the Consistency Gap: Self-Evolving Agents That Learn to Stay on Course

**中文译名：** 弥合一致性鸿沟：学会保持正确轨道的自演化智能体

**方向：** arXiv 预印本 v1／代码发布

**重要性排名：** #4

- **日期：** 2026-09-08
- **状态：** arXiv 预印本 v1／代码发布
- **Agent Memory 相关性：** 轨迹诊断、情景记忆抽取与跨任务复用
- **入选理由：** 将平均成功率掩盖的重复运行不稳定性定义为独立目标，并把易翻转步骤转化为可检索的针对性记忆。

### 一句话概述

智能体在同一任务上可能平均表现良好却无法稳定复现成功，本文通过黑盒重采样定位易翻转的轨迹步骤，并把诊断转化为供相似任务检索的情景记忆指引。

<details>
<summary>论文摘要翻译</summary>

由大型语言模型驱动的智能体可能平均而言准确，却在生产环境中并不可靠；这种差异虽已被观察到，却基本没有得到解决。在同一任务上运行五次时，使用 GPT-4.1 的 ReAct 智能体在 AppWorld 基准中只有 53% 的任务能够五次全部成功，尽管其单次运行通过率平均为 77%。作者把这 24 个百分点的差距称为“一致性鸿沟”，并认为解决它是可信部署 AI 智能体的前提。

作者提出一个缩小这一鸿沟的自演化智能体框架：识别轨迹中不稳定、低一致性的步骤，并将其转化为未来运行可调用的情景记忆。核心组件包括一致性分析器，用来定位轨迹在何处以及为何可能跨运行发生翻转；以及指引生成器，把诊断转化为有针对性的规则，写入记忆并注入后续相似任务的执行。

在采用 ReAct 与 GPT-4.1 的 AppWorld 实验中，该框架使同任务评估中五次全部成功的任务比例提高 16 个百分点，并使相似任务泛化评估中的该比例提高 13 个百分点。

</details>

<details>
<summary>现存问题</summary>

常用平均成功率无法显示同一任务跨运行反复失败的概率，而只从明显失败轨迹提炼经验，又会漏掉本次成功但决策分布高度不稳定的步骤。

</details>

<details>
<summary>已有方法的不足</summary>

既有轨迹记忆方法主要从结果或生成模型的自我判断抽取规则，缺少步骤级的稳定性信号；传统 Pass@k 还强调“至少成功一次”，无法衡量部署所需的重复成功。

</details>

<details>
<summary>当前方法为什么可行</summary>

分析器在不访问模型内部的情况下重采样每个推理点，按响应类型计算步骤一致性，再把低一致性决策标给指引生成器；生成的策略、恢复和优化规则带元数据写入情景记忆，并按相似任务检索。AppWorld 上的同任务和兄弟任务实验支持这些规则能够迁移，但仅覆盖 ReAct、两个模型族和一个受控应用环境。

</details>

<details>
<summary>未来展望</summary>

作者明确提出在记忆准入前验证每条指引，避免模糊、冲突或过拟合规则，并扩展到更多模型和已有策略记忆的智能体栈；还需通过自适应采样降低逐步骤重采样成本。论文同时强调，一致性分析器不是正确性验证器，稳定的错误同样会得到高分。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2609.08832)

## 5. SkillAdam: Stable and Efficient Skill Evolution for Agents

**中文译名：** SkillAdam：稳定且高效的智能体技能演化

**方向：** arXiv 预印本 v1／代码发布

**重要性排名：** #5

- **日期：** 2026-09-08
- **状态：** arXiv 预印本 v1／代码发布
- **Agent Memory 相关性：** 技能记忆的跨轮优化、稳定性与更新幅度控制
- **入选理由：** 为非参数化技能文档引入持久优化状态和证据驱动的编辑预算，并覆盖短程与长程任务及消融、迁移和成本分析。

### 一句话概述

基于局部执行反馈反复改写技能文档容易覆盖既有有效经验并产生不稳定更新，本文用跨轮问题与尝试记录稳定修改方向，再依据近期效果波动自适应限制编辑范围。

<details>
<summary>论文摘要翻译</summary>

智能体技能为冻结参数的语言模型智能体提供领域知识和过程指引，是一种轻量方式，但获得高质量技能成本高昂且难以扩展。专家编写技能需要大量人力；近期技能自演化方法利用执行反馈在迭代循环中自动修改技能，但启发式更新策略经常导致优化不稳定、迭代效率低下。

作者指出稳定且高效的技能自演化面临两个挑战。“方向稳定性”要求有效修正持续累积，而不是被当前迭代的局部反馈覆盖；“更新自适应性”要求每次修改的范围能够反映近期样例级改善的一致程度。作者据此提出 SkillAdam，一个受 Adam 启发、用于优化离散且不可微技能文档的框架。

作为 Adam 一阶矩的功能类比，优化记忆会记录已识别问题和以往解决尝试的结果，以稳定更新方向；作为二阶矩的功能类比，波动驱动的编辑预算追踪近期样例级改善的历史加权变化，并自适应控制修改幅度。

在覆盖短程和长程任务的七个基准上，SkillAdam 取得了当前最佳表现，优化动态更加稳定；相较既有方法，它还通过更少的优化迭代和更低成本得到更强的技能。作者同时发布了代码仓库。

</details>

<details>
<summary>现存问题</summary>

技能自演化每轮只看到有限样例，新的修正可能推翻此前已验证的约束；当反馈在不同样例上的效果不一致时，大范围编辑尤其容易造成退化。

</details>

<details>
<summary>已有方法的不足</summary>

现有提示优化和技能自演化方法会保留候选及分数、执行验证或进行有界编辑，但通常没有同时维护“该继续解决什么问题”和“本轮应修改多少”的跨迭代优化状态。

</details>

<details>
<summary>当前方法为什么可行</summary>

Evolving Issue Tracker 持久记录问题、状态和历史解决结果，为每轮修改提供累积方向；波动驱动预算根据样例级收益的一致性收紧或放宽编辑范围，再由多指标接受门控阻止受保护指标退化。七个基准、累积消融、跨模型迁移和调用成本分析共同支持完整框架，但接受决策未使用额外验证集，稳定性轨迹也只展示一次运行，不能把收益完全归因于优化记忆本身。

</details>

<summary>未来展望</summary>
