## 1. Forgetting Without Restarting: Execution-State Unlearning for Stateful LLM Agents

**中文译名：** 无需重启的遗忘：面向有状态 LLM 智能体的执行状态反学习

**方向：** arXiv v1

**重要性排名：** #1

- **日期：** 2026-09-04
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 记忆删除、派生状态清理、来源追踪与可验证遗忘
- **入选理由：** 把“删除记录”提升为覆盖摘要、计划和缓存的反事实执行状态恢复问题，并同时给出下界与系统方案。

### 一句话概述

现有遗忘操作无法清除已传播到摘要、计划和缓存中的信息，本文通过来源图定位注入点、恢复干净检查点并重放净化后的后缀来重建未观察目标信息的执行状态。

<details>
<summary>论文摘要翻译</summary>

长期运行的 LLM 智能体具有状态性：除会话记录外，它们还会积累压缩摘要、明文记忆、待执行工具计划，以及所有服务 API 都存在的 KV 缓存；然而，今天的“遗忘”操作通常只删除一条明文记忆记录，所有由被撤销信息派生的产物仍被保留。本文形式化提出执行状态反学习：收到遗忘请求后，智能体的行为应当如同从未观察到目标信息。作者把运行时建模为确定性转移系统，证明目标出现前的轨迹前缀可以免费复用；若没有词元级归因，目标之后的后缀不可避免地受到污染；精确反学习至少需要重新计算 T−τ+1 次转移，其中 τ 是目标的注入步骤。来源引导的选择性重放以跨提示、压缩记忆和缓存的契约达到这一下界：来源图定位注入点，恢复检查点可化为裁剪 KV 缓存，净化后的重放则重新生成反事实后缀。作者在三个智能体套件、九种基线和三个模型系列上采用诱导、随机及无字符串行为测试进行审计；普通记忆删除不会降低泄漏，基于指令的遗忘在诱导测试下失效，源文本删改仍会影响对已撤销偏好的行为，而选择性重放在审计中与完整重置不可区分，且最多减少九倍重算词元。

</details>

<details>
<summary>现存问题</summary>

敏感信息一旦进入长时智能体，会继续影响压缩摘要、工作记忆、未执行计划和 KV 缓存；只删除可见记录无法证明后续行为已消除该信息的影响。

</details>

<details>
<summary>已有方法的不足</summary>

明文删除和源文本删改遗漏派生状态，指令式遗忘可能只是压制输出，信息流控制只能阻止新的危险流向而不能净化已污染状态；完整重置虽可恢复，却重复计算本来干净的前缀。

</details>

<details>
<summary>当前方法为什么可行</summary>

方法把遗忘定义为与“从未观察目标”的反事实状态等价：来源图确定最早污染边界，目标之前的检查点与反事实轨迹相同，裁剪缓存后只需重放净化的后缀。论文给出 T−τ+1 的重算下界，并在多个套件、基线和模型系列中用字符串泄漏与行为影响审计验证运行时恢复；保证不覆盖模型参数、已提交外部副作用或目标的相关信息。

</details>

<details>
<summary>未来展望</summary>

作者明确限定当前保证只覆盖可重建的运行时状态，不能撤销模型参数、已提交副作用，也不处理会因目标缺失而改变的人类后续回合。编辑推断：下一步需要把来源追踪扩展到可回滚工具副作用、随机交互和更细粒度影响归因；这些扩展尚未被本文证明。

</details>

**原始来源：** [arXiv 主页面](https://arxiv.org/abs/2609.04875)

## 2. Does Your Agent's Memory Survive a Model Upgrade? A Controlled Study of Memory Portability

**中文译名：** 模型升级后，智能体记忆还能保留吗？一项记忆可移植性的受控研究

**方向：** 审稿中

**重要性排名：** #2

- **日期：** 2026-09-04
- **状态：** 审稿中（arXiv 预印本 v1）
- **Agent Memory 相关性：** 长期记忆迁移、嵌入索引兼容性与灾后修复
- **入选理由：** 首次在统一受控条件下拆分记忆写入、检索和读取阶段，直接回答模型或嵌入升级时什么会失效。

### 一句话概述

模型或嵌入组件升级可能在存储仍可用时悄然破坏记忆，本文通过受控比较原始历史、RAG、自然语言笔记和固定模式知识图谱来定位迁移损失及可恢复条件。

<details>
<summary>论文摘要翻译</summary>

模型升级很常见，记忆迁移却并非如此；即使保留同一个记忆库，智能体仍可能遗忘，因为新模型可能以不同方式解释旧笔记，混合不同嵌入版本可能破坏检索，而缺少原始证据时修复可能失败。本文比较同一段历史以四种方式保存时的表现：逐字保留供长上下文读取（LC-RAW）、切分后用于检索增强生成（RAG）、由模型压缩成自然语言笔记（NOTES），或规范化为固定模式知识图谱（KG-fixed）。研究使用 48 段带随机答案编码的合成历史、精确评分，以及两个参数量低于 100 亿的开放权重模型。测量显示，固定模式结构能够可靠迁移，写入模型替换后 KG-fixed 的准确率变化仅为 +0.0004±0.0020；相反，压缩笔记与模型高度耦合，不同迁移方向会分别带来 +9.91 或 −13.28 个百分点的非对称变化。在 RAG 系统中，使用新旧嵌入各半的部分迁移索引只获得 4.96 个百分点的提升，丢失了完整重嵌入所获 11.90 个百分点增益中的大部分。诊断分解表明，NOTES 准确率缺口的 80% 源于初始构建阶段的信息损失，而 RAG 缺口的 81% 来自检索失败。最后，仅依靠已有存储修复 NOTES 在全部 48 个测试案例中都未达到 90% 的性能恢复目标；保留原始历史后，其中一个迁移方向有 34 个案例成功恢复。这些发现强调了按迁移方向测试、严格隔离嵌入空间以及为记忆修复保留源历史的必要性。

</details>

<details>
<summary>现存问题</summary>

智能体记忆库的生命周期往往长于生成或读取它的模型，但系统通常把升级视为普通数据复制，缺少对写入者、读取者、嵌入器和修复来源的分离测试。

</details>

<details>
<summary>已有方法的不足</summary>

现有工作多在单一架构或单一迁移设置下研究跨模型传递；自然语言笔记可能在写入时丢失证据，RAG 会在部分重建索引时静默漏检，而没有原始历史的存储改写无法恢复已经被压缩掉的信息。

</details>

<details>
<summary>当前方法为什么可行</summary>

实验固定历史和读取者，分别改变写入模型、嵌入空间或修复来源，并用随机答案编码和精确评分排除预训练记忆与模型裁判干扰；四类表示的统一比较进一步把损失拆到写入、检索和读取阶段。证据只覆盖两个规模相近的开放模型、一个单阶段密集检索器和合成历史，不能推出固定模式知识图谱在所有任务上都更优。

</details>

<details>
<summary>未来展望</summary>

作者提出迁移前执行方向相关测试、隔离不同嵌入空间并保留可恢复的源历史，同时提醒原始历史会增加隐私、保留和删除义务。编辑推断：后续应在真实跨会话历史、更广模型规模、多阶段或混合检索器上验证兼容性，并研究兼顾可修复性与最小数据保留的机制；本文证据尚不足以确定通用方案。

</details>

**原始来源：** [arXiv 主页面](https://arxiv.org/abs/2609.05339)

## 3. Linguistic Trajectory Encoding for Efficient Long-Horizon Spatial Memory in Embodied Agents

**中文译名：** 面向具身智能体高效长时空间记忆的语言轨迹编码

**方向：** arXiv v1

**重要性排名：** #3

- **日期：** 2026-09-04
- **状态：** arXiv 预印本 v1／新基准
- **Agent Memory 相关性：** 多模态记忆编码、动态物体轨迹检索与长时空间状态
- **入选理由：** 补上现有具身记忆缺少“可用自然语言查询的逐物体状态变化时间线”这一明确表示与评测空白。

### 一句话概述

具身智能体难以在跨小时至数天的观察中查询动态物体的状态变化，本文用语言描述、稀疏空间锚点和视觉锚点联合压缩每个物体的长期运动轨迹。

<details>
<summary>论文摘要翻译</summary>

执行长时任务的具身智能体需要一种记忆表示，使动态物体的状态转移在跨越数小时至数天的观察范围内仍可通过自然语言查询。现有系统要么丢失细粒度运动信息，如片段级视频—语言嵌入；要么只用原始坐标保留运动，如几何 SLAM；要么围绕即时任务上下文组织信息，如智能体工作记忆。这些方法都没有为智能体提供逐物体时间线，使其中的状态转移本身能够以语言查询。本文的核心贡献是语言轨迹编码（LTE），它通过结合自然语言描述、稀疏空间锚点和视觉锚点的混合表示来压缩动态物体的运动历史。LTE 根据运动复杂度调整压缩方式：对缺少可靠观察的时段锚定在最后可见位置，并用几何路径点和语言描述表示运动以保持准确性。为在延长的时间范围内评估这些能力，作者基于 EgoLife 多日记录构建空间记忆基准（SMB），针对现有基准缺少的语义轨迹检索和长时物体检索能力。LTE 系统在 SMB 的语义轨迹检索和长时物体检索上分别取得 45.3% 和 48.7% 的成功率，超过结构化记忆和 VLM 基线；它在 24 小时视频上实现 8.7 至 26.1 倍轨迹压缩和亚秒级查询延迟，并在 Ego4D 自然语言查询上达到 28.75%/55.10% 的 R@1/R@5。

</details>

<details>
<summary>现存问题</summary>

长期具身观察不仅要记住物体在哪里，还要回答物体何时、如何移动以及状态如何变化；现有表示缺少兼顾语义可查询性、空间精度和长时间压缩的逐物体轨迹。

</details>

<details>
<summary>已有方法的不足</summary>

片段级视频语言嵌入会抹平细粒度运动，几何 SLAM 保留坐标却缺少语言语义，面向当前任务的工作记忆又不能稳定覆盖多日历史；现有基准也没有同时测量语义轨迹检索与长时物体检索。

</details>

<details>
<summary>当前方法为什么可行</summary>

LTE 先按运动阶段生成语言描述，再以稀疏三维位置和视觉裁剪提供几何与外观锚点，并根据观测可靠性调整压缩；SMB 和 Ego4D 分别检验长时家庭环境及较短跨环境查询，消融显示语言描述、视觉锚点和空间索引承担不同功能。证据仍受上游跟踪与三维重建误差影响，长时测试仅覆盖 EgoLife 家庭场景。

</details>

<details>
<summary>未来展望</summary>

作者明确提出扩展到关节部件动态、多摄像头融合、下游规划器，以及办公室、仓库和户外环境；附录还指出跨环境使用需要物体重识别与地图对齐。编辑推断：若作为通用 Agent Memory，还需加入隐私可控的保留策略和对不确定轨迹的修订机制；本文未验证这些能力。

</details>

**原始来源：** [arXiv 主页面](https://arxiv.org/abs/2609.04802)

## 4. From Interaction Traces to Persistent Skills: Online Evolution for Computer-Use Agents

**中文译名：** 从交互轨迹到持久技能：计算机使用智能体的在线演化

**方向：** 代码已发布

**重要性排名：** #4

- **日期：** 2026-09-04
- **状态：** arXiv 预印本 v1／代码发布
- **Agent Memory 相关性：** GUI 轨迹抽象、程序记忆写入、版本演化与来源审计
- **入选理由：** 把计算机使用经验做成可版本化的共享程序记忆，并罕见地同时报告跨任务复用与无效反复修订。

### 一句话概述

计算机使用智能体的交互经验通常随单次执行消失，本文把轨迹和评估反馈转成在后续迭代中可检索、修订且保留来源的持久技能库。

<details>
<summary>论文摘要翻译</summary>

计算机使用智能体能够在图形界面中执行日益复杂的任务，但其交互经验通常是短暂的：一次执行中获得的程序知识不会被系统性地保留、改进并在后续任务中复用。现有技能库提供外部程序知识，但相对于同一智能体在无技能条件下的增量价值，以及技能库在重复交互中的长期动态，仍缺少充分刻画。本文提出一个在线技能演化框架，把交互轨迹和评估器反馈转换成持久、带版本的可复用程序库。每次迭代都针对冻结的技能库快照执行，基于证据的技能更新只在后续迭代中可用，而无需修改模型参数。作者在四个 OSWorld 应用领域中，把完整演化技能库系统与配置匹配的空技能库控制组进行比较，两者使用相同的固定动作生成与 GUI 定位栈、任务集和迭代周期。经过五轮空技能库预热后，完整系统在四个观测领域运行中的预热后平均评估分都更高，平均差异为 5.7 至 18.6 个百分点，时间稳定性因领域而异。在 GIMP 中，带来源的分析发现技能会跨越其来源任务被检索，也发现修订震荡：多次被接受的编辑仍不能恢复来源任务。这些发现把演化技能库刻画为可审计、共享的程序记忆，它可以改善固定的计算机使用栈，但收益具有条件性，反复修订也不保证恢复。代码已经发布。

</details>

<details>
<summary>现存问题</summary>

GUI 智能体会积累大量可复用操作经验，但原始轨迹过细，技能修改又可能在运行中污染当前实验；同时，仅观察技能被检索并不能证明它真正被遵循或带来收益。

</details>

<details>
<summary>已有方法的不足</summary>

既有程序记忆研究证明技能可以表示、检索或组合，但对同一固定执行栈下技能库相对空库的长期增量价值、版本来源和失败驱动过度修改缺少匹配观察；单纯的技能调用记录也无法建立因果归因。

</details>

<details>
<summary>当前方法为什么可行</summary>

框架把每轮执行固定在只读快照上，再用官方评估器结果、动作轨迹、截图和技能调用遥测形成结构化事实；协调器约束创建、编辑和删除，Git 提交保存每次变更来源，后续轮次才读取新版本。四个 OSWorld 应用领域的配置匹配比较和 GIMP 来源分析支持其可用性，但每个条件—领域只有一次运行、重复同一任务集且存在预热不平衡，因果强度有限。

</details>

<details>
<summary>未来展望</summary>

作者明确提出增加重复运行、留出任务、匹配组件消融和技能遵循测量，并在原生计算机动作智能体上验证；还建议用强化学习按下游效用优化技能修改，抑制修订震荡。编辑推断：自动合并、回滚和顺序无关的并行演化也是长期程序记忆需要解决的能力，但本文尚未实现。

</details>

**原始来源：** [arXiv 主页面](https://arxiv.org/abs/2609.04869)

## 5. TROVE: Adaptive Agent Skill Orchestration via Trace-Grounded Route Validation and Editing

**中文译名：** TROVE：通过轨迹驱动的路线验证与编辑实现自适应智能体技能编排

**方向：** arXiv v1

**重要性排名：** #5

- **日期：** 2026-09-04
- **状态：** arXiv 预印本 v1
- **Agent Memory 相关性：** 经验轨迹蒸馏、技能层级、转移记忆与运行时局部重规划
- **入选理由：** 将历史执行轨迹从被动案例库变成可验证的技能与状态转移结构，补强程序记忆的在线使用阶段。

### 一句话概述

预先确定的技能路线会因运行时结果而过时，TROVE 从已评估轨迹提炼复合技能和结果条件转移图，并仅保留、插入或替换被新证据影响的后续路线。

<details>
<summary>论文摘要翻译</summary>

智能体往往在决定性运行结果出现之前，就优化、选择或约束执行结构。然而，这种执行前承诺会造成编排瓶颈：当中间证据使待执行的后续步骤失效时，智能体只能继续执行过时步骤或进行大范围重规划，从而累积错误、浪费计算并丢弃已有进展。为此，本文提出基于轨迹的路线编排、验证与编辑方法 TROVE，它只修改被运行时证据判定为无效的部分。在线下，TROVE 把经过评估的工作流搜索轨迹蒸馏为原子技能、复合技能和结果条件转移图，在保留稳定片段的同时暴露依赖结果的决策。在线上，它把计划路线视为暂定方案：每次只提交一个顶层技能，随后保留仍有效的后续路线、插入由轨迹支持的局部响应，或只替换失效的后缀。作者在代码生成、问答和数学推理基准上使用不同 LLM 骨干进行评估，结果显示 TROVE 相比数据集级优化、查询级架构选择和图约束调度基线取得更好的质量—效率权衡；当运行结果会改变适当后续步骤时质量增益最大，而在接近饱和的任务上，提前终止可显著提升效率。消融进一步表明，复合技能承担大部分离线收益，插入操作支持局部纠正，后缀替换主要改善效率。这些发现把选择性路线编辑确立为自适应智能体编排的一项通用原则。

</details>

<details>
<summary>现存问题</summary>

技能编排器常在执行前锁定完整工作流，但测试、审阅或工具失败产生的新证据可能让尚未执行的后缀失效；全量重启会丢弃有效进展，逐步重新规划又增加成本和决策波动。

</details>

<details>
<summary>已有方法的不足</summary>

AFlow 固定数据集级工作流，MaAS 在运行前选择查询级架构，LAS 只能在预定义图中在线选路；它们分别缺少结果出现后的结构修改能力，或无法在保留已完成前缀的同时重建图外后缀。

</details>

<details>
<summary>当前方法为什么可行</summary>

离线搜索轨迹提供局部结构变更及其质量、时间证据，稳定片段被封装为复合技能，结果相关关系留在转移图；在线控制器只执行路线首个技能，再按最新边界状态选择保留、局部插入或后缀替换。六个基准、三个骨干及消融支持这一机制链，但在线时间与词元统计排除了离线搜索和轨迹蒸馏成本，任务也主要是静态代码、问答和数学基准。

</details>

<details>
<summary>未来展望</summary>

论文结论没有提出明确的后续研究计划。编辑推断：需要在真实工具环境和长时间任务中验证转移图面对状态漂移的稳健性，并把离线构建成本、错误轨迹污染和跨任务技能迁移纳入统一评估；现有证据不足以证明这些能力。

</details>
