## 1. ModHarness-RL: Recasting Harnesses as Learnable and Evolving Programs for Agentic RL

**中文译名：** ModHarness-RL：将智能体强化学习的运行框架重构为可学习、可演化的程序

**方向：** Task D · 2026-11-17 · 轨迹处理与诊断后自进化

**今日研究优先级：** #1

- **日期：** 2026-11-13（arXiv 首投日）
- **状态：** arXiv v1 预印本；未核实正式录用
- **研究相关性：** 逐轮交互→类型化状态块→压缩视图与失败触发器→回放筛选→持久引导程序及策略权重更新。
- **入选理由：** 首次报告；把证据处理、失败模式回放和更新准入连成可执行闭环，直接连接本任务两条研究主线。

### 一句话概述

针对固定运行框架难以适应智能体训练中行为变化的问题，该方法将交互整理为类型化状态块，并从轨迹中学习上下文压缩程序和可回放的纠偏引导程序。

<details>
<summary>论文摘要翻译</summary>

智能体强化学习越来越依赖运行框架，即决定模型看到哪些自身交互信息、获得何种引导的外围支撑结构。现有方法大多在手写且始终固定的框架下训练，但有效框架依赖领域、数据和模型，并随模型训练而变化。我们提出 ModHarness-RL，将框架重构为从数据学习、随强化学习训练演化的程序。它把交互记录为由类型化块组成的结构化状态，并将两个核心组件表示为操作这些块的程序：Compression 将累积历史组织为模型上下文，Steering 在行为偏离时提供引导。训练期间，系统依据近期轨迹提出候选程序，通过执行验证，并在过去轨迹上回放，使框架跟踪模型行为变化。我们深入研究 CodeSearch，并进一步分析 ALFWorld 和 BIRD SQL，模型规模为 1.5B 至 8B。所提压缩与引导机制在多数设置下改善了相对固定框架基线的留出集表现。这些结果表明，智能体强化学习框架可以从任务数据中学习，并与模型共同演化。

</details>

<details>
<summary>现存问题</summary>

工具输出中的冗余信息挤占上下文；训练中有些错误自行消失，另一些持续存在，固定提示无法区分应介入的失败。

</details>

<details>
<summary>已有方法的不足</summary>

手工框架长期不变；在线模型摘要需要额外调用。论文比较了记忆、技能、提示和框架优化方法，但完整方法与全部基线的比较主要限于 CodeSearch。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入单位为每轮动作—观察及推理、工具名、参数、返回值等类型化块；压缩只改呈现视图，原始状态仍保留。Compression 在训练前选定后冻结；Steering 从同任务成败轨迹提出触发器，回放历史训练轨迹形成失败频率曲线，经判断与留出任务准入后保留，并与 GRPO 权重更新交替。CodeSearch 使用 Lite/Verified/Pro 的 100/100/88 个定位任务，指标是文件、模块、实体 F1 的均值，不是修复成功率；Qwen3-8B 限制上下文设置由 0.333 至 0.412。历史触发器回放不等于执行干预后的反事实成功验证，后者另由准入执行承担；本次未复现。

</details>

<details>
<summary>未来展望</summary>

作者指出应扩大准入样本，并在 ALFWorld、BIRD SQL 补齐完整方法及基线比较。编辑推断：可将类型化回放扩展为诊断证据接口；开放式对话中难以规则化的语义错误仍缺充分证据。

</details>

## 2. Beneath the Surface: What We Overlook When We Talk About Agent Evolution

**中文译名：** 表象之下：讨论智能体进化时我们忽略了什么

**方向：** Task D · 2026-11-17 · 诊断后自进化与回归评估

**今日研究优先级：** #2

- **日期：** 2026-11-05（arXiv 首投日）
- **状态：** arXiv v1 预印本；未核实正式录用
- **研究相关性：** 跨版本轨迹与任务结果→行为证据包→诊断和依赖闭合修改→准入→冻结版本重复评估。
- **入选理由：** 首次报告；将平均表现、任务覆盖、旧能力损失和修改兼容性拆开测量，并把审计发现落实为经过评估的进化算子修改。

### 一句话概述

针对智能体进化的总分掩盖旧能力退化与修改相互干扰的问题，该研究通过逐任务重复评估、组件干预和准入回放诊断进化过程，再据此修订选择、分析、修改与准入算子。

<details>
<summary>论文摘要翻译</summary>

智能体运行框架进化可在不更新模型权重的情况下实现递归自我改进。我们考察更高的基准分数是否带来可靠、高效且可迁移的改进，并跨运行框架、通用任务和编程任务评估四种方法。重复评估、受控候选扩展、组件干预和准入回放揭示了反复出现的模式：全部十六个进化后智能体都获得了此前未覆盖的任务，同时失去了此前已覆盖的任务。在一个通用任务案例中，可靠性上升 5.2 个百分点，却失去了十个此前覆盖的任务。大多数可靠性收益也增加了部署成本。具体修改通常胜过泛化提醒，但组合后收益可能改变。在四个候选池中，得分最高的智能体都未产生最大的平均后续改进，更严格的准入还可能丢弃有用替代方案。迁移只保留部分收益：通用任务目标上的覆盖率通常在两类框架与不同范式下下降，而仅允许外层修改的框架在编程目标上覆盖率上升。这些发现支持关注能力保留的评估、经过检验的决策规则和明确的适用条件。作为建设性后续，EvoAudit 将这些诊断转化为选择、分析、修改与准入的修订，取得了最佳表现。

</details>

<details>
<summary>现存问题</summary>

新解决任务可抵消旧任务退化；当前最强版本未必最值得继续进化，单个有益修改也可能在组合后失效。

</details>

<details>
<summary>已有方法的不足</summary>

只用最终平均分选择和接纳版本，无法反映覆盖变化、部署成本及修改依赖；一味收紧准入也可能丢失候选。论文没有证明统一准入规则适合所有框架。

</details>

<details>
<summary>当前方法为什么可行</summary>

AGE 从本轮及上一轮谱系轨迹构建限长证据包，保留工具调用、成败返回和结束信号；诊断输入排除基准奖励与隐藏测试，区分观察和推断。修改目标为允许的提示、技能、编排或源码，跨运行保留；验证分数改善，或同分且可比成本下降，才准入。研究比较四方法×两框架×两基准，冻结版本各重复八遍；Avg@8 分母为任务数×8，Pass@8 分母为任务数，不能混用。AGE 的收益来自四项组合修订，未独立证明每项修订的因果贡献；主表还包含训练/验证任务，外部迁移与留出结果须单独看。

</details>

<details>
<summary>未来展望</summary>

作者主张按决策分别评估后续收益、修改兼容性、保留候选质量及成本。编辑推断：可把旧任务损失谱系作为长期监测对象；有限基准、单次进化种子和专家认可不足以证明部署安全。

</details>

## 3. Silent Instrument Errors Reorder Agent Leaderboards

**中文译名：** 静默的评测工具错误会重排智能体排行榜

**方向：** Task D · 2026-11-17 · 轨迹数据处理与评测审计

**今日研究优先级：** #3

- **日期：** 2026-11-03（arXiv 首投日）
- **状态：** arXiv v1 预印本；两排行榜的实证审计
- **研究相关性：** 嵌套 span、动作列表、评分终止事件与评测器版本→去重、来源对齐和重计分→可信诊断与回归输入。
- **入选理由：** 首次报告；直接证明轨迹和评分记录本身可能污染诊断、训练与排序，给出能落到数据处理层的审计规则。

### 一句话概述

针对智能体排行榜的成本、动作记录和评分流程会静默失真的问题，该研究从公开底层轨迹重建调用与动作来源并交叉重计分，以定位评测工具链中的错误。

<details>
<summary>论文摘要翻译</summary>

在一个公开智能体排行榜上，通用智能体在涉及数据库的任务上，比专为航空客服基准构建的框架落后十三个百分点，读者可能由此认为通用性牺牲了准确性。差距来自评分器：通用智能体经常以不触发评分的方式结束对话，因此只有约一半回合被评分，其余被存成失败。按照基准自身规则给未评分部分补评分，无需重跑智能体便能消除汇总差距。我们仅用公开产物审计维护良好的 HAL 和 τ²-bench 两个排行榜，又发现三种评测工具错误：成本列不均匀地重复计算嵌套模型调用；归档轨迹把评分器写入的动作记为智能体动作；用新评测器重评旧轨迹本身就是一次新测量，一次正确且已公告的修复改变排名，而误读四个文件的模式检查使分数下降五十九至八十二个百分点却未报错。所有错误都产生了看似合理的数字，HAL 维护者在五周内确认了其中三项。案例共同表明，负责评分、日志、回放和版本管理的基础设施是测量的一部分，而且会静默失效，使分数和排名在无明显征兆时变化。这些模式来自评测流水线的构造，而流水线与智能体变化同样迅速，因此我们预计其他地方也存在类似问题。我们提出低成本检查：报告实际评分比例、从根 span 汇总成本、标注每条动作的来源，并固定评测器版本、公布重评分差异。

</details>

<details>
<summary>现存问题</summary>

未评分被写成失败，包装层与子调用重复计费，评分器回放混入智能体动作；合理数值无法暴露这些来源错误。

</details>

<details>
<summary>已有方法的不足</summary>

标准化日志、公开代码及奖励规则审计，不能保证运行时正确应用规则；仅裁掉动作列表尾部还会漏掉位于中间的评分器动作。

</details>

<details>
<summary>当前方法为什么可行</summary>

按工具名和参数顺序，将原始模型调用对齐到归档动作，分离评分器来源；对 span 按根调用或响应标识去重，再固定环境与评测器重放。论文成本分析单位为 134 个运行，动作污染分析为 2,334 条航空记录；不是一次处理全部公开语料。主要航空对比分母限定于 50 项任务中的 41 项及九个共有模型，离线重评分只覆盖数据库与输出条件。作者仓库有更正记录；使用论文修订口径，不沿用早期夸大的排名变化。本次仅核验论文与仓库，未运行脚本，也未确认当前线上排行榜已修复。

</details>

<details>
<summary>未来展望</summary>

作者建议随归档附带机器可读勘误、逐动作来源和重评分差异。编辑推断：可把评分覆盖率及回放错配率设为训练数据准入条件；两排行榜案例不足以估计全行业错误发生率。

</details>

**原始来源：** [arXiv 原始论文](https://arxiv.org/abs/2611.04399)

## 4. Executable Prefix Values for Locating Agent Failures

**中文译名：** 用可执行的轨迹前缀价值定位智能体失败

**方向：** Task D · 2026-11-17 · 诊断证据与执行回放

**今日研究优先级：** #4

- **日期：** 2026-10-13（arXiv 首投日）
- **状态：** arXiv v1 预印本；历史高价值补充
- **研究相关性：** 轨迹步骤与环境指纹→可重建中间状态→续跑成功概率曲线→定位价值下降与重启决策。
- **入选理由：** 历史高价值补充；把文本错误标签与执行价值下降分开检验，为失败归因提供独立于裁判一致性的参照。

### 一句话概述

针对文本裁判标出的首个错误可能只是失败症状的问题，该研究从经校验重建的轨迹中间状态多次续跑，估计前缀价值曲线以定位价值下降和可重启位置。

<details>
<summary>论文摘要翻译</summary>

调试大语言模型智能体的研究，把人类或模型裁判标出的“首个错误”视为轨迹失败位置的真值。我们询问这些标签指向原因还是症状，并让这种区别能够通过执行检验：从失败轨迹重建的中间状态重启智能体，估计其前缀价值 V(h_t)，即从每一步继续执行的成功概率，并为失败确定经过认证的不归点。在 150 个 SWE-bench Verified 任务上，使用两个冻结的开放权重智能体，我们分别为 47 和 60 条失败轨迹构建曲线，并检验四个前沿裁判按照 Traverse 规则标出的每一步。我们发现标签并未准确指示控制器所需位置。不同谱系裁判仅在 57 个案例中的 21 个对精确步骤一致，最新裁判还在两个智能体各自的 10 条成功运行中，分别给 8 条和 10 条标出错误。66% 的标签所指步骤并未发生成功概率下降；188 个回答中只有 7 个指出决定性步骤。在测得的重启点重启，使离线预期成功率从 0.44 升至 0.57，实际重启也确认了其优势；按裁判标签重启则没有这种收益，变化为 −0.08 至 −0.03。我们发布了代码、曲线和标签。

</details>

<details>
<summary>现存问题</summary>

“首个看起来错误的步骤”未必损害后续成功机会；失败还可能由多个小幅退化累积，强行标单步会混淆症状与责任。

</details>

<details>
<summary>已有方法的不足</summary>

按裁判或人工标签一致性排名，缺少对真实执行后果的检验；固定早停、盲目按标签重启还可能中断本会成功的运行。

</details>

<details>
<summary>当前方法为什么可行</summary>

命令回放后校验规范化观察、文件变化与 Git 状态，错配轨迹剔除并同层补样；以轨迹×步骤×随机种子续跑，补丁去重后用官方测试评分，输出成功比例、区间与价值下降位置。主策略 47 条曲线使用 15,576 次续跑；实际重启检查为 30 条选定轨迹各八次。0.44→0.57 是假定价值策略不误重启成功运行的离线估计，不能写成部署成功率；第二策略的剩余预算耗尽检查未通过。价值依赖冻结策略及预算，重启不构成持久自进化，本次未复现。

</details>

<details>
<summary>未来展望</summary>

作者主张用捕获的价值损失及稳健重启边界评估定位器。编辑推断：可蒸馏低成本前缀价值预测器，但需先验证成功轨迹上的误干预和跨策略校准；论文未证明普适因果根因。

</details>

**原始来源：** [arXiv 原始论文](https://arxiv.org/abs/2610.17633)

## 5. Synthesizing Code Completion Trajectories for Mid-training in Software Engineering

**中文译名：** 合成用于软件工程中期训练的代码补全轨迹

**方向：** Task D · 2026-11-17 · 轨迹构建与诊断信号蒸馏

**今日研究优先级：** #5

- **日期：** 2026-11（正式刊载月份；具体发布日期未标注）
- **状态：** IJCNLP-AACL 2026 Findings 正式论文；代码数据发布未核实
- **研究相关性：** 测试覆盖→函数任务与依赖上下文→补全—执行—诊断轨迹→中期训练→持久模型参数更新。
- **入选理由：** 首次报告；正式论文给出从失败执行反馈到参数学习的具体路径，并比较静态样本、成功轨迹及完整轨迹。

### 一句话概述

针对可执行的软件工程训练轨迹难以规模化构建的问题，该方法从有测试覆盖的仓库函数合成补全与调试轨迹，并将失败诊断作为模型中期训练的监督。

<details>
<summary>论文摘要翻译</summary>

大语言模型在交互式真实软件工程场景中展现了显著能力，但感知执行过程的训练数据难以规模化，而且大多用于后训练，智能体中期训练仍研究不足。为此，我们提出 COMP-SYNTH，一条合成反思式代码补全轨迹的新型自动流水线。具体而言，它基于可执行仓库环境识别测试覆盖的目标函数，遮蔽其实现，并提示模型在执行反馈下完成补全；随后通过运行关联测试验证每次生成的补全，同时为失败尝试增加诊断信号，提取有用监督。由此我们构建 COMP-TRAJ 中期训练数据集，使模型接触仓库上下文、执行反馈和迭代代码修改。仓库级软件工程基准上的广泛实验表明，在 COMP-TRAJ 上进行中期训练能够有效增强软件工程能力。我们的代码和数据已在项目仓库公开。

</details>

<details>
<summary>现存问题</summary>

既有轨迹主要用于后训练，构建可执行环境又昂贵。论文的跨方法比较混有不同模型和框架，较可信的是同一 Qwen3-8B 与后续 SFT 配方下的数据消融；测试通过也不能保证语义完全正确。

</details>

<details>
<summary>当前方法为什么可行</summary>

测试覆盖映射到函数，调用关系抽取调用方与被调用方上下文；每轮保存提示、补全和执行反馈。失败诊断可查看参考实现，是特权监督，不是在线自诊断。成功轨迹训练补全，失败轨迹训练诊断，持久改变模型权重。表中合计 453,680 个函数级实例来自 32,230 个仓库环境，并非同数独立仓库。三类 SWE 基准以官方测试通过定义 Pass@1，各设置两次运行取均值；完整轨迹对照成功轨迹提供增量证据，但不是部署后的自动持续进化。本轮可读仓库快照只见 README 占位，抓取标记为两天前，原始 README 访问失败；摘要的代码数据公开声明未核实，未复现。

</details>
