## 1. TRAJDEBUG: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories

**中文译名：** TRAJDEBUG：追踪错误生命周期，定位长程智能体轨迹中的关键失败

**方向：** Task D · 2026-10-12 · 轨迹处理与诊断反馈

**今日研究优先级：** #1

- **日期：** 2026-08-06（arXiv v1）
- **状态：** arXiv 预印本；未核实正式录用
- **研究相关性：** 逐步骤多粒度压缩 → 证据化错误实例 → 关键步骤归因 → 跨任务提示记忆
- **入选理由：** 历史高价值补充：把已修复错误与终局相关错误分开，并检验诊断反馈在留出任务上的用途。

### 一句话概述

针对长轨迹中错误证据分散且局部错误未必导致最终失败的问题，TrajDebug 通过多粒度历史压缩和错误生命周期追踪组织证据并定位关键错误。

<details>
<summary>论文摘要翻译</summary>

基于大语言模型的智能体系统在复杂领域展现出显著能力，但仍面临级联错误和调试困难。关键错误检测旨在定位失败轨迹中对最终失败负责的最早错误步骤，但研究面临两项主要挑战。首先，判断某一步骤所需的证据可能散布在相距很远的指令、观察和历史上下文中，使长轨迹中的单个错误难以识别。其次，一条失败轨迹往往含有多个局部错误，其后续影响不同：有些得到修复，有些无害，只有部分促成最终失败。本文提出错误生命周期追踪框架 TrajDebug，利用多粒度历史压缩和基于证据的错误识别发现长轨迹中的错误，并通过追踪错误的解决状态与终局影响支持关键归因。我们进一步构建 TrajErrBench，包含来自 τ²-Bench 和 SWE-Bench Pro 的 486 条人工标注失败轨迹，覆盖真实的工具使用与编码场景。在多种智能体基准上的实验表明，TrajDebug 相比已有基线取得最佳总体表现；应用研究进一步表明，其诊断能为下游智能体提供可操作的改进反馈。我们将发布代码与数据以支持后续研究。

</details>

<details>
<summary>现存问题</summary>

同一错误会跨步骤重复出现，也可能被后续修复；直接寻找第一处异常，容易把症状、无害偏差或已修复错误当作根因。

</details>

<details>
<summary>已有方法的不足</summary>

整轨迹判读难以连接远距证据；错误分类或约束检查未必判断终局责任。结构化筛选也会漏掉真正关键步骤，最终归因仍依赖 LLM。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入失败轨迹，按 step 建立高、中、低细节视图；提取同时引用错误陈述与被违反证据的触发项，按共同证据对象合并实例，再依据是否修复、是否留下终局影响筛选并归因。输出关键步骤与反馈；历史失败反馈被汇总为系统提示记忆，在每个数据集的 1/3 构建、2/3 留出划分上测试，跨任务保留的是提示内容，未更新权重。论文评测 869 条轨迹，七子集宏平均精确步骤准确率为 34.11%；这不是一次海量批处理，平均约 138 万 token/轨迹的诊断开销也限制扩展。同题重试与留出记忆迁移分开报告，均非本地复现。

</details>

<details>
<summary>未来展望</summary>

作者指出应改善隐蔽错误召回与候选归因。编辑推断：下一步宜测压缩丢证率、拒答校准及单位有效诊断成本，再为记忆写入增加回归门槛；现有研究不足以证明长期自治更新或生产规模收益。

</details>

## 2. Verified Critical Step Optimization for LLM Agents

**中文译名：** 面向大语言模型智能体的已验证关键步骤优化

**方向：** Task D · 2026-10-12 · 诊断后参数自进化

**今日研究优先级：** #2

- **日期：** 2026-07 正式发表；2026-02-03 首发
- **状态：** 已发表于 Findings of ACL 2026；已核实论文集
- **研究相关性：** 失败步骤筛选 → 替代动作续跑验证 → 步骤偏好对 → 持久化 DPO 参数更新
- **入选理由：** 历史高价值补充：诊断候选须通过当前策略的实际续跑验证，才转成训练信号，直接连接诊断、更新与再评估。

### 一句话概述

针对长程智能体训练中整轨迹奖励归因粗糙和步骤评分不可靠的问题，CSO 将失败步骤的替代动作经策略续跑验证后转化为偏好学习数据。

<details>
<summary>论文摘要翻译</summary>

随着大语言模型智能体处理越来越复杂的长程任务，有效的后训练变得至关重要。已有工作面临根本挑战：只依赖结果的奖励无法精确地向中间步骤分配贡献，估计的步骤奖励会引入系统性噪声，而通过蒙特卡洛采样估计步骤奖励的计算成本过高。受推理强化学习中仅少量高熵 token 驱动有效学习这一发现启发，我们提出关键步骤优化 CSO，将偏好学习集中于经过验证的关键步骤，即替代动作能够使任务由失败转为成功的决策点。关键在于，方法从策略自身的失败轨迹而非专家示范出发，直接针对策略模型的弱点。我们利用过程奖励模型筛选候选关键步骤，请专家模型提出高质量替代动作，再由策略模型从这些替代动作继续执行直至任务完成。只有策略能执行到正确结果的替代方案才被验证并用于构建 DPO 训练数据，以保证质量与策略可达性。这在关键决策处提供细粒度、可验证监督，同时避免整轨迹监督粗糙及步骤级噪声。在 GAIA-Text-103 与 XBench-DeepSearch 上，CSO 相比 SFT 基线分别取得 37% 与 26% 的相对改进，并显著超过其他后训练方法，同时仅需监督 16% 的轨迹步骤。这说明选择性的验证式学习对智能体后训练有效。

</details>

<details>
<summary>现存问题</summary>

失败轨迹中仍有正确动作，整段惩罚会混淆贡献；教师给出的好动作，也不保证学生能够完成其后的执行。

</details>

<details>
<summary>已有方法的不足</summary>

整轨迹 DPO 缺少局部归因，稠密 Step-DPO 依赖有噪评分，逐步蒙特卡洛续跑成本高。CSO 仍依赖闭源专家与 PRM，验证结果也受终局判分器影响。

</details>

<details>
<summary>当前方法为什么可行</summary>

失败 ReAct 轨迹 → 专家替代动作及 PRM 候选筛选 → 当前策略从分支续跑至终局 → 同一状态下的正负动作对 → DPO 更新权重，再采集新失败。论文使用 CK-Pro-8B，在 GAIA 文本子集 103 题和 XBench-DeepSearch2505 的 100 题上评测，终局正确性由 LLM 对照标准答案判断；表 1 报告 35.9%→49.5% 与 23→29，摘要是相对变化而非百分点。表 3 的 671 是偏好对数，不是完整轨迹数；验证不是独立物理环境的因果证明。本次仅核验论文与官方仓库页面。

</details>

<details>
<summary>未来展望</summary>

作者提出研究早停、并行续跑及开放 PRM 与策略联合优化。编辑推断：上线前还需验证数据隔离、判分器偏差与旧能力回归；论文没有证明无限轮自进化。

</details>

**原始来源：** [已核验的一手论文](https://aclanthology.org/2026.findings-acl.1974/)

## 3. Parsing the Stream: A Live Trace Model for Long-Horizon Agents and Their Observers

**中文译名：** 解析事件流：面向长程智能体及其观察者的实时轨迹模型

**方向：** Task D · 2026-10-12 · 轨迹数据处理

**今日研究优先级：** #3

- **日期：** 2026-09-01（arXiv v1）
- **状态：** arXiv 预印本；官方代码页面可访问
- **研究相关性：** JSONL 内容块 → 类型化事件账本 → 增量运行状态 → 观察者与智能体视图
- **入选理由：** 历史高价值补充：给出事件关联、用量去重、事实保留与可追溯聚合的具体机制，并公开反例与独立重计核验方式。

### 一句话概述

针对持续增长的执行轨迹难以被观察者和智能体共同使用的问题，该工作将事件流增量折叠为类型化运行状态并编译成各自所需的视图。

<details>
<summary>论文摘要翻译</summary>

长程智能体的轨迹会超出两类使用者的处理能力：监控运行的人类观察者，以及必须把轨迹重新纳入有限上下文的智能体自身。我们提出实时轨迹模型，将只追加的事件账本增量折叠为类型化运行状态，再编译为面向不同使用者的视图，并针对两类使用者用确定性真值进行评估。在观察者侧，以 LLM 阅读器为代理，编译视图相较于受预算限制的单次原始轨迹阅读，在回答监控问题时输入 token 分别约为原来的 1/14 和 1/15，成本约为原来的 1/5—1/7，准确率更高，为 0.85—0.87 对 0.48。由于问题与视图结构共同设计，我们把以结构覆盖问题为前提的 token 与成本减少视为可迁移结果。在智能体侧，面对 120 环节的顺序依赖任务，在逐步状态中维护任务累计统计量的机制能在完整上下文提示失败时成功：干净协议下为 30/30 对 8/30，每组 n=30；因基准与系统共同开发，这些结果被标为描述性。提示级草稿区以更低成本达到相同准确率；两组分解对照将折叠机制的准确率归于确定性聚合，将成本优势归于紧凑表示。相对于更便宜的替代方案，该机制的其余价值在于确定性可审计性，以及用同一状态服务观察者。我们从观察到的失败中提出十一项候选轨迹折叠要求，并用一种对顺序敏感、折叠不再有帮助的任务族划定边界。代码、基准、可重新生成的合成语料与全部工作台轨迹均已发布。

</details>

<details>
<summary>现存问题</summary>

内容块重复携带消息级用量，工具调用与迟到结果需要关联；压缩、逐出与重复读取可能丢失或重复计算事实。

</details>

<details>
<summary>已有方法的不足</summary>

原始尾部日志难回答全程聚合问题，普通摘要缺少确定性核验。更便宜的草稿区或简单累加器在特定任务上同样有效，本文不支持普遍优越性。

</details>

<details>
<summary>当前方法为什么可行</summary>

内容块转为带来源引用及指纹的事件；隔离坏行、保留未知类型、按消息 ID 去重用量，再增量形成 RunState、版本化派生节点和双视图。事实逐出保留指定统计量，非所有原始语义。论文的观察者评测是 12 个真实会话、112 MB、每条件 70 个问题；解析耗时的 104 MB/16,737 事件仅为暖缓存单次测量，排除 LLM 提取与视图生成。非提取路径可确定性重计，LLM 提取路径不是跨缓存确定性；这是一项证据处理能力，不是自动根因归因或持久化自进化。

</details>

<details>
<summary>未来展望</summary>

作者明确提出独立设计的问题、可多次调用工具的阅读器及真人研究。编辑推断：可将状态与来源链接接到诊断器，但需另测诊断覆盖率；顺序敏感任务、单厂商栈和未公开真实语料限制外推。

</details>

**原始来源：** [已核验的一手论文](https://arxiv.org/abs/2609.01466)

## 4. MESH-Harness: Self-Improving Agent Harnesses via Bandit-Guided Compositional Evolution

**中文译名：** MESH-Harness：通过老虎机引导的组合演化改进智能体运行框架

**方向：** Task D · 2026-10-12 · 诊断后自进化

**今日研究优先级：** #4

- **日期：** 2026-10-04（arXiv v1）
- **状态：** arXiv 预印本；未核实正式录用
- **研究相关性：** 验证轨迹分组及代表例 → 模块修改 → 组合选择与整框架评估 → 冻结保留代码
- **入选理由：** 近期首次报道：把诊断驱动的模块生成与昂贵评估预算分配分开，且明确区分入池检查、实际奖励与最终保留。

### 一句话概述

针对智能体运行框架修改后评估成本高的问题，MESH-Harness 依据执行轨迹修订可组合模块，并通过老虎机模型选择需要完整评估的模块组合。

<details>
<summary>论文摘要翻译</summary>

智能体运行框架是为语言模型组织上下文、维护状态并协调工具调用的代码。我们研究在模型权重固定的条件下，如何以有限评估预算改进运行框架。MESH-Harness 将每个框架组织为具有明确角色接口的功能模块，使各模块的不同实现可以替换并重新组合。它使用共享模块表示和全协方差 LinUCB，依据预测表现与探索价值为候选组合评分；混合起点的坐标上升无需枚举组合空间，即可选出待评估的完整配置。随后，验证轨迹引导局部代码编辑，生成的候选进入容量固定、按角色划分的模块池，供后续重组。在候选评估预算一致时，MESH-Harness 在文本任务、检索增强数学推理、代码生成和交互式科学任务上，相比 Meta-Harness 分别高 5.70、7.01、2.00 和 5.00 分。迭代优化使其相对首轮配置增加 5.63—7.79 分。对所报告配置，测试阶段总成本比 Meta-Harness 低 44.2%，包括搜索的总成本低 14.6%。这些结果表明，结合模块设计复用与反馈驱动的组合搜索，可以在控制总体优化成本的同时系统地改进智能体运行框架。

</details>

<details>
<summary>现存问题</summary>

提出代码修改便宜，验证完整 Agent 昂贵；整体重写也难复用不同轮次的有效机制，有限预算需要决定评估哪些组合。

</details>

<details>
<summary>已有方法的不足</summary>

固定候选池不能产生新实现，整体程序搜索难显式重组模块。本文的线性均值模型仍是近似，模块入池检查不等于该修改已带来任务收益。

</details>

<details>
<summary>当前方法为什么可行</summary>

验证轨迹 → 最多八个错误组、每组两个代表例及相关修改历史 → 诊断与局部模块编辑；候选通过接口/执行检查后入池，LinUCB 选择完整组合，任务奖励更新代理模型，最终按验证集选出并冻结代码。历史视图最多 24,000 字符，删去完整记录且保留来源。论文每任务预算为 40 次完整候选评估，冻结后测试三次；权重不变、代码改动保留。须限定摘要分数：文本是数据集宏平均，数学是 500 题 pooled pass@1，LiveCodeBench 是 100 题且每题最多取前八个测试用例，ScienceWorld 是 102 episode 的平均进度而非完成率。

</details>

<details>
<summary>未来展望</summary>

作者未在所查结论中提出独立未来工作清单。编辑推断：应补多次独立搜索、完整代码测试集与跨任务回归，检查代表例截断是否漏掉稀有失败；现有三次测试不能当作三次独立演化。

</details>

**原始来源：** [已核验的一手论文](https://arxiv.org/abs/2610.05300)

## 5. Robust Tool Use via Fission-GRPO: Learning to Recover from Execution Errors

**中文译名：** 通过 Fission-GRPO 实现稳健工具使用：学习从执行错误中恢复

**方向：** Task D · 2026-10-12 · 诊断后参数自进化

**今日研究优先级：** #5

- **日期：** 2026-07 正式发表；2026-01-22 首发
- **状态：** 已发表于 ACL 2026 主会长文；已核实论文集
- **研究相关性：** 错误轨迹筛选 → 诊断上下文 → 当前策略恢复采样 → GRPO 参数更新
- **入选理由：** 历史高价值补充：把错误反馈接入持续训练分布，提供静态/动态反馈消融及等更新预算比较，补充参数层改进路径。

### 一句话概述

针对工具调用出错后智能体反复无效重试的问题，Fission-GRPO 将错误及诊断反馈组成纠错上下文，并用当前策略生成恢复轨迹来训练模型。

<details>
<summary>论文摘要翻译</summary>

大语言模型能够有效调用工具，但在多轮执行中仍然脆弱：工具调用出错后，较小模型往往重复无效调用，而不是理解反馈并恢复。这种失败持续存在，因为当前训练范式没有明确教授如何从执行错误中恢复。尤其是，标准强化学习把丰富的失败经验压缩为稀疏负奖励，而预先收集的纠错数据会与策略不断变化的失败模式失配。为弥合这一差距，我们提出 Fission-GRPO，在强化学习循环内把执行错误转化为当前策略上的纠错监督。核心机制将每条失败轨迹加入由微调错误模拟器产生的诊断反馈，分裂为新的训练实例，再按当前策略重新采样多条恢复轨迹。这使模型从探索时实际犯下的错误中学习，而不是依赖静态、预先收集的错误案例。在 BFCL v4 Multi-Turn 上，Fission-GRPO 使 Qwen3-8B 的错误恢复率绝对增加 5.7 个百分点，总体准确率增加 4.0 个百分点，由 42.75% 达到 46.75%，超过强化学习基线及专门的工具使用智能体。该方法还泛化到 TAU-Bench 与 TAU2-Bench，在多数设置中取得领先结果，增益最高为 +17.4%。

</details>

<details>
<summary>现存问题</summary>

工具返回错误后，模型可能编造参数或重复同一调用；只惩罚失败无法教会下一步如何纠正，全组失败还会削弱相对优势信号。

</details>

<details>
<summary>已有方法的不足</summary>

离线纠错样本会落后于当前策略的错误分布，标准 GRPO 缺少有针对性的恢复训练。诊断模拟器需标准工具调用，不能直接假定部署时具备同等信息。

</details>

<details>
<summary>当前方法为什么可行</summary>

按格式与功能正确性筛选失败 → 确定性格式反馈或 Qwen3-32B 错误模拟器生成诊断 → 最近错误优先缓冲 → 恢复轨迹组 → GRPO 更新并保留模型权重。模拟器训练和推断均读取标准调用；学生只接收受约束反馈。论文在 Qwen3 的 1.7B/4B/8B 上评测，BFCL 总体准确率与“已发生错误条件下的成功率”分母不同；τ 系列为 GLM-5 模拟用户下的 pass@1。静态反馈消融与相同更新步数对照支持训练机制，但不等于真实 API 总成本相同；人工审核仅有 100 条反馈，96% 判为不泄漏，并非零泄漏保证。摘要最大增益对应 Qwen3-4B 在 τ-bench Retail 相对 GRPO 的 17.4 个百分点，非跨任务均值。

</details>
