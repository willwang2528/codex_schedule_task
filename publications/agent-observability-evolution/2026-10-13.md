## 1. VERSE: Verified Self-Evolving Optimizer for Agent Harnesses

**中文译名：** VERSE：面向 Agent 运行框架的经验证自进化优化器

**方向：** Task D · 2026-10-13 · 诊断后自进化

**今日研究优先级：** #1

- **日期：** 2026-10-02
- **状态：** arXiv 预印本 v1；未核实正式录用
- **研究相关性：** 失败轨迹与回放证据 → 诊断、改动验证 → 执行器及优化器运行框架持久更新。
- **入选理由：** 近期首次纳入：把优化器自身的诊断和验证流程纳入进化，并设置互斥的训练、验证、测试任务。

### 一句话概述

VERSE 针对优化器难以验证失败诊断及框架改动的问题，将执行校验、失败回放和步骤干预接入反馈循环，同时迭代执行器与优化器自身的运行框架。

<details>
<summary>论文摘要翻译</summary>

运行框架进化会改进大语言模型 Agent 的提示、工具和工作流，而优化器自身的工具与流程往往保持不变。我们研究：优化器能否通过同时改进失败诊断、修改开发及效果测试方式，更有效地改进另一个 Agent。两项观察指导了设计：在受控研究中，没有基于执行的验证时，优化器自进化未能提升性能；具备验证时，则取得该研究中的最佳结果。在五种执行器上，自进化优化器构建了用于失败分析、验证、训练审计和工作流控制的工具。据此，我们提出 VERSE，一种面向 Agent 运行框架的经验证自进化优化器。它允许优化器在提交前测试草稿修改、回放失败并扰动可疑步骤，同时跨轮跟踪修复与退步。利用这些反馈，优化器同时修改执行器框架及自身的提示、技能、工具、钩子和笔记，双方模型权重保持固定。在训练、验证和测试任务互不重叠的统一协议下，VERSE 改进了所评估的四种框架优化器在 SWE-rebench 留出任务及更新的五语言分布外任务上的表现。验证集选出的最佳框架准确率分别为 42.3% 和 37.7%，最强基线分别为 39.2% 和 29.3%。代码已公开。

</details>

<details>
<summary>现存问题</summary>

轨迹中的解释未必对应真实修复；跨轮修改也可能使旧任务退步，需要保留可执行的诊断证据。

</details>

<details>
<summary>已有方法的不足</summary>

仅阅读日志并生成反思缺少干预验证；固定优化器难以改进自身工作方式。不过总执行预算不完全相等，不能把全部收益归因于自进化。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入失败轨迹和逐轮结果 → 轨迹缩减、修复/退步审计及回放证据 → 框架补丁。草稿执行、失败回放和步骤扰动提供反馈；执行器框架与优化器的提示、技能、工具等跨轮保留，模型权重不变。论文使用 110 个训练任务、50 个验证任务、108 个同分布测试任务及 107 个分布外测试任务，验证集选择后冻结框架。主结果 avg@3 是同一进化产物的三次评估，不是三次独立训练；开启优化器自进化的增益也并非每种配置都成立。已核验论文与仓库说明，未运行代码。

</details>

<details>
<summary>未来展望</summary>

编辑推断：优先补充独立进化随机种子、相同总执行预算和部署环境回放，检验诊断工具的收益能否迁移；现有证据不足以支持所有任务都会持续改善。

</details>

**原始来源：** [arXiv 原始记录｜全文已核验](https://arxiv.org/abs/2610.02616)

## 2. AgentSpy: Making AI Agent Behavior Observable

**中文译名：** AgentSpy：让 AI Agent 的行为可观测

**方向：** Task D · 2026-10-13 · 轨迹数据处理

**今日研究优先级：** #2

- **日期：** 2026-10-05
- **状态：** arXiv 预印本 v1；未核实正式录用
- **研究相关性：** 系统调用及网络事件 → 规范化资源图与确定性告警 → 行为审查；补足 Agent 自报轨迹。
- **入选理由：** 近期首次纳入：观察 Agent 及其子进程的真实环境行为，并评估资源级聚合、任务一致性与攻击规则。

### 一句话概述

AgentSpy 针对 Agent 自报轨迹遗漏子进程行为的问题，在隔离环境中采集系统调用与网络活动，并将其整理为资源图和规则告警供行为审查。

<details>
<summary>论文摘要翻译</summary>

基于大语言模型的 AI Agent 通常以用户权限运行 shell 命令、读写文件并访问网络。然而，其执行行为难以理解：测试断言的是结果，Agent 轨迹只记录其自报信息，可能遗漏子进程执行的行为。我们提出 AgentSpy，从 Agent 外部观察它。AgentSpy 按声明式规范配置隔离环境，记录 Agent 及其启动的所有进程的系统调用和网络流量。在此基础上，它支持两类分析：一致性分析衡量执行应该履行的义务，安全分析检查执行绝不能违反的禁令。我们各实现一种分析。可靠性分析通过规则，将每次运行概括为所使用的环境资源：执行的命令、访问的文件和联系的主机；安全分析对系统调用应用确定性规则。可靠性评估使用 codex 框架、三种近期模型及 77 个任务，每个任务重复运行三次。在 92.2% 的比较中，同一任务的重复运行集合比混入其他任务运行的集合更相似。对于三次运行均通过结果测试的任务，18% 的情况出现无关活动，7% 读取评分文件，17% 未使用开发者指导。安全评估中，通用规则检测到五类攻击中的四类，在 50 次运行中没有误报。

</details>

<details>
<summary>现存问题</summary>

任务通过测试，不代表执行过程符合要求；模型日志也无法完整揭示文件、网络及子进程行为。

</details>

<details>
<summary>已有方法的不足</summary>

结果测试与自报轨迹缺少外部行为证据。资源相似性只能提示差异，不能自动判定语义违规或根因。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入 Agent 进程树的系统调用与网络事件 → 路径、命令、主机解析及无资源信息事件过滤 → 每次运行的星形资源图、访问计数和规则告警。按资源类型比较加权 Jaccard 相似性，供人工审查。星形图聚合会丢失时间顺序，原始日志仍保留。77 个任务来自排除 10 个环境失败后的集合；人工审查实际分母为 88 个任务–模型对、264 份报告，而非 88 个独立任务。安全实验共 50 次运行，实际发生的 18 次攻击检出 14 次；无误报不能解释为无漏报。没有诊断后持久更新实验。

</details>

<details>
<summary>未来展望</summary>

作者讨论了平台、工作负载和规则覆盖限制。编辑推断：可把资源证据关联到 Agent 步骤与 span，并保留顺序供归因；尚无证据证明这种接入能够自动修复 Agent。

</details>

**原始来源：** [arXiv 原始记录｜全文已核验](https://arxiv.org/abs/2610.06001)

## 3. VERA: Scaling Verifiable Environments for Agentic co-Evolution

**中文译名：** VERA：扩展可验证环境以支持 Agent 协同进化

**方向：** Task D · 2026-10-13 · 诊断后自进化

**今日研究优先级：** #3

- **日期：** 2026-10-05
- **状态：** arXiv 预印本 v1；未核实正式录用
- **研究相关性：** 轨迹分阶段重建 → 可复位环境与失败归因 → 模型参数和技能交替更新、验证后保留。
- **入选理由：** 近期首次纳入：连接证据准备、归因与双目标更新；同时明确模型验收允许退步及公开资产尚不完整。

### 一句话概述

VERA 针对长流程 Agent 缺少可复位、可核验反馈的问题，将执行轨迹转成分阶段训练环境，并依据失败归因交替更新模型参数与技能。

<details>
<summary>论文摘要翻译</summary>

有能力的 Agent 需要精确且可验证的环境，例如可以在任意阶段恢复、并根据可观测证据演化的沙箱。然而，多数长流程工作表明这种环境非常稀缺：例如医疗研究 Agent 必须经过数十个相互依赖的步骤，为发现建立依据、分类并撰写报告，但现有环境只对最终结果评分。为应对稳定训练的挑战，我们提出 VERA，规模化构建此类环境并让 Agent 在其中进化。VERA 从初始轨迹构建环境：由 Agent 编写评分细则和可执行检查，评判器验证每个沙箱，只有通过验证者进入训练库。在这些环境中，VERA 交替执行两种更新：使用细则奖励训练模型，或编辑运行框架的技能。我们还建立验证器，依据明确的开发集验收标准筛选模型检查点和框架修改。这种归因使 VERA 的协同进化区别于单轴基线：更新不仅针对原因，也针对结果。借助包含九千多个长流程可验证环境的开源语料，9B 模型及其协同进化 Agent 在两个领域分别超过最强基线 10.3 和 13.0 分。在 27B 规模下，它在 AutoCoWorkBench 和 AutoMedBench 上分别达到 71.6 和 80.7，超过基线，并迁移至未见工作流、保留通用能力。

</details>

<details>
<summary>现存问题</summary>

最终奖励难以指出长流程中哪里出错；模型能力不足与技能说明不足需要不同更新方式。

</details>

<details>
<summary>已有方法的不足</summary>

只更新参数或只编辑技能不能覆盖两类问题。摘要中的保留通用能力不是全配置无退步结论；公开仓库说明初版未包含环境语料和训练产物。

</details>

<details>
<summary>当前方法为什么可行</summary>

轨迹、文档和工作区 → 阶段切分、可恢复状态及可执行评分细则 → 沙箱验证后入训练库；随后按阶段失败归因生成模型/技能报告。固定技能时用 GRPO 更新参数，固定模型时增删改技能，版本持续保留。模型验收允许开发分数相对下降不超过 20%；技能编辑另需配对评估、无端到端退步及安全检查，不能概括为每轮提升。AutoCoWork Lite 含 40 个端到端任务；AutoMed 按有效重复–赛道单元聚合并排除基础设施无效单元。摘要分数是 Overall 综合分，九千多环境不是测试任务数。部分长工具反馈由模型模拟；未做本地复现。

</details>

<details>
<summary>未来展望</summary>

作者提出扩展工作流，并检验环境规模与验证质量。编辑推断：先补齐语料、权重及有效评估单元清单，再做评判器敏感性和长期退步审计；目前不足以支持生产闭环稳定改善。

</details>

**原始来源：** [arXiv 原始记录｜全文已核验](https://arxiv.org/abs/2610.05923)

## 4. Detect Before You Attribute: Cascade Failure Attribution for Multi-Agent Systems

**中文译名：** 先检测再归因：多 Agent 系统的级联失败归因

**方向：** Task D · 2026-10-13 · 轨迹筛选与诊断

**今日研究优先级：** #4

- **日期：** 2026-08-30
- **状态：** arXiv 预印本 v1；未核实正式录用
- **研究相关性：** 调用树节点 → 语义/结构异常评分 → 保留依赖的候选子轨迹 → 下游失败归因。
- **入选理由：** 历史高价值补充：把证据筛选与诊断推理明确分离，并评估筛选预算、根因召回及下游归因。

### 一句话概述

DuoTrace 针对冗长多 Agent 轨迹稀释归因线索的问题，用语义与调用结构联合建模筛出可疑步骤，再交由下游诊断器判断失败来源。

<details>
<summary>论文摘要翻译</summary>

基于大语言模型的 Agent 在通过多步推理解决复杂任务方面展现了潜力，但仍容易发生执行失败，因此准确的失败归因对提高可靠性至关重要。现有基于拓扑和谱的方法利用轨迹结构，却往往忽视细粒度语义；基于大语言模型的归因方法能够捕获语义线索，但在冗长轨迹上面临长上下文性能退化。为解决这些问题，我们提出 DUOTRACE，一种用于大语言模型失败归因的即插即用检测过滤器。它遵循先检测、后归因的范式：先检测异常执行，再向下游归因方法提供聚焦的轨迹证据。为有效开展基于变分自编码器的轨迹异常检测，DUOTRACE 结合语义与结构双视图节点表示、基于 Tree-LSTM 的轨迹编码器，以及前缀链和大语言模型数据增强，以处理异构节点、层次执行结构和失败数据不足。对六种大语言模型归因基线的实验表明，DUOTRACE 将 Agent 级和步骤级归因准确率分别提高 8.7% 和 7.0%。

</details>

<details>
<summary>现存问题</summary>

长轨迹中大量常规步骤消耗诊断上下文；过度删减又可能丢掉真正的致错步骤。

</details>

<details>
<summary>已有方法的不足</summary>

结构方法缺少语义，直接让模型阅读全轨迹易受长上下文影响。异常节点仍可能只是症状，检测分数本身不证明因果。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入带 Agent 身份、操作及文本负载的执行树 → 身份/操作名称嵌入与 Tree-LSTM 结构编码 → VAE 重建及 token 消耗预测误差 → Z 分数筛选并保留结构上下文 → 下游模型输出责任 Agent 与步骤。公式实际嵌入身份和操作名称，不能说完整正文均被语义编码。Who&amp;When 共 184 条失败轨迹，其中手工系统 58 条、自动系统 126 条；六种归因器平均增益对应摘要的 8.7 和 7.0 个百分点。过滤器还比较了保留相同上下文预算的对照。合成正常轨迹与前缀增强用于训练，不等于在线持续诊断或执行修复；未独立复现。

</details>

<details>
<summary>未来展望</summary>

编辑推断：应联合报告筛选预算、根因漏失及最终归因错误，并测试非树协作和多重故障；尚未证明筛选结果能驱动经回归验证的持久 Agent 改进。

</details>

**原始来源：** [arXiv 原始记录｜全文已核验](https://arxiv.org/abs/2608.29646)

## 5. LongRCA Bench: Root-Cause Localization in Long-Horizon Agent Trajectories

**中文译名：** LongRCA Bench：长流程 Agent 轨迹中的根因定位

**方向：** Task D · 2026-10-13 · 诊断基准与证据组织

**今日研究优先级：** #5

- **日期：** 首发 2026-08-15；v4 2026-09-21
- **状态：** arXiv 预印本 v4；未核实正式录用
- **研究相关性：** 完整失败轨迹 → 统一步骤与人工标注 → 原始记录检索、交接指令回溯 → 责任角色/根因步骤。
- **入选理由：** 历史高价值补充：提供长距离错误定位基准，明确保留原始证据，并揭示根因步骤与责任角色并不等价。

### 一句话概述

LongRCA Bench 针对长轨迹中错误源头与后续症状难以区分的问题，构建人工标注的失败语料，并通过原始证据检索与交接指令回溯开展归因。

<details>
<summary>论文摘要翻译</summary>

在长时间 Agent 执行中，早期错误可能持续影响后续动作和检查，而追溯其来源所需的证据分散在历史中。短历史不足以检验在大量后续执行之后恢复错误起点的能力。我们提出 LongRCA Bench：来自五个来源的 1,140 条完整失败轨迹，全部由人工标注责任角色和最早的决定性根因步骤。参考根因到执行结束的间隔中位数为 48 个记录步骤，28.4% 的轨迹在根因之后还有超过 100 步。使用 DeepSeek-V4-Flash 在完整基准上评估时，五种基线中最强者的根因步骤精确准确率为 13.2%。我们提出无需训练的根因轨迹归因方法 RCTA，组织原始候选记录和明确的交接指令供归因。片段摘要与轨迹提纲引导候选检索；可用的交接记录为最终的指令–执行比较提供上游指令上下文。在相同骨干模型和评分协议下，RCTA 达到 24.1% 的根因步骤精确准确率及 51.1% 的责任角色准确率。LongRCA-Mini 提供固定的 200 条轨迹，支持成本较低的比较筛选。即使采用 RCTA，精确恢复的参考根因仍不足四分之一。

</details>

<details>
<summary>现存问题</summary>

早期致错决策与末端报错相距很远；执行根因步骤的角色也未必是应该承担责任的角色。

</details>

<details>
<summary>已有方法的不足</summary>

全日志诊断及只看摘要容易混淆症状与来源。责任角色分类有类别先验，不能替代根因定位；人工标注也存在分歧。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入五类任务的完整失败记录 → 保留内容、角色和顺序并统一步骤编号 → 分段摘要/提纲召回候选 → 取回原文及明确的上游交接指令 → 分别输出责任角色和根因步骤。主测试按 1,140 条轨迹计分，无效输出仍计入分母；Mini 按每来源 40 条组成，不能直接当完整集分布。双人标注样本的步骤完全一致率为 40.3%，经裁决形成参考标签；组件消融的差异未通过 Holm 校正显著性检验。该方法是离线完整轨迹归因，未验证在线预警、干预收益或持久策略更新。
