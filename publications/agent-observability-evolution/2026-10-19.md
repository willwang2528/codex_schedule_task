## 1. Trace-to-Architecture: Capability Bottleneck Diagnosis for Harness Revision

**中文译名：** 从轨迹到架构：面向运行框架修订的能力瓶颈诊断

**方向：** Task D · 2026-10-19 · 诊断后自进化

**今日研究优先级：** #1

- **日期：** 2026-10-12
- **状态：** arXiv v1；正式录用未核实
- **研究相关性：** 按执行特征分组轨迹、跨成功/失败案例核对诊断，再持久化修改技能、输入构造与执行控制。
- **入选理由：** 近期首次报告；把诊断适用条件、改动实际触发和受保护任务回归纳入同一修订闭环，直接连接两项研究重点。

### 一句话概述

该研究针对相似失败需要不同修复的问题，将成功与失败轨迹组织成可追溯的诊断记录，并据此修订和验证 Agent 运行框架。

<details>
<summary>论文摘要翻译</summary>

改进大语言模型 Agent，需要知道它失败时应修改什么；相似失败可能需要不同修复，解决一个问题也可能暴露另一个问题。我们提出 Trace-to-Architecture（T2A），利用执行轨迹确定应修改 Agent 运行框架的哪些部分，以及这些修改何时适用。开发 Agent 使用成功和失败任务的执行证据诊断问题，修订相应框架组件，再检查目标任务是否改善、选定的成功任务是否仍然成功，以及改动是否真正被触发。新的执行证据继续指导后续诊断与修订。在 ALFWorld、ScienceWorld 和 AppWorld 上，T2A 对三个受测任务 Agent 均获得最高综合得分，比各自最强基线高出 6.2—30.3 分。我们还把 T2A 的诊断与验证流程整合进 Meta-Harness，从相同初始框架出发，使所得框架的 ScienceWorld 平均得分提高 21.6 分。

</details>

<details>
<summary>现存问题</summary>

终局失败不能区分知识缺失、技能没有送入模型输入、动作检查缺失或状态过期；修好局部问题也可能破坏原本成功的任务。

</details>

<details>
<summary>已有方法的不足</summary>

只按总分选择框架，难以判断改动是否被执行及为何奏效；仅修改技能文字，也无法解决调用条件和执行控制错误。原文与 GEPA、Meta-Harness 等比较，但部分主表设置、环境版本和开发预算并不完全一致，不能把全部差异归因于诊断。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入为逐任务的模型输入、决策、动作处理、环境反馈及终局分数；脚本按可观测特征分组，保留任务与步骤索引，再抽查代表轨迹并检索相关成功/失败案例，形成“原因假设—适用条件—原始证据”记录，未解决项继续保留。开发 Agent 据此修改组件、驱动代码或采集规则；预先登记目标改善、成功任务保护和改动触发条件，通过后保留新框架，模型权重不变。论文在三类模型与三个环境上评估冻结框架；ScienceWorld 测试含 241 个任务，主表为三次评估，综合分按环境等权汇总。语义验收由开发 Agent 自己判断，程序没有独立裁决语义条件；不是完整因果证明，也没有本地复现。

</details>

<details>
<summary>未来展望</summary>

编辑推断：可把诊断假设、任务/步骤证据和补丁触发记录作为跨轮回归索引，并用独立检查器复核语义验收；原文尚未证明这种替换能提高可靠性。大规模在线轨迹流的吞吐与长期回归控制也缺乏充分证据。

</details>

**原始来源：** [arXiv 原文与版本记录](https://arxiv.org/abs/2610.16725)

## 2. EnactOpt: Diagnosis-Guided Harness Evolution for Embodied Agents

**中文译名：** EnactOpt：诊断引导的具身 Agent 运行框架演化

**方向：** Task D · 2026-10-19 · 轨迹证据与自进化

**今日研究优先级：** #2

- **日期：** 2026-10-10
- **状态：** arXiv v1；正式录用未核实
- **研究相关性：** 对齐相邻决策的反馈、实际模型输入与动作，将诊断摘要用于联合更新技能和上下文构造代码。
- **入选理由：** 历史高价值补充；明确区分“证据没呈现”与“已有证据没用好”，并把证据处理代码和行为指导一起作为演化对象。

### 一句话概述

EnactOpt 针对具身 Agent 难以区分证据呈现不足与证据使用不当的问题，通过相邻决策诊断联合修订可复用技能和上下文构造代码。

<details>
<summary>论文摘要翻译</summary>

基于基础模型的具身 Agent 依赖执行框架来组织观测、指导动作，并把执行反馈纳入后续决策。失败不仅可能源于模型能力有限，也可能源于框架呈现证据和指导证据使用的方式。这些模型外部机制提供了无需更新模型参数的适应目标，但收集任务特定的交互经验可能代价高昂。仅凭任务结果，无法判断相关证据是没有出现在模型输入中，还是已经可用却未被充分利用；这两个方面又相互耦合：有效的动作指导可能需要当前上下文遗漏的证据，而仅暴露证据并不能保证恰当响应。我们提出 EnactOpt，在保持底层模型与运行时不变的情况下，利用有限执行反馈联合演化可复用的文本技能和上下文构造代码。它通过关联动作反馈、实际模型输入和随后动作来诊断相邻决策，由结构化回合摘要通过提示层面的编辑操作指导联合修订，并对候选框架进行兼容性检查和基于验证的保留。在 VLABench、ALFWorld 和具身 Agent 接口 EAI 上，EnactOpt 相比初始框架将任务成功率提高约 10—27 个百分点，并超过所评估的 GEPA、TextGrad 和 Trace2Skill 基线；增益也延伸到未参与框架演化或候选选择的任务条件。结果支持一条互补的具身适应路径：联合改进证据的呈现和使用方式，把有限执行经验转化为可复用的行为改进。

</details>

<details>
<summary>现存问题</summary>

相同的无效动作，可能源于反馈被上下文构造器遗漏，也可能是技能没有指导模型响应反馈；两类修复不能只靠成功/失败标签区分。

</details>

<details>
<summary>已有方法的不足</summary>

只改技能而固定上下文代码，无法补回丢失信息；仅改代码也不保证模型采取正确动作。论文的 TextGrad、Trace2Skill 是作者实现的 skill-only 版本，整体比较不是等计算预算实验。

</details>

<details>
<summary>当前方法为什么可行</summary>

分析单位是相邻决策窗口：前一动作及反馈→当前完整模型输入与动作→当前动作的环境结果。诊断器检查证据呈现与使用，回合汇总器将逐步诊断压成带步骤引用和不确定性的摘要；优化器只读这些摘要，不能依步骤引用回查原始轨迹。随后用增、改、删、移、拆、并等提示约定联合替换技能及上下文代码，经接口检查和验证集评分保留候选，冻结后测试。三环境分别演化，训练/验证各 30 个任务，测试分别为 920/274/282 个实例；原文有诊断、编辑操作和联合修订消融。改动跨任务保留，模型权重固定；兼容性通过不等于行为保持，诊断也不是因果证明。

</details>

<details>
<summary>未来展望</summary>

作者提出跨基准迁移、更复杂任务组合、实体机器人可靠性及等预算独立测试；现有证据仅覆盖基准内适应，未证明新增感知或低层控制能力。编辑推断：可为摘要中的争议判断增加原始步骤回查，并测量压缩造成的诊断损失，效果仍待验证。

</details>

**原始来源：** [arXiv 原文与版本记录](https://arxiv.org/abs/2610.14977)

## 3. AgentLens: Revealing The Lucky Pass Problem in SWE-Agent Evaluation

**中文译名：** AgentLens：揭示软件工程 Agent 评估中的侥幸通过问题

**方向：** Task D · 2026-10-19 · 轨迹数据处理

**今日研究优先级：** #3

- **日期：** 2026-05-13；v4 修订 2026-10-05
- **状态：** arXiv v4；正式录用未核实；代码发布未验证
- **研究相关性：** 工具日志规范化为带意图的状态序列，合并同任务成功轨迹为 PTA，输出过程评分、分歧点及浪费模式。
- **入选理由：** 历史高价值补充；提供可分解的确定性轨迹处理流程，并清楚区分原始语料、可评分子集和成功轨迹分母。

### 一句话概述

AgentLens 针对最终测试通过掩盖低质量执行过程的问题，将工具日志转为意图状态序列并与多条成功轨迹构建的参考图对齐，以定位过程偏离和无效操作。

<details>
<summary>论文摘要翻译</summary>

软件工程 Agent 的评估主要依赖一个二元信号：最终补丁是否通过测试。这种只看结果的视角，把有原则的求解与混乱的试错过程视为等价，我们实证表明这种等价并不成立。我们评估了八个模型后端在 60 个 SWE-bench Verified 任务上的 2,614 条 OpenHands 轨迹，其中 47 个任务具有足够的成功轨迹来构建任务级过程参考，形成包含 1,815 条轨迹的评估子集。该子集中，10.7% 的成功轨迹表现出我们称为“侥幸通过”的行为，包括回退循环、盲目重试、缺乏验证，或探索、实现和验证的时序混乱。我们提出过程级评估框架 AgentLens，并定义 AgentLens-Bench：它为 1,815 条轨迹标注质量分数、浪费信号、分歧点，并提供 47 个任务级前缀树接受器（PTA）参考。AgentLens 合并同一任务的多条成功解法来构建 PTA，并使用上下文敏感的意图标注器，依据轨迹历史而非仅工具身份，将动作归为探索、实现、验证或编排。在该基准上，质量分数把成功轨迹区分为侥幸、稳健和理想三个层级，并将侥幸通过进一步分为五类反复出现的机制。八个模型的侥幸通过比例介于 0.5% 与 23.2%，部分模型按质量分数而非通过率排序时相差达五个位次。我们计划近期发布项目仓库，包括基准产物、SDK 和分析工具。

</details>

<details>
<summary>现存问题</summary>

通过测试并不能说明执行过程值得学习；重复搜索、缺乏验证和低效试错可能一起进入“成功示范”训练池，同一个工具调用的作用也随上下文改变。

</details>

<details>
<summary>已有方法的不足</summary>

单条参考轨迹覆盖不了多种有效策略，单纯文本相似度不能解释步骤级浪费。但 AgentLens 并非所有指标最优：逐条轨迹匹配的 AUROC 为 0.805，高于其 0.766；优势主要在结构化报告和参考聚合。

</details>

<details>
<summary>当前方法为什么可行</summary>

工具调用及响应→含文件、行区间、内容哈希、位置和意图标签的状态序列→同任务成功轨迹合并的 PTA→结构对齐、覆盖、连贯性和时间分布评分→分歧与浪费报告，供诊断和数据筛选。评分使用规则与固定权重，不需 LLM 调用；被评分轨迹不进入自身参考图。原始 2,614 条中，实际评分为 47 个任务的 1,815 条，其中成功 1,136 条，侥幸通过为 122/1,136；意图标签一致性另在 200 个状态、七名标注者上评估。分层中也包含有效另类策略，低分不能直接当作真实故障或因果根因。论文没有执行基于该筛选的训练改进实验。

</details>

<details>
<summary>未来展望</summary>

作者提出过程奖励、课程构建、版本纵向比较以及向 Web/计算机使用迁移。编辑推断：应先验证参考图外的有效策略会否被误罚，再用于训练筛选；下游收益目前证据不足。最新 v4 写明计划发布，机构页的已发布措辞不能替代本次未成功取得的仓库证据。

</details>

**原始来源：** [arXiv 原文与版本记录](https://arxiv.org/abs/2605.12925)

## 4. The Art of Building Verifiers for Computer Use Agents

**中文译名：** 为计算机使用 Agent 构建验证器的实践

**方向：** Task D · 2026-10-19 · 证据处理与回归评估

**今日研究优先级：** #4

- **日期：** 2026-04-05
- **状态：** arXiv v1；微软官方列为 COLM 2026，会议录未独立核实
- **研究相关性：** 按评分标准组织全轨迹截图证据，分离过程与结果标签；另评估反馈驱动的验证器提示修订。
- **入选理由：** 历史高价值补充；把视觉证据筛选、环境阻塞区分和验证器误判控制连接起来，为自进化的验收信号提供研究依据。

### 一句话概述

该研究针对计算机使用 Agent 的成功判定容易遗漏视觉证据的问题，按独立评分标准筛选和核查轨迹截图，并分别生成过程评价、结果判断和故障诊断。

<details>
<summary>论文摘要翻译</summary>

验证计算机使用 Agent（CUA）轨迹是否成功是一项关键挑战：没有可靠验证，评估与训练信号都不可信。本文总结了我们构建用于 Web 任务的先进验证器 Universal Verifier 的经验。其设计围绕四个原则：构建有意义且互不重叠的评分标准以减少噪声；分离互补的过程奖励与结果奖励，识别执行步骤正确却受阻或经意外路径成功的情形；区分可控和不可控失败，并采用避免级联错误重复惩罚的评分策略以细化失败理解；采用分治式上下文管理，关注轨迹中的全部截图，以提高长任务的可靠性。我们在同时具有人类过程与结果标签的新数据集 CUAVerifierBench 上验证这些发现，显示该验证器与人类的一致程度可比人类彼此之间的一致程度。相较 WebVoyager（假阳性率至少 45%）和 WebJudge（至少 22%）等基线，我们报告假阳性率降至接近零；这些增益来自上述设计选择的累积作用。我们还发现，自动研究 Agent 用专家 5% 的时间达到其 70% 的质量，但未发现复现 Universal Verifier 所需的全部策略。我们开源该系统及 CUAVerifierBench。

</details>

<details>
<summary>现存问题</summary>

长截图序列中的关键事实可能被漏看，Agent 自述成功也可能与视觉证据冲突；把登录墙等不可控阻塞与操作错误混为一谈，会污染改进信号。

</details>

<details>
<summary>已有方法的不足</summary>

把全部截图塞入同一上下文会增加查找难度，只看末尾截图会丢失早期证据；只输出成功/失败也难表达合理尝试后的环境阻塞。论文提供更换基线模型和设计消融，但摘要的“接近零”不等于无误判。

</details>

<details>
<summary>当前方法为什么可行</summary>

任务目标及动作—截图序列→互不重叠的 rubric→截图×标准相关矩阵→每项标准的 top-k 证据组→过程分、结果标签及带位置的诊断。全部截图参与相关性筛查，不代表全部在一次最终推理中处理。人工核验集分别为 WebTailBench 的 140 条和 Online-Mind2Web 的 106 条轨迹，区分先盲评与后查看验证器输出的阶段；结果假阳性率分别为 0.01/0.08，分母是人工判失败的样本。大规模重评分以 UV 为参考，不是新的人工真值。另有自动研究闭环：根据一致性反馈修改并保留验证器提示，假阳性率上升则回滚；这不证明被评估 Agent 已完成自进化。

</details>

<details>
<summary>未来展望</summary>

作者结论指出，自动研究仍难独立发现关键结构设计。编辑推断：可将相互独立的人工留出集、环境阻塞标签和误判回归门槛接入演化验收；在反复用于优化的内部数据上提高一致性，尚不足以证明部署期评判可靠性。

</details>

**原始来源：** [arXiv 原文与版本记录](https://arxiv.org/abs/2604.06240)

## 5. Holistic Evaluation and Failure Diagnosis of AI Agents

**中文译名：** AI Agent 的整体评估与失败诊断

**方向：** Task D · 2026-10-19 · 轨迹数据处理与诊断

**今日研究优先级：** #5

- **日期：** 2026-05-14
- **状态：** arXiv v1；正式录用未核实
- **研究相关性：** 在层次化 trace 上进行叶 span 评估、向上聚合与跨后代行为检查，产出位置、指标和理由。
- **入选理由：** 历史高价值补充；给出从遥测结构到诊断输出的明确接口，并公开讨论局部错误上卷与终局影响之间的缺口。

### 一句话概述

该框架针对长轨迹评估难以同时解释错误类型和具体位置的问题，将逐 span 的局部评估与跨执行结构的整体行为检查结合起来生成诊断证据。

<details>
<summary>论文摘要翻译</summary>

AI Agent 执行复杂的多步骤流程，但现有评估仍有不足：结果指标报告成功或失败，却无法解释原因；过程级方法则难以把错误类型连接到冗长、结构化轨迹中的准确位置。我们提出整体 Agent 评估框架，把自上而下的 Agent 级诊断与自下而上的 span 级评估结合，将分析分解为独立的逐 span 评估。该分解可扩展到任意长度的轨迹，并为每个判断生成 span 级理由。在 TRAIL 基准上，该框架在 GAIA 与 SWE-bench 的所有指标上均取得最佳结果，相对最强既有基线，类别 F1 的提升最高为 38%，定位准确率最高达到 3.5 倍，联合定位与分类准确率最高达到 12.5 倍。逐类别分析显示，该框架领先的错误类别多于其他评估器。尤其是，同一个前沿模型在框架内的定位准确率，是直接作为整条轨迹单体评判器时的数倍，说明评估方法而非模型能力是瓶颈。

</details>

<details>
<summary>现存问题</summary>

遥测记录了调用及层次关系，却没有语义正确性标签；局部工具错误与跨步骤的反复调用、计划偏离，要求不同粒度的检查。

</details>

<details>
<summary>已有方法的不足</summary>

整轨迹单次评判容易受上下文限制并丢失 span 定位；仅做叶节点检查又会漏掉跨步骤行为。本文默认“任一子节点失败即向上失败”的规则，可能把已恢复或无结果影响的小错误放大。

</details>

<details>
<summary>当前方法为什么可行</summary>

层次化 Agent/LLM/tool trace→叶 span 的指标、判定及输入输出证据理由→沿树聚合，并以 Agent 级指标检查后代间的计划、工具覆盖和滥用→带位置的诊断输出。实验基于 TRAIL 的 148 条 trace、841 个 span 级错误，底层评判器为 GPT-5.4，另用 LLM 将指标映射到 TRAIL 类别。GAIA/SWE-bench 的联合准确率为 0.616/0.638，分母为预测错误数，要求位置和类别同时匹配；不是全部真实错误的召回率。部分整轨迹基线排除了超窗样本，比较口径需保留。树上错误传播不是干预式因果证明；有限基准也不验证任意长度或生产吞吐，本文未执行后续持久化 Agent 修复。

</details>

<details>
<summary>未来展望</summary>

作者明确提出严重性加权、结果相关过滤、利用理由的聚合，以及更丰富的多粒度标注数据。编辑推断：可把重复出现但已恢复的局部异常与真正导致失败的模式分开排序，再选诊断案例；能否改善后续修复仍需回放验证。

</details>
