## 1. Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses

**中文译名：** 智能体 Harness 工程：可观测性驱动的编程智能体 Harness 自动进化

**方向：** Task D · 2026-10-09 · 可观测证据→自进化

**今日研究优先级：** #1

- **日期：** 2026-04-28 首发；2026-05-18 v4（源站日期）
- **状态：** arXiv 预印本 v4；未核实正式录用
- **研究相关性：** 按任务组织消息与轨迹，形成可下钻诊断证据；更新并保留工具、中间件、技能等模型外组件。
- **入选理由：** 历史高价值补充：把海量轨迹整理、故障分析、组件修改及下一轮验证接成已执行的闭环，最贴合完整研究链。

### 一句话概述

针对编程智能体轨迹难以转化为可执行改进的问题，AHE将轨迹整理成可下钻证据，并用带预测的组件修改与后续任务验证驱动运行框架演化。

<details>
<summary>论文摘要翻译</summary>

（完整译自 v4 正文摘要；结果及解释为作者报告。）
Harness 是智能体性能的核心，负责衔接模型、工具与执行环境，但其工程设计仍主要依靠人工，因为自动化需要面对异构的可编辑组件、淹没有效信号的大量轨迹，以及难以归因的修改效果。我们提出 Agentic Harness Engineering（AHE），通过三个相互配合的可观测性支柱构建闭环：组件可观测性将每个可编辑组件表示为文件，使操作空间明确且可回退；经验可观测性将数百万原始轨迹 token 提炼为演化智能体可以使用的分层、可下钻证据库；决策可观测性为每次修改附上自主声明的预测，再用下一轮任务结果验证。三者使每次修改成为可证伪的契约，使 Harness 能自主演化而不陷入盲目试错。十轮 AHE 迭代将 Terminal-Bench 2 的 pass@1 从 69.7% 提升到 77.0%，超过人工设计的 Codex Harness（71.9%）及 ACE、Training-Free GRPO 自演化基线。冻结后的 Harness 无需再次演化即可迁移：在 SWE-bench-verified 上获得最高的总体成功表现，相比初始版本少用 12% 的 token；在 Terminal-Bench 2 上，三个替代模型家族获得 5.1—10.1 个百分点的增益，表明演化组件编码了通用工程经验，而非仅针对基准调优。消融进一步将增益定位于工具、中间件和长期记忆，而非系统提示词。这些结果表明，可观测性驱动的演化是使编程智能体 Harness 随基础模型持续改进的一条实践路径。

</details>

<details>
<summary>现存问题</summary>

同一任务的成败线索散落于长消息和工具输出中；只看总成功率无法判断应修改哪个组件，也难辨一次修改修复了旧错误还是引入了回归。

</details>

<details>
<summary>已有方法的不足</summary>

提示词、反思文本或单一技能优化覆盖的修改空间有限。AHE 的对照包括 ACE、Training-Free GRPO 与仅修改系统提示词的版本；这些对照支持讨论组件覆盖面，但不能把所有收益归因于某一个组件。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入：每任务多次执行的消息、工具调用及成败结果。处理：按任务归组、逐消息文件化，保留原始与轻清理轨迹；Debugger 阅读这些材料后另行生成任务诊断报告，汇总为总览→报告→原始证据的层级。输出与用途：Evolve Agent 据此提交组件文件修改及修复/回归预测，下一轮执行核对任务变化，版本历史支持保留和回退；基础模型权重不更新。
论文在 89 个 Terminal-Bench 2 任务上每轮各跑 2 次、连续演化 10 轮，属于同一任务集上的优化结果，不是独立测试集收益。冻结迁移至 500 个 SWE-bench Verified 任务时，作者报告总体成功率由 75.2% 到 75.6%，且存在仓库退步；跨任务迁移不能等同普遍保证。回归预测的平均精确率/召回率仅为 11.8%/11.1%，因此预测清单不构成可靠防回归证明。以上为论文实验，未本地复现。

</details>

<details>
<summary>未来展望</summary>

作者指出组件交互、演化运行配置和自修改治理仍有限，回归预判尤其薄弱。编辑推断：可把独立回归集、组件级撤销及修改证据留存设为保留更新的条件；该生产级闭环的可靠性尚未由本文证明。

</details>

## 2. Coherence Collapse: Diagnosing Why Code Agents Fail After Reaching the Right Code

**中文译名：** 连贯性崩塌：诊断编程智能体为何在找到正确代码后仍然失败

**方向：** Task D · 2026-10-09 · 轨迹数据处理→诊断

**今日研究优先级：** #2

- **日期：** 2026-03-25 首发；2026-05-26 v2（源站日期）
- **状态：** arXiv 预印本 v2；旧题名为 TRAJEVAL
- **研究相关性：** 工具步骤→文件/函数集合→阶段指标与失败分型→检查点及共识干预检验。
- **入选理由：** 历史高价值补充：提供跨框架的大规模轨迹处理方法，并把失败模式转为可检验的控制策略；明确区分找到代码与修对代码。

### 一句话概述

针对编程智能体最终成败无法揭示失败过程的问题，TrajEval把执行轨迹对齐到搜索、阅读和编辑阶段，再用失败分型指导检查点与共识干预。

<details>
<summary>论文摘要翻译</summary>

（完整译自 v2 正文摘要；结果及解释为作者报告。）
编程智能体能解决 SWE-bench Verified 中 65%—70% 的问题，但 Pass@1 无法解释其余任务为何失败；我们的研究还表明，缺少轨迹数据时，能力较强模型的失败会被系统性误诊。我们提出无需训练的 TrajEval，将智能体轨迹分解为与参考补丁对齐的搜索、阅读和编辑阶段，并将其应用于覆盖三种架构、七个模型的 16,758 条轨迹。能力较强模型的主要失败并非定位问题：SWE-Agent 和 OpenHands 中 60%—69% 的失败已找到并编辑正确函数，却仍生成错误补丁；这一模式也出现在仅用 bash 的 LiveSWEAgent 的多数模型中。在这些编辑质量问题中，我们识别出的最大主题是“连贯性崩塌”：智能体已到达正确代码，却随后覆盖它或反复无效修改；该现象同时出现在 SWE-bench Verified 与多语言 PolyBench Verified 中。在五个案例里，智能体曾在轨迹中途生成与标准参考逐位一致的补丁，却在后续将其破坏；编辑提交检查点通过 SWE-bench Docker 验证环境恢复了全部五个案例。一个无需参考补丁、由共识驱动的变体，在 GPT-5 上测得方向性的 Pass@1 增益 3.0 个百分点（p=0.08）。

</details>

<details>
<summary>现存问题</summary>

最终补丁错误可能发生在搜索、阅读、编辑目标或编辑质量等不同阶段；把所有失败归为定位不足，会错过已形成正确修改后又自行破坏的过程。

</details>

<details>
<summary>已有方法的不足</summary>

Pass@1 只有轨迹级二元结果；仅检查最终补丁会丢失中间状态。本文的阶段指标仍主要测量定位覆盖，不能把阅读函数视为理解正确，也不能把编辑正确函数视为补丁语义正确。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入：工具动作/观察、生成补丁及参考补丁。处理：将不同框架动作映射为查看、编辑等类别，用 tree-sitter 等提取函数，形成访问文件、阅读函数、修改函数集合及六项精确率/召回率，再按阈值和编辑特征形成失败分型。分析单位为步骤、文件、函数和整条轨迹；不是把全部语料塞入一次模型上下文。
论文语料含 SWE-bench Verified 的 9,500 条和 PolyBench Verified 的 7,258 条轨迹。连贯性崩塌的 39.7% 指 SWE-Agent 上 914 条编辑质量失败中的占比，不能当作所有轨迹的占比。诊断后测试的无参考共识干预，在同一组 500 个 SWE-bench Verified 问题上使 GPT-5 从 330 个成功变为 345 个，同时有 39 个修复、24 个退步；p=0.08，不宜称为统计显著改善。检查点的五例恢复是存在性证据。本文没有证明自动保留策略或持续更新模型的自进化闭环。

</details>

<details>
<summary>未来展望</summary>

作者将跨架构复核失败分类、扩展对反复无效修改的干预列为待研究方向。编辑推断：可将轨迹分型用于选取回归用例，并在独立任务上验证检查点策略；参考补丁依赖及不同正确解的偏差仍须单独处理。

</details>

**原始来源：** [arXiv v2 · 已核验全文](https://arxiv.org/html/2603.24631v2)

## 3. ScienceClaw: Benchmarking Continual Self-Evolution of AI-for-Science Agents Across the Natural and Social Sciences

**中文译名：** ScienceClaw：跨自然科学与社会科学的科研智能体持续自进化基准

**方向：** Task D · 2026-10-09 · 诊断后自进化→回放验证

**今日研究优先级：** #3

- **日期：** 2026-10-06 v1（源站日期）
- **状态：** arXiv 预印本 v1；方法与基准论文
- **研究相关性：** 已验证失败—成功轨迹→关联的 Skill/Operator 更新→源任务重放与独立验证→持久化程序。
- **入选理由：** 近期研究：明确规定修复如何抽象成可复用程序，以及哪些验证通过后才保留，补足从单次修复到持续演化的关键环节。

### 一句话概述

针对科研智能体的临时修复难以沉淀为可复用能力的问题，ScienceClaw从经重执行验证的修复轨迹生成关联技能与算子，并以源任务回放和独立任务验证决定是否保留。

<details>
<summary>论文摘要翻译</summary>

（完整译自 v1 正文摘要。）
大语言模型智能体正在加速科研自动化，但经过验证的执行很少转化为持久的程序级改进，现有评测也没有在同时涵盖自然科学与社会科学的连续任务上考察这一过程。我们将 ScienceClaw 形式化为固定模型参数的程序自进化，将任务求解、科学验证和程序更新统一起来。ScienceClaw-Eval 覆盖 23 个学科，通过连续任务流和独立重置评测，衡量科学正确性、演化收益、能力保留、跨数据集迁移及演化成本。我们的框架通过多轮交互修复可执行工作流，将经重新执行验证的失败—成功轨迹转换为相互关联的 Skill 与 Operator 候选；只有当源任务回放复现修复，且独立科学任务表现改善时，才保留更新。代码已公开，原文给出了官方仓库链接。

</details>

<details>
<summary>现存问题</summary>

能在当前会话修好工作流，不代表修复在重置环境后仍成立，也不代表新技能或工具能用于后续任务；科研任务还需满足类型、数值及领域约束。

</details>

<details>
<summary>已有方法的不足</summary>

单项工具或技能优化缺少关联程序更新的验证；只测当轮任务成功可能混入临时状态收益。本文将源任务修复复现、独立验证、跨数据集测试分别设置，基线包括冻结智能体及经统一适配的 SkillOpt、TTE、AHE、EvoMaster、EvoScientist。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入：带类型、形状、单位等约束的工作流执行、诊断信号及失败—成功修复区间。处理：从重置后可复现的修复中抽取 Skill 控制逻辑与可执行 Operator 子图，记录边界契约和来源，形成关联更新包。输出：源任务重放必须实际使用新版本并复现修复，随后通过独立验证的硬约束、预算与性能门槛，才替换持久化程序；模型参数保持固定。
已执行评测为 23 学科、7 轮连续任务；各学科 64 个 IID 与 64 个 OOD 实例，即每类 1,472 个实例。OOD 是同学科的新数据集，不是全新学科，且不用于产生或选择更新。统一使用 Qwen3.5-27B 求解、GPT-5.4 演化；作者报告 OOD 学科宏平均成功率从初始 77.72% 到第七轮 91.30%。这些是论文报告的程序更新实验，尚未独立复现；不能把跨学科任务覆盖写成已证实跨学科能力迁移。

</details>

<details>
<summary>未来展望</summary>

作者指出需要重复运行和学科级置信区间，自动科学评估也可能遗漏领域错误。编辑推断：除通过/拒绝更新外，应跟踪旧技能失效、错误保留及长期回归；现有七轮结果不足以证明无限期稳定积累。

</details>

## 4. Diagnosing with Insights: Structured Analysis of Agent Failures via Behavioral Abstractions

**中文译名：** 洞察驱动的诊断：通过行为抽象结构化分析智能体失败

**方向：** Task D · 2026-10-09 · 轨迹重建→诊断证据

**今日研究优先级：** #4

- **日期：** 2026-09-02 v1（源站日期）
- **状态：** arXiv 预印本 v1；未核实正式录用
- **研究相关性：** 事件与日志→带步骤语义的推理—动作图→不变量违规候选及证据→决定性错误判断。
- **入选理由：** 把步骤对齐、语义表示、候选证据保留与最终归因明确拆开，并覆盖编程和 Web 智能体，直接服务可观测数据处理研究。

### 一句话概述

针对长轨迹中步骤与依赖难以对齐的问题，AgentScope将运行记录重建为带语义的推理动作图，再通过神经不变量检查与候选证据汇总定位失败步骤和类型。

<details>
<summary>论文摘要翻译</summary>

（完整译自 v1 正文摘要；效果表述为作者报告。）
随着大语言模型智能体日益普及，理解并诊断其失败，对于实现更好的有效性与可信性至关重要。智能体失败往往体现在漫长而复杂的轨迹中，依靠人工大海捞针难以为继；然而，传统软件缺陷诊断技术难以处理大语言模型智能体的失败，完全依靠大语言模型担任裁判又会产生不可靠的诊断。为克服这些挑战，本文提出 AgentScope，一种用于智能体失败模式诊断的新型神经符号方法。其核心原则是依据轨迹，将智能体行为抽象为结构化表示；它还提出神经不变量的概念，用于规定智能体行为属性。AgentScope 在结构化表示之上，利用大语言模型引导的推理检查神经不变量，定位轨迹中的失败步骤及其类型。我们在公开智能体失败数据集 Who&amp;When 和自行构建的更全面数据集 AgentErrata 上展示其有效性，其中 AgentScope 的故障定位和归因准确性显著优于现有方法。研究表明，将结构化抽象与大语言模型引导推理结合，可以实现有效、可靠且可解释的智能体失败诊断。

</details>

<details>
<summary>现存问题</summary>

工具事件、推理文本和日志缺少统一步骤边界，局部异常又可能被后续纠正；诊断器需要区分异常出现、传播与最终决定任务失败的位置。

</details>

<details>
<summary>已有方法的不足</summary>

整条轨迹一次判定容易混合不同步骤的证据；逐步前缀判定又缺少全局依赖。本文比较这两类基线，但不能由总方案优势推断每个表示组件都有独立因果贡献；神经不变量仍由 LLM 检查，并非形式化正确性证明。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入：API 调用、工具交互、系统日志与推理内容。处理：以步骤为节点，保留 ID、角色、操作内容，补充意图/上下文、推理/动作、信号/验证三组语义字段，并连接控制与数据依赖；再按失败类型挑选相关上下文进行不变量检查，保留多个带证据的候选。输出：最终裁判结合完整轨迹选出决定性步骤与类型；前两阶段的证据准备不等同最终归因，也没有后续自动修复与保留更新的实验。
评测包括 303 条注入并人工核验的 AgentErrata 轨迹，以及 Who&amp;When 的 126/58 条轨迹；这是离线语料规模。GPT-5.1、不提供原任务标准解时，AgentErrata 的严格步骤命中率为 31.35%，容许偏差三步才是 54.13%；分母是轨迹数，不是所有步骤。Who&amp;When 上部分设置并不胜过最强基线。运行开销仅抽样 20 条轨迹，约 25—750 秒，不能据此宣称已解决生产级海量处理。

</details>

<details>
<summary>未来展望</summary>

作者提出改用失败起点、不可恢复点或整条传播链等不同归因目标，并讨论合并或并行检查。编辑推断：可先用廉价特征筛选代表轨迹，再调用图诊断；其采样偏差、吞吐收益及对后续修复的价值仍缺少实验。

</details>

**原始来源：** [arXiv v1 · 已核验全文](https://arxiv.org/html/2609.02371v1)

## 5. False Frontiers: Diagnosing and Mitigating Co-Cheating in Self-Evolving Search Agents

**中文译名：** 虚假前沿：诊断并缓解自进化搜索智能体中的协同作弊

**方向：** Task D · 2026-10-09 · 反馈诊断→训练机制修正

**今日研究优先级：** #5

- **日期：** 2026-09-30 首发；2026-10-03 v2（源站日期）
- **状态：** arXiv 预印本 v2；本任务首次报告
- **研究相关性：** 保存来源、伪标签与回答进行事后诊断，再以来源隔离的交叉反馈改变课程生成和持续参数更新。
- **入选理由：** 近期研究：针对自进化内部奖励失真提出可操作修正，并以相同题目回放区分反馈污染与课程变化，补足闭环评估的可信性。

### 一句话概述

针对自进化搜索智能体把共同错误当作学习反馈的问题，本文通过来源证据审计发现错误一致，并用按来源隔离的交叉求解器反馈调整后续训练。

<details>
<summary>论文摘要翻译</summary>

（完整译自 v2 正文摘要；结果及解释为作者报告。）
自进化搜索智能体可以共同优化生成问题的提议者和回答问题的求解者，从而构造自己的训练课程。这个闭环引入了我们称为“协同作弊”的失败模式：提议者和求解者越来越多地对共同错误达成一致，使内部奖励提高，却没有相应的外部正确性增长。依据来源证据开展的事后参考审计表明，该问题随自进化轮次不断加重：即使环内训练信号改善，伪标签正确性仍停滞或下降。最直接的缓解方法是在训练前验证每项提议。因此，我们提出多次采样验证 MSV，分别在提供来源和不提供来源时向自进化所用的同一模型各查询三次，以决定任务是否进入训练并替换不可靠伪标签。MSV 部分减少了错误一致，但仍留下大量协同作弊，而且每个候选都需额外生成六次标签。这些局限促成了主要方法 CrossFit：将提议者的来源文档分为 A、B 两组，A 组生成的问题交由仅在 B 组上训练的辅助求解者评分，反之亦然。交叉拟合的一致性决定提议者奖励，防止同源伪标签经反馈求解者直接再现，同时保持原求解者的更新规则不变。我们使用 Qwen3.5-4B 与 Qwen3.5-9B 重新运行完整自进化闭环，评估两种干预。自进化后，MSV 将错误一致占比从 6.1% 降至 5.7%、从 8.8% 降至 7.2%，CrossFit 则分别降至 3.0% 和 3.7%。以排除同源训练的反馈重放相同提议，进一步将错误一致降至 0.4% 和 0.1%，从而将反馈来源历史的影响与生成课程的变化分离。在七个下游搜索基准上，CrossFit 相比标准耦合自进化的平均表现分别增加 8.8 和 8.4 个百分点，相比 Search-R1 分别增加 8.7 和 7.8 个百分点。

</details>

<details>
<summary>现存问题</summary>

当伪标签训练过求解者，同源后续问题又由它给提议者提供奖励时，错误答案可在闭环中自我强化。文中的“协同作弊”指这种优化结果，不意味着智能体有意合谋。

</details>

<details>
<summary>已有方法的不足</summary>

同一模型多次核验仍可能共享错误，并带来额外生成成本；仅随机划分问题也可能让同一来源文档跨越训练与反馈两侧。内部一致率因此不能替代有来源依据的正确性评估。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入：每个审计训练步保存的来源文档、采用的伪标签及五个求解回答。处理：外部 LLM 依据来源形成参考、标记错误一致与未决样本；审计只用于事后测量，不进入奖励。诊断后修改：CrossFit 按来源 ID 固定分组，辅助求解者只学习另一组来源，再为当前组提供提议者奖励；主求解者仍用全部获准问题按原更新规则训练，参数更新会跨轮保留。
实验在两个 Qwen3.5 模型规模上重跑三轮；129 个审计步是训练步，不是独立运行次数。错误一致占比按被评估的标签—回答对计算，第三轮表值是该轮 43 个步率的均值，另报约 86% 的审计覆盖率。下游固定 1,325 题，报告七个数据集等权宏平均 Cover-EM，而非严格答案完全匹配或全题微平均。另用固定提议库回放及不同来源划分作对照，支持反馈路径解释；外部 LLM 审计仍可能出错。完整 CrossFit 的预留 GPU 时预算还高于原循环，不能称为免费收益。

</details>

<details>
<summary>未来展望</summary>

作者指出共享预训练知识、相关网页来源及自适应提议仍可产生相关错误，来源隔离仅切断指定训练路径。编辑推断：可将来源 ID 扩展为近重复文档族，并联查审计覆盖率、保留任务表现和完整成本；这一扩展尚未得到本文验证。

</details>
