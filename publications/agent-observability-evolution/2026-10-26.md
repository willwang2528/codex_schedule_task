## 1. AgentTriage: Replayable Security Diagnosis Across Heterogeneous Agent Runtimes

**中文译名：** AgentTriage：跨异构智能体运行时的可重放安全诊断

**方向：** Task D · 2026-10-26 · 轨迹数据处理与诊断

**今日研究优先级：** #1

- **日期：** 2026-10-22
- **状态：** arXiv v1 预印本；未核实正式录用
- **研究相关性：** 原生事件规范化 → 调用生命周期关联 → 溯源图切片 → 可审计诊断。
- **入选理由：** 近期首次报道；把跨运行时证据完整性、诊断与缺证弃权纳入统一可检验契约。

### 一句话概述

AgentTriage 针对异构智能体运行时安全事件难以追溯的问题，通过统一事件契约、关联调用生命周期和溯源图切片生成可重放的证据化诊断。

<details>
<summary>论文摘要翻译</summary>

使用工具的智能体写入文件、执行代码或发送数据时，其最终回复无法解释由此产生的安全事件，而异构运行时通过不兼容的接口暴露相关证据。我们提出 AgentTriage，一个用于跨异构运行时可重放安全诊断的可执行契约。该契约接纳引用规范运行时事件的诊断主张，并要求在必需证据缺失时弃权。运行时适配层规范化原生观测，确定性流水线关联调用与结果生命周期、构建有类型的溯源图、选择对策略判定起决定作用的切片，并将主张绑定到已记录证据。给定相同的规范化轨迹、适配层版本和运行前策略判定器，无需语言模型判断即可重算诊断并重新核查主张。在五种运行时中，一个契约捕获全部 159 次适用执行，并审计原生与合成标识符。在 120 个经裁决案例上，AgentTriage 的有证据支撑联合诊断指标为 0.858，必需证据覆盖率为 0.966，无支撑主张率为 0.036；相对最强同模式基线，联合诊断提高 0.175，95% 置信区间为 [0.092, 0.258]。这些结果量化了可重放诊断的精度及需要弃权的观测边界。我们发布开源实现与部分脱敏证据。

</details>

<details>
<summary>现存问题</summary>

工具请求、实际执行结果和拦截结果容易混淆；并发分支、跨智能体交接及异步返回使时间邻近关系不足以证明父子关系。

</details>

<details>
<summary>已有方法的不足</summary>

终态评分缺少执行证据；按时间串联或文本相似性连接事件会混入其他生命周期。本文贡献是执行契约与测量体系，并非新的通用因果诊断算法。

</details>

<details>
<summary>当前方法为什么可行</summary>

单位为事件、调用生命周期和单次执行：原生观测 → 规范事件及参数 → STPG → 决定性终点的祖先切片 → 引用事件的诊断。切片剔除无关并发分支与终点后记账；策略解释与证据整理分开。159 次采集执行与 120 个裁决诊断案例是不同分母。官方仓库仅公开一轮 53 个行为案例和 40 页无标签证据，未公开完整标注与评分代码；未执行自动修复或持久进化闭环。

</details>

<details>
<summary>未来展望</summary>

作者提出可添加独立验证的语义影响分析层，同时保留显式证据图。编者推断：缺证结果可用于指导插桩补全和回归检查；对真实生产规模、未观测副作用及诊断后修复效果，证据仍不足。

</details>

**原始来源：** [已核验一手来源](https://arxiv.org/abs/2610.30738)

## 2. Divide, Optimize, Merge: Scalable Fine-Grained Generative Optimization for LLM Agents

**中文译名：** 拆分、优化、合并：面向大语言模型智能体的可扩展细粒度生成式优化

**方向：** Task D · 2026-10-26 · 轨迹分组与诊断后自进化

**今日研究优先级：** #2

- **日期：** 2025-11（正式发表月份）
- **状态：** Findings of EMNLP 2025 正式发表；已读最终 PDF
- **研究相关性：** 分组消化轨迹与诊断反馈 → 局部提示词/工具优化 → 模块合并与回测。
- **入选理由：** 历史高价值补充；直接处理轨迹集合超出上下文的问题，并用模块合并连接局部诊断与持久更新。

### 一句话概述

FGO 针对大量执行轨迹超出优化器上下文且难以提取细粒度模式的问题，采用任务拆分、局部反馈优化和递归模块合并来更新智能体提示词与工具。

<details>
<summary>论文摘要翻译</summary>

基于大语言模型的优化在改进智能体系统方面展现了显著潜力。然而，随着数据集增大，将整个训练集上的轨迹一次性提供给大语言模型生成式优化器的传统做法变得不可持续，导致上下文窗口溢出和模式识别退化。为解决这些挑战，我们提出细粒度生成式优化 FGO：这一可扩展框架将大型优化任务拆分为可管理的子集，进行有针对性的优化，再通过渐进合并系统地整合优化后的组件。在 ALFWorld、LogisticsQA 和 GAIA 上的评估表明，FGO 相比传统方法提高 1.6%—8.6%，同时将平均提示词 token 消耗减少 56.3%。该框架为不断复杂化的智能体系统扩展大语言模型生成式优化提供了实用方案。进一步分析表明，在所有所测试的训练集规模下，FGO 都获得了最一致的性能提升，展示了其可扩展性和效率。

</details>

<details>
<summary>现存问题</summary>

把跨任务轨迹全部拼进一次优化请求，会截断有用反馈，且优化器难以兼顾不同任务的细节；局部改进又可能在合并时丢失。

</details>

<details>
<summary>已有方法的不足</summary>

一次性、顺序分批和有放回采样优化分别面临上下文限制、局部偏置或覆盖不稳定。分组合并增加回测成本，不能据摘要的平均节省声称它比所有基线都省。

</details>

<details>
<summary>当前方法为什么可行</summary>

任务子集中的轨迹与答案 → 失败点及模式的文本反馈 → 局部提示词/工具 → 按模块文本嵌入聚类、递归合并 → 在组成子集的合并任务集上回测。聚类对象是模块，不是原始轨迹；更新外部模块，模型权重不变。训练/测试任务数分别为 ALFWorld 60/134、LogisticsQA 48/219、GAIA 36/60；GAIA 两部分均取自官方 validation。规模实验最多 60 个 ALFWorld 训练任务，不能外推为百万轨迹吞吐证明；合并回测也不是独立留出回归门禁。

</details>

<details>
<summary>未来展望</summary>

作者计划用大语言模型预测或贝叶斯近似降低合并回测成本。编者推断：可进一步研究按失败模式分组及独立历史回归集；近似评分能否保留真实执行验证的可靠性，尚无证据。

</details>

**原始来源：** [已核验一手来源](https://aclanthology.org/2025.findings-emnlp.1034/)

## 3. WebClipper: Efficient Evolution of Web Agents with Graph-based Trajectory Pruning

**中文译名：** WebClipper：通过图式轨迹剪枝实现网页智能体的高效进化

**方向：** Task D · 2026-10-26 · 轨迹剪枝与参数更新

**今日研究优先级：** #3

- **日期：** 2026-07（正式发表月份）
- **状态：** ACL 2026 主会长文；已读最终 PDF
- **研究相关性：** 行动—信息图 → 冗余步骤识别与轨迹改写 → 持久参数微调。
- **入选理由：** 历史高价值补充；连接单轨迹依赖整理、冗余诊断与训练，并分别评估剪枝和改写组件。

### 一句话概述

WebClipper 针对网页智能体搜索轨迹中的循环与无效分支，将行动和信息组织成依赖图，剪除冗余步骤并改写衔接内容，再以整理后的轨迹训练智能体。

<details>
<summary>论文摘要翻译</summary>

基于网页智能体的深度研究系统在解决复杂信息搜寻任务方面展现出强大潜力，但其搜索效率尚未得到充分研究。我们观察到，许多先进开源网页智能体依赖冗长的工具调用轨迹，其中包含循环推理和对无效分支的探索。为此，我们提出 WebClipper，通过图式剪枝压缩网页智能体轨迹。具体而言，我们将搜索过程建模为状态图，把轨迹优化表述为最小必要有向无环图挖掘问题，生成保留必要推理、消除冗余步骤的剪枝轨迹。使用这些精炼轨迹继续训练，能够使智能体形成更高效的搜索模式，将工具调用轮数减少约 20%，同时提高准确率。此外，我们提出 F-AE 分数，用于衡量模型平衡准确率与效率的整体表现。实验表明，WebClipper 在保持优良表现的同时压缩了工具调用轮数，为网页智能体设计中的效果与效率平衡提供了实用见解。

</details>

<details>
<summary>现存问题</summary>

搜索轨迹反复核验已知信息或探索无贡献分支，增加调用成本；直接删除步骤又可能使后续思考引用已不存在的观测。

</details>

<details>
<summary>已有方法的不足</summary>

提示词要求少调用工具约束不足；直接让模型整段删除冗余轮次会丢失依赖。图依赖仍由模型抽取，不能视为经过环境干预证明的因果关系。

</details>

<details>
<summary>当前方法为什么可行</summary>

观察—思考—行动轨迹 → 行动节点与原子信息节点，语义匹配合并信息 → 最短路与反向依赖闭包剪枝 → 多次图构建一致性筛选 → 上下文感知改写与困惑度选择 → SFT 持久更新参数。效率版仅用剪枝轨迹，混合版加入不同查询的未剪枝轨迹。以 Tongyi-DeepResearch 为底座，在四个基准上评估，并消融图剪枝、改写和训练策略；GAIA 为 103 个文本开发样本，HLE 为 500 个文本样本，准确率使用 o3-mini 裁判。未核实训练轨迹总数，不能声称全量海量处理。

</details>

<details>
<summary>未来展望</summary>

作者提出结合强化学习或在线学习探索基模原有轨迹之外的策略，并扩展到多模态、数据库和 API 工具。编者推断：应补充依赖误判与必要步骤误删审计；目前不足以证明剪枝对任意工具空间安全。

</details>

**原始来源：** [已核验一手来源](https://aclanthology.org/2026.acl-long.988/)

## 4. ArenaFlow: From Trajectory Ranking to Hierarchical Credit Propagation for Open-Ended Agent RL

**中文译名：** ArenaFlow：从轨迹排序到开放式智能体强化学习的分层信用传播

**方向：** Task D · 2026-10-26 · 诊断反馈与持久学习

**今日研究优先级：** #4

- **日期：** 2026-10（正式发表月份）；预印本 2026-09-18
- **状态：** Findings of EMNLP 2026 记录已核实；全文核验使用 arXiv v1，终版 PDF 不可访问
- **研究相关性：** 轨迹比较 → 关键步骤与技能使用归因 → 参数学习及技能库更新、淘汰。
- **入选理由：** 历史高价值补充；将比较反馈拆成步骤和技能两层信号，有组件消融及人工归因审计。

### 一句话概述

ArenaFlow 针对开放式任务中轨迹级奖励掩盖关键步骤与可复用策略的问题，从轨迹比较中提取结构化反馈，并将信用分配到策略更新和技能维护。

<details>
<summary>论文摘要翻译</summary>

强化学习已显著改善可验证领域中的大语言模型智能体，但在开放式智能体任务中仍难以应用，因为解答多样且可靠的标量奖励难以获得。近期成对评估方法用相对偏好代替逐项评分，缓解了奖励区分能力坍缩。然而，它们仍将丰富的比较反馈压缩为单个轨迹级奖励，掩盖决定性中间步骤，也使成功行为无法沉淀为可复用技能。我们提出 ArenaFlow，一个面向开放式智能体强化学习的分层信用传播框架。ArenaFlow 利用锦标赛式相对排序获得轨迹级奖励信号，并为每次比较加入结构化反思评估，揭示关键成功步骤、可复用策略技能以及检索技能使用归因三类监督。在步骤层面，ArenaFlow 根据锦标赛存活深度，将轨迹级优势传播到高置信关键步骤，从而更有针对性地优化局部推理行为。在技能层面，ArenaFlow 根据组级使用归因估计技能效用，通过效用感知的更新、剪枝和检索维护全局技能记忆。得到的高效用技能进一步作为未来探索的策略先验。广泛实验验证了 ArenaFlow 在开放式智能体任务上的有效性。

</details>

<details>
<summary>现存问题</summary>

开放式报告或旅行规划缺少唯一正确答案；单一胜负奖励无法指出哪些中间决策值得强化、哪些检索技能实际被使用。

</details>

<details>
<summary>已有方法的不足</summary>

轨迹级偏好优化将信用分散到各步骤；只检索或积累技能不能证明其有用。作者的关键步骤与技能归因来自裁判判断，尚非反事实因果证据。

</details>

<details>
<summary>当前方法为什么可行</summary>

同一查询的 16 条轨迹 → 锦标赛排序与结构化比较 → 按轮次深度加权的步骤优势、技能使用信用 → 更新 Qwen3-8B 参数与持久技能库；负效用且经过足够评估的技能退出检索池。Open-Travel 有步骤信用、技能信用、记忆及深度权重消融；另在 100 题 DeepResearch Bench 上测迁移。开放任务主指标为去除平局的双裁判比较胜率，Open-DeepResearch 还以有效生成为条件，不能读成任务成功率。人工审计覆盖 200 对比较；一致性不等于因果正确。

</details>

<details>
<summary>未来展望</summary>

正文未给出具体后续实验计划。编者推断：可用冻结外部评分、移除技能的配对重放和跨分布回归检验信用是否可靠；现有消融与人工一致性尚不能保证每条新增技能带来独立增益。

</details>

**原始来源：** [已核验一手来源](https://aclanthology.org/2026.findings-emnlp.2341/)

## 5. Closing the Consistency Gap: Self-Evolving Agents That Learn to Stay on Course

**中文译名：** 缩小一致性差距：学会保持执行稳定的自进化智能体

**方向：** Task D · 2026-10-26 · 步骤诊断与重复执行评估

**今日研究优先级：** #5

- **日期：** 2026-09-08
- **状态：** arXiv v1 预印本；未核实正式录用
- **研究相关性：** 记录提示词重采样 → 步骤稳定性评分 → 持久指导记忆 → 重复执行验证。
- **入选理由：** 历史高价值补充；从成功轨迹也能发现不稳定决策，并把平均成功与多次全部成功分开评估。

### 一句话概述

该研究针对智能体在相同任务上反复执行时决策不稳定的问题，对记录中的决策提示词重采样定位易变步骤，并将针对性指导写入记忆供后续执行使用。

<details>
<summary>论文摘要翻译</summary>

大语言模型驱动的智能体可能平均准确率很高，却在生产中不可靠，这种差异虽已被观察到，但尚未得到充分解决。在 AppWorld 基准上，使用 GPT-4.1 的 ReAct 智能体面对同一任务执行五次时，只有 53% 的任务能五次全部成功，尽管每次运行的平均通过率为 77%。我们将这 24 个百分点的差额称为一致性差距，并认为解决它是可信智能体部署的前提。我们提出一个自进化智能体框架，通过识别轨迹中不稳定、低一致性的步骤，并将其转化为后续运行可调用的情景记忆来缩小差距。核心是一致性分析器，用于定位轨迹在不同执行中可能发生变化的位置及原因；指导生成器将诊断转化为针对性指导，存入记忆，并注入未来相似任务的执行。在 AppWorld 的 ReAct/GPT-4.1 配置中，该框架使五次全部成功的任务比例在同任务评估中提高 16 个百分点，在相似任务泛化评估中提高 13 个百分点。

</details>

<details>
<summary>现存问题</summary>

平均成功率掩盖重复执行波动；一次成功轨迹也可能含有易变化决策，因此只分析失败终态会遗漏可靠性问题。

</details>

<details>
<summary>已有方法的不足</summary>

固定解码方式不足以控制托管端点变化；稳定性评分也不能验证正确性，稳定地犯错仍可能得高分。当前流程把生成指导直接入库，未实现入库前回归门禁。

</details>

<details>
<summary>当前方法为什么可行</summary>

单条记录轨迹 → 对每步原提示词重采样 → API 名称/参数的 Jaccard 一致性评分 → 针对低分步骤生成指导 → 带来源元数据的持久记忆与检索，权重不变。实验每步重采样 30 次；这不是环境反事实重放。AppWorld test_normal 共 168 个任务、每任务五次运行；相似任务实验是 336 个目标任务—来源指南组合，非 336 个独立任务。Pass^5 指五次全成功，区别于至少一次成功的 Pass@5；同场景变体迁移不等于跨领域泛化。

</details>
