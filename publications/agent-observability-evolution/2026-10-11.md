## 1. Evolving Agents in the Dark: Retrospective Harness Optimization via Self-Preference

**中文译名：** 在缺少外部反馈时进化 Agent：基于自偏好的回溯式 Harness 优化

**方向：** Task D · 2026-10-11 · 轨迹筛选与持久化进化

**今日研究优先级：** #1

- **日期：** 2026-06-04 首发；2026-08-29 v3
- **状态：** arXiv v3；作者标注 EMNLP 2026 Findings 接收，论文集未独立核验
- **研究相关性：** 历史轨迹 → 难度与多样性筛选 → 对比诊断 → 指令、技能及工具更新 → 留出评测
- **入选理由：** 历史高价值补充：直接连接轨迹压缩选择与持久化修改，并明确区分无标签优化和有评分器的最终评测。

### 一句话概述

RHO针对缺少标注反馈时难以改进Agent的问题，从历史轨迹筛选多样难例并通过重复执行、自诊断和候选比较来更新持久化Harness。

<details>
<summary>论文摘要翻译</summary>

AI Agent依靠由技能、工具和工作流组成的Harness解决复杂问题；持续改进这一Harness对于适应新任务至关重要。然而，现有优化方法通常需要带真实标签的验证集，而实际部署中很难获得这类数据。为此，我们提出回溯式Harness优化（RHO），一种仅使用历史轨迹优化Agent Harness的自监督方法。具体而言，RHO从历史轨迹中选出兼具多样性和挑战性的核心任务集，并并行重新求解。Agent通过轨迹内自验证和轨迹间自一致性分析这些执行过程，随后生成候选Harness更新，并依据自身的成对偏好选择最有效的候选。我们在软件工程、技术工作和知识工作三个领域评估RHO。值得注意的是，在不使用任何外部评分的优化过程中，单轮优化将SWE-Bench Pro通过率从59%提高到78%。进一步分析表明，RHO能够针对既有失败模式采取改进，使优化后的Harness改变Agent的行为模式，并在长程会话中维持更高的准确性。

</details>

<details>
<summary>现存问题</summary>

部署轨迹很多，但缺少可直接用于优化的真实标签；逐条优化成本高，重复或简单案例还会稀释关键失败信号。

</details>

<details>
<summary>已有方法的不足</summary>

文中比较的经验笔记与记忆方法主要保留文本经验；依赖验证反馈的Harness搜索需要标签。RHO扩大可修改对象，但不同基线的调用量和执行成本并非完全相同，不能据此宣称普遍算力优势。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入为历史任务及执行轨迹；逐条生成难度分和失败描述，嵌入描述后用DPP选择兼顾难度、多样性的10个任务。每题重跑3次，形成自验证、自一致性诊断JSON；生成3个持久化指令／技能／工具候选，以核心集上的成对自偏好筛选，仅在平均偏好大于零时替换。
论文报告：固定GPT-5.5高推理档的Codex式Agent，SWE-Bench Pro从100条历史任务池选核心集，在另100题留出集上由原始评分器评估，59%→78%；Terminal-Bench 2和GAIA-2留出分母分别为59题、100题。选择与诊断处理的是核心集，不能说把整套基准一次性输入优化器。只验证了单轮持久化更新，未证明多轮单调改进；本次未运行代码。

</details>

<details>
<summary>未来展望</summary>

作者明确提出扩展到其他模型、Agent框架和多轮回溯优化；当前要求环境可重置，也未证明跨基准共享同一Harness。编辑推断：接入独立回归集可检验自偏好接受的修改是否牺牲旧能力，现有证据不足以保证这一点。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2606.05922)

## 2. CoEvolve: Training LLM Agents via Agent-Data Mutual Evolution

**中文译名：** CoEvolve：通过 Agent 与数据相互进化训练大语言模型 Agent

**方向：** Task D · 2026-10-11 · 反馈驱动数据与参数进化

**今日研究优先级：** #2

- **日期：** 2026-04-17 首发；2026-07 正式发表
- **状态：** ACL 2026 主会长文；已核验 ACL Anthology 正式论文集
- **研究相关性：** 轨迹薄弱信号 → 结构化探索上下文 → 可执行新任务 → GRPO参数更新
- **入选理由：** 历史高价值补充：用真实执行反馈改变训练分布，并提供固定数据GRPO、随机探索及反馈消融对照。

### 一句话概述

CoEvolve针对固定训练数据无法跟随Agent能力变化的问题，从执行轨迹中的薄弱行为提取反馈并据此探索、验证新任务和更新模型参数。

<details>
<summary>论文摘要翻译</summary>

大语言模型Agent的强化学习通常在静态数据分布上进行，无法适应Agent不断变化的行为，也难以充分覆盖复杂的环境交互。为解决这些问题，我们提出CoEvolve，一种Agent与数据相互进化的框架，使大语言模型Agent能够通过交互驱动的闭环训练持续改进。具体而言，CoEvolve从执行轨迹中提取遗忘、不确定性等反馈信号，识别容易失败的交互模式，并用这些信号指导大语言模型合成任务。合成任务经过环境交互验证后用于更新数据分布，从而使Agent与数据共同适应。在AppWorld和BFCL上，针对Qwen2.5-7B、Qwen3-4B和Qwen3-30B-A3B开展的大量实验表明，相比强基座模型，该方法取得一致且显著的改进，绝对增益分别为19.43、15.58和18.14个百分点。

</details>

<details>
<summary>现存问题</summary>

固定任务集不能持续暴露已学会后又遗忘、结果不稳定或覆盖稀少的交互模式；无目标地生成新任务也未必针对当前弱点。

</details>

<details>
<summary>已有方法的不足</summary>

静态合成数据和常规GRPO缺少行为反馈到任务分布的闭环；随机再探索不能保证命中失败模式。摘要增益以未采用该训练方法的基座为对照，不能全部归因于反馈模块。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入为同一策略的多次rollout及历史任务得分；提取遗忘、边界和低频动作模式，再由LLM形成失败解释与结构化探索上下文。重新交互得到带rollout标识的动作—观察三元组，按任务聚合成任务—解法对，经环境执行／奖励验证后加入训练集，以GRPO持久更新模型参数。
论文表2：Qwen3-4B在AppWorld-TestN的任务完成率为35.71%，固定数据GRPO为28.57%；BFCL-V3 Multi-turn Base为63%与58%。分母分别是任务和完整多轮用例，本文未明确列出相应测试总例数。摘要三项增益来自表1跨五个评测列的平均差，并非合并样本成功率。表8仍有原本正确而更新后失败的用例：占AppWorld全体评测用例9.53%、BFCL用例5%；总体改进不等于无回归。本次未复现训练。

</details>

<details>
<summary>未来展望</summary>

作者指出可扩充反馈类型，并讨论信号受当前策略、尤其早期弱策略限制。编辑推断：部署研究应另外保留时间外测试与旧能力回归集；本文训练闭环不能直接证明持续在线适应不会遗忘。

</details>

**原始来源：** [ACL Anthology 正式论文](https://aclanthology.org/2026.acl-long.1055/)

## 3. TelemetrySuffBench: Is Agent Telemetry Sufficient for Failure-Origin Diagnosis?

**中文译名：** TelemetrySuffBench：Agent 遥测是否足以诊断失败起因？

**方向：** Task D · 2026-10-11 · 遥测证据处理与诊断基准

**今日研究优先级：** #3

- **日期：** 2026-08-08，v1
- **状态：** arXiv预印本／受控诊断基准；未核验正式接收
- **研究相关性：** event/span → 规范化轨迹与字段遮罩 → 证据充分性、故障起点与拒答评测
- **入选理由：** 历史高价值补充：把检测、定位和证据不足时拒答分开评估，直接约束轨迹采样与压缩应保留什么。

### 一句话概述

TelemetrySuffBench针对检测到失败却无法定位起因的证据缺口，将同一执行轨迹转换为受控信息视图并用成对故障与拒答测试检查诊断依据是否充分。

<details>
<summary>论文摘要翻译</summary>

Agent系统越来越多地暴露执行轨迹，但能揭示失败的遥测仍可能不足以确定失败起源。我们提出TelemetrySuffBench，一个将失败检测、故障起点定位和证据不足时的安全拒答分开的受控基准。该基准构造带延迟绑定故障的规范化多组件轨迹，并将其呈现为成对粗粒度视图、七因素遥测遮罩，以及可见信息完全相同但起点不同的歧义样本对。我们用统一协议、显式候选集、无效输出计分、子组分析和冻结盲测集评估五个前沿语言模型。完整遥测下，各模型起点步骤Top-1准确率为33.8%—97.2%。元数据、兼容OpenTelemetry和兼容OpenInference的视图保留99.5%—100%的检测F1，但起点步骤准确率最多0.5%，揭示出稳定的检测—定位差距。因素消融进一步表明，移除决策内容后，所有模型的起点准确率均降为零；移除来源信息也会造成幅度因模型而异的大幅下降。在需要拒答的丰富歧义输入上，证据门控使三个模型无依据地回答唯一起点的比例减少12.5—48.6个百分点，另两个模型仍回答所有案例，显示安全拒答强烈依赖模型。冻结留出集在同一生成器家族内复现了核心模式。这些发现说明，终态可以支持检测，而可靠的因果归因需要明确的决策—来源关联，以及跨模型有效的拒答保障。数据集和基准实现已提供。

</details>

<details>
<summary>现存问题</summary>

终态异常、错误传播位置和真正引入故障的事件可能相距很远；日志看似完整，也可能有多个与观测一致的起点。

</details>

<details>
<summary>已有方法的不足</summary>

只报检测率或在单一固定轨迹表示上测定位，无法判断证据本身是否可辨识起因。论文中的OTel／OpenInference兼容视图是作者的保守字段映射，不能据其结果断言这些标准本身不支持诊断。

</details>

<details>
<summary>当前方法为什么可行</summary>

受控工作流发出span，转换为保留事件ID、步骤、身份、依赖、决策及来源映射的规范化trace；私有注入标签与可见字段分离，再确定性生成粗视图和因素遮罩，输出定位／拒答评测案例。遮掉的内容不再供诊断使用，事件ID、步骤及候选列表仍保留。
主语料312条轨迹含216条故障、96条正常；RQ1每模型为312×6个视图案例，检测分母为全部轨迹，定位分母为216条故障。RQ2在216条确认集上应用11种遮罩，其中定位只计144条故障；这些是重复视图，不是更多独立轨迹。另在218条可评分TraceElephant自然失败轨迹上做内容删减压力测试，每个请求采用固定3000字符中部截断。没有更新Agent本体；本次仅核论文，匿名代码页未返回可读内容。

</details>

<details>
<summary>未来展望</summary>

作者计划在生产轨迹中加入匹配干预，检验决策—对象绑定及来源边对定位的作用。编辑推断：可把该基准用于评估压缩后是否还保留诊断信息；现有主结论受合成故障家族限制，公开自然轨迹只支持内容敏感性对照，不能替代完整因素消融。

</details>

**原始来源：** [arXiv 原文](https://arxiv.org/abs/2608.07899)

## 4. AgentDiagnose: An Open Toolkit for Diagnosing LLM Agent Trajectories

**中文译名：** AgentDiagnose：用于诊断大语言模型 Agent 轨迹的开放工具包

**方向：** Task D · 2026-10-11 · 轨迹处理与训练数据筛选

**今日研究优先级：** #4

- **日期：** 2025-11，正式论文集月份
- **状态：** EMNLP 2025 System Demonstrations；系统演示论文，非主会研究长文
- **研究相关性：** 推理／动作／观察轨迹 → 能力评分与语义导航 → 高质量轨迹子集 → 微调
- **入选理由：** 历史高价值补充：实际对46k训练轨迹评分并筛出6k用于微调，提供从大批轨迹处理到下游训练的直接证据。

### 一句话概述

AgentDiagnose针对大量Agent轨迹难以观察过程能力的问题，将推理与动作转成能力评分、语义浏览视图和导航视图，并用这些信号筛选训练轨迹。

<details>
<summary>论文摘要翻译</summary>

大语言模型Agent产生丰富的多步骤轨迹，其中交织着观察、内部推理和工具动作。然而，大多数评估流程只关注任务最终是否成功，使Agent的决策过程不透明且难以理解。我们提出AgentDiagnose，一个用于诊断Agent轨迹的开源模块化框架。当前版本完整支持Web领域，并采用可扩展的开放平台架构，以兼容大多数Agent轨迹。AgentDiagnose包括：一个量化回溯与探索、任务分解、观察解读、自我验证和目标质量这五项核心Agent能力的评估模块；以及一个通过t-SNE动作嵌入、交互式词云和状态转移时间线展示轨迹语义的可视化模块。在30条人工标注轨迹上，自动指标与人工判断的平均Pearson相关系数为0.57，任务分解维度达到0.78。此外，用AgentDiagnose筛选包含46k样例的NNetNav-Live数据集，仅使用得分最高的6k轨迹微调Llama-3.1-8B，便使WebArena成功率提高约0.98个百分点，而训练数据量仅为原来的13%。因此，AgentDiagnose既是分析Agent的诊断工具，也能用于构建更高质量的训练数据。工具包和演示均已公开。

</details>

<details>
<summary>现存问题</summary>

原始轨迹回放不便于从大批执行中发现反复绕路、未验证结果或低质量目标；最终成功标签也无法充分表示过程质量。

</details>

<details>
<summary>已有方法的不足</summary>

普通查看器偏重逐步回放；整体评分或参考轨迹匹配难以暴露具体过程能力。本文补充可筛选的过程信号，但没有建立严格的因果根因定位。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入单位为含观察、推理、动作的步骤及其轨迹；从推理中解析动词／名词，嵌入并生成t-SNE与词云，将选择映射回原轨迹；把URL状态转移压成导航视图。LLM按五项准则评分，保留高分轨迹供训练。
论文用Gemini 2.5 Pro评估NNetNav-Live的46k训练样本，筛出6k微调Llama-3.1-8B，再比较WebArena任务成功率。这是逐轨迹评分与一次数据筛选—微调验证，不是一次上下文处理46k轨迹，也未证明自动持续自进化。人工一致性仅验证30条轨迹，且回溯／探索维度Pearson r仅0.39；没有大规模吞吐或存储压缩证据。本次未复现。

</details>

<details>
<summary>未来展望</summary>

作者提出用细粒度人工标注训练专门评估器，并指出当前主要面向Web导航。编辑推断：应先检验评分与筛选策略能否迁移到编码、多模态轨迹，再讨论跨域应用；当前证据不足以确认。

</details>

## 5. HERA: Harness-Environment Co-Evolution for Reliable Agentic Abstention

**中文译名：** HERA：面向可靠 Agent 弃权的 Harness 与环境共进化

**方向：** Task D · 2026-10-11 · 诊断后Harness与环境共进化

**今日研究优先级：** #5

- **日期：** 2026-10-05，v1
- **状态：** arXiv预印本；未核验正式接收
- **研究相关性：** 成对执行轨迹 → 失败分组 → Harness修改与环境变异 → 固定验证门及留出测试
- **入选理由：** 近期首报：同时演化Agent和暴露其弱点的任务环境，明确设置旧样例保留及候选接受条件。

### 一句话概述

HERA针对Agent在任务不可行时仍继续行动的问题，通过分析可行与不可行任务的成对执行失败来共同修改Harness和任务环境，并用验证门筛选保留的修改。

<details>
<summary>论文摘要翻译</summary>

大语言模型Agent在复杂工具使用环境中的行动能力不断增强，但往往无法识别任务不可行、没有有效解的情况。近期工作将这一可靠性缺口形式化为Agent弃权问题，而现有方法通常针对固定任务集优化模型或Agent Harness，对未见失败模式的泛化有限。我们提出HERA，一种面向Agent弃权的Harness—环境共进化框架。HERA包括：通过受控环境变异，将可解任务转为应当弃权的情况，自动构造可验证的可行／不可行任务对；以及利用既有任务上的表现失败，驱动Harness适应，并生成针对既往弱点的新执行环境和任务的共进化过程。在留出评测任务上，HERA演化出的Harness将弃权准确率从61.7%提高到83.3%，同时将可行任务完成率从68.3%提高到76.7%，在所比较的方法中这两项均最高。所得最佳Harness可迁移到另外19个大语言模型，无需针对模型单独优化，平均将弃权准确率提高15.3个百分点，并使较小模型以估计低85%的成本达到较强模型的表现。

</details>

<details>
<summary>现存问题</summary>

Agent可能在缺少关键资源、证据或授权时继续尝试；只针对固定任务优化，容易耗尽失败反馈，却未暴露新的不可行模式。

</details>

<details>
<summary>已有方法的不足</summary>

固定弃权提示、仅改Harness或单纯追加任务，不会持续根据当前Agent的弱点改变环境。HERA比较这些基线，但实验仍是生成并审核的工具环境，不能泛化为生产可靠性证明。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入为同一请求在可行／不可行环境中的工具调用、观察、结果和评价；分析器按可能原因分组，供环境设计器与Harness编辑器使用。新任务对须验证可行解、排查替代解，并通过变异恢复检查；不能仅因求解器失败就贴不可行标签。编辑持久化指令、配置与Python控制模块，模型权重固定。
训练池从20增至50对并保留旧任务；每轮产生4个顺序候选，在独立固定15对验证集上要求弃权与成对成功率均不降且至少一项提高，否则保留旧版。最终冻结后测60对hera-bench：摘要两项百分比的分母分别为60个不可行、60个可行任务。另19模型迁移限于同一基准；85%是特定模型配对的API成本估算。单次rollout和小验证集不能保证真实无回归，本次未复现。

</details>

<details>
<summary>未来展望</summary>

作者未在结论中给出独立未来工作清单。编辑推断：需要扩大真实环境及时间外任务、重复采样并审计不可行标签，检验反复复用15对验证集是否过拟合；当前不足以证明开放部署中的长期稳定改进。

</details>
