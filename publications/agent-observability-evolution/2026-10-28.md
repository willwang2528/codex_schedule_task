## 1. From General Agents to RCA Experts: A Self-Evolving Harness for Root Cause Analysis

**中文译名：** 从通用智能体到根因分析专家：用于根因分析的自进化运行框架

**方向：** Task D · 2026-10-28 · 诊断后自进化

**今日研究优先级：** #1

- **日期：** 2026-08-26（初稿）
- **状态：** arXiv v1 预印本；正式录用未核实
- **研究相关性：** 诊断会话切分 → 成败证据对照 → 知识与工具更新 → 双重验证保留；外部运维遥测与 Agent 轨迹分别处理。
- **入选理由：** 历史高价值补充。将证据整理、失败诊断、持久更新和防退化验证连成可检查的闭环，最贴近完整研究链。

### 一句话概述

针对通用智能体难以积累系统专属根因分析经验的问题，OpsHarness 从成败诊断轨迹提炼知识与工具修改，并经双重验证决定是否保留。

<details>
<summary>论文摘要翻译</summary>

使用大语言模型进行自动化根因分析（RCA）日益受到关注。如今，站点可靠性工程师通常采用两种方式：直接使用 Codex 或 Claude Code 等通用智能体诊断，或者从零构建专用 RCA 智能体。随着主流通用智能体能力增强并快速迭代，我们的定量研究发现，前者现在往往胜过后者。但其准确性仍未满足生产需求，差距主要来自通用能力之外的外部适配层，即运行框架。因此，我们主张基于大语言模型的 RCA 应聚焦这一外部框架，复用现代智能体的强大通用能力，而非从头重建智能体。这样的框架应具备自进化能力，从过去的诊断中积累系统专属经验，使其越用越好。我们提出 OpsHarness，将诊断经验转化为可复用专长。其数据平面结合分层运维知识与思路卡片工具库，控制平面协调初始化、诊断、进化和验证。进化时，OpsHarness 对照成功与失败轨迹，将证据转为原子修改提案，仅允许通过旨在防止过拟合和退化的双重验证的更新进入系统。在两个公开基准和一项工业部署的评估中，OpsHarness 达到 59.0% 的首选根因准确率，相对裸通用智能体改善 63.4%，为基线 RCA 智能体的 4.02 倍。

</details>

<details>
<summary>现存问题</summary>

通用 RCA Agent 会重复探索已有运维经验，也可能将单次错误诊断固化为规则；因此需要同时解决经验提取和更新验收。

</details>

<details>
<summary>已有方法的不足</summary>

直接调用通用 Agent 缺少系统专属适配；静态专用流程难以随环境变化积累经验。论文设置不进化与不验证对照，但结论限于所测 RCA 环境。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入分两层：外部日志、指标、调用链用于 RCA；Agent 的时间序列会话事件用于自进化。方法按诊断命令切分会话，过滤框架外片段，结合工程师反馈和真值形成正确/错误轨迹及成本记录；对照步骤与成败案例，生成工作流骨架、操作、规则和工具卡的原子增删改。修改先在沙箱通过来源案例检查，再经与挖掘案例分离的测试床验证，才持久写入外部框架，执行模型参数不变。OpenRCA 与 RCAEval 按时间划分预热和留出部分；摘要的 59.0% 对应公开基准跨子集、跨骨干的平均 A@1，并非工业数据与公开案例合并后的比例。工业遥测点数也不是 Agent 轨迹数。以上为论文报告，未本地复现。

</details>

<details>
<summary>未来展望</summary>

作者讨论了环境变化、陈旧知识和未见故障带来的限制。编辑推断：来源可追溯的修改提案与分离验证库可迁移到其他 Agent，但跨任务域迁移和长期抗退化仍需独立实验。

</details>

**原始来源：** [论文原始来源](https://arxiv.org/abs/2608.25661)

## 2. TRACES: Proactive Safety Auditing for Multi-Turn LLM Agents via Trajectory-State Modeling

**中文译名：** TRACES：通过轨迹状态建模主动审计多轮大语言模型智能体的安全性

**方向：** Task D · 2026-10-28 · 轨迹数据处理

**今日研究优先级：** #2

- **日期：** 2026-05-26（初稿）；2026-09-19（v2）
- **状态：** 作者 arXiv 记录标注 EMNLP 2026 主会；已核查 v2 全文
- **研究相关性：** 步骤表示 → 潜在机制特征 → 前缀风险状态；风险排序进一步生成持久策略训练信号。
- **入选理由：** 历史高价值补充。用轨迹级弱监督组织密集前缀风险证据，并探索从监测信号到策略更新的连接。

### 一句话概述

针对多轮智能体的风险在最终结果出现前已逐步形成的问题，TRACES 将观察模型的步骤表示转为随时间演化的轨迹风险状态以支持提前审计。

<details>
<summary>论文摘要翻译</summary>

大语言模型智能体越来越多地通过多轮工具使用和环境交互开展工作，安全风险往往早在最终结果显现之前就已出现在中间步骤。因此，被动审计并不足够：事后诊断经常错过在风险发展过程中发出警示的机会。我们提出 TRACES，一种基于表示的主动审计器，从观察者大语言模型的隐藏表示中学习轨迹前缀级风险状态。TRACES 从步骤表示中归纳潜在机制特征，并对其时间演化建模，以估计部分轨迹是否正在偏向不安全行为。为绕开逐步骤风险标注的成本和歧义，TRACES 使用轨迹级弱监督训练，同时仍产生密集的前缀级风险估计。在多个智能体安全基准上，TRACES 改善了完整轨迹的安全预测和主动风险区分能力。我们的分析还表明，这些风险状态可能帮助训练更安全的智能体，凸显了主动审计对长程智能体安全的更广泛潜力。

</details>

<details>
<summary>现存问题</summary>

仅看最终输出无法反映中途的风险积累；逐步标注昂贵，且同一动作在不同历史上下文中风险不同。

</details>

<details>
<summary>已有方法的不足</summary>

事后语言模型裁判和逐步独立分类难以同时兼顾提前预警与时间依赖。论文比较审计基线并进行表示、时间建模消融；这不等于已经验证生产级告警成本或因果根因解释。

</details>

<details>
<summary>当前方法为什么可行</summary>

请求、动作和工具观察组成轨迹前缀；冻结观察模型的动作末端隐藏表示被压缩为机制亲和度及变化特征，再由只读历史的 GRU 输出前缀风险。整条轨迹标签监督时间状态，避免逐步人工标签。ATBench、ASSEBench 上评估完整轨迹判断、提前预警和迁移。训练扩展将同一前缀的候选下一步动作按风险配对，用 DPO 更新 Qwen3-4B 的 LoRA 参数；附录明确这是无可执行环境的离线前缀实验，以外部裁判评估下一步动作，不能解释为完整任务安全收益。论文的 causal-prefix 指不使用未来信息，不构成根因因果证明。

</details>

<details>
<summary>未来展望</summary>

作者提出机制定向干预和在可执行多轮环境中开展完整 rollout 强化学习。编辑推断：可进一步保留风险特征对应的原始步骤证据，并测试告警阈值的误报代价；当前证据不足以支持大规模线上吞吐或端到端安全保证。

</details>

**原始来源：** [论文原始来源](https://arxiv.org/abs/2605.27690)

## 3. Harness Updating Is Not Harness Benefit: Disentangling Evolution Capabilities in Self-Evolving LLM Agents

**中文译名：** 运行框架更新不等于从中受益：分解自进化大语言模型智能体的进化能力

**方向：** Task D · 2026-10-28 · 进化反馈评估

**今日研究优先级：** #3

- **日期：** 2026-10（正式出版月）；2026-05-28（初稿）
- **状态：** EMNLP 2026 主会论文；出版记录已核实，方法核查基于 arXiv v1
- **研究相关性：** 执行证据 → 持久技能/提示/记忆更新 → 调用与遵循诊断 → 任务流收益评估。
- **入选理由：** 历史高价值补充，首次报道。将“会写改进”与“会用改进”分开评估，直接约束诊断后自进化的成功判据。

### 一句话概述

针对智能体能修改运行框架却未必能从修改中受益的问题，该研究分别评估更新者与执行者，并用框架调用和遵循轨迹诊断收益瓶颈。

<details>
<summary>论文摘要翻译</summary>

大语言模型智能体越来越多地部署为围绕可编辑外部运行框架构建的系统，包括提示、技能、记忆和工具，这些组件无需改变模型参数就能影响任务执行。框架自进化利用执行证据更新这些组件，使智能体适应任务。然而，模型的基础任务求解能力能否预测其框架自进化能力仍不清楚：哪些模型能产生有用的更新，哪些模型真正能从中受益？我们分析两种能力：框架更新能力，即根据执行证据产生有用且持久更新的能力；框架受益能力，即执行任务时从更新后的框架中获益的能力。分析得到两项发现。第一，框架更新能力随基础能力变化基本平坦：不同能力层级模型产生的更新带来出乎意料地相似的收益，甚至 Qwen3.5-9B 的更新也能带来与 Claude Opus 4.6 相当的收益。第二，框架受益能力与基础能力呈非单调关系：弱模型受益少，中等模型受益最多，强模型受益少于中等模型。我们将弱模型收益低追踪到两类失败：未能激活相关框架产物，或激活后未能忠实遵循。上述发现提示，应把能力预算优先用于任务执行智能体，并在训练中针对框架调用与长程指令遵循。源代码已在作者的 A-EVO-Lab/a-evolve 仓库 harness-evolution 分支公开。

</details>

<details>
<summary>现存问题</summary>

更新产物的存在或质量不能直接代表执行收益；执行者可能没有检索/加载相关技能，也可能加载后偏离步骤。

</details>

<details>
<summary>已有方法的不足</summary>

将自进化视为单一能力，会把更新者水平与执行者使用能力混在一起。本文通过锚定模型组合拆分两者，但不是所有更新者与执行者的完整笛卡尔积，所得指标依赖锚点选择。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入为固定求解框架下的任务轨迹、结果和评分；更新者据此持久编辑外部技能，部分环境还允许提示与记忆更新，执行模型权重保持不变。SWE-bench Verified、MCP 与 SkillsBench 的任务流用于评估。实现采用 in-situ 顺序评分：任务先使用已有框架执行计分，再将其证据用于更新，不能冒称最终冻结框架的独立留出测试。诊断分别统计技能加载率、已加载轨迹中的忠实遵循率与成功率；后两者的分母不是全部轨迹。遵循性含模型裁判，加载与成功的关系也不是干预性因果证明。论文的层级规律以所测模型和基准为限。

</details>

<details>
<summary>未来展望</summary>

作者建议加强框架调用和长程遵循训练。编辑推断：增加冻结产物后的任务隔离回放，以及强制加载/不加载的配对干预，可更直接检验知识是否被实际使用；现有实验尚不能回答这些因果与泛化问题。

</details>

**原始来源：** [论文原始来源](https://aclanthology.org/2026.emnlp-main.2326/)

## 4. TraceProbe: An Execution-Based Benchmark for Diagnosing Safety Failures in LLM Agents

**中文译名：** TraceProbe：基于执行的大语言模型智能体安全故障诊断基准

**方向：** Task D · 2026-10-28 · 证据处理与回放

**今日研究优先级：** #4

- **日期：** 2026-10（官方仅提供出版月）
- **状态：** EMNLP 2026 主会基准论文；官方最终 PDF 已核查
- **研究相关性：** 工具执行事件与状态差异 → 规范化轨迹和结构化违规证据 → 逐步重放定位。
- **入选理由：** 首次报道。把终点之外的中间违规变成可回放证据，为后续修复验证提供基础；与已报道的同名编码轨迹工作不是同一论文。

### 一句话概述

针对终点安全评估难以揭示智能体执行中风险来源与传播路径的问题，TraceProbe 在沙箱中记录规范化执行证据，并重放工具动作以定位违规步骤。

<details>
<summary>论文摘要翻译</summary>

大语言模型智能体越来越多地通过文件、工具、记忆、检索内容和其他智能体执行动作，这些交互可能在执行过程中触发安全故障。现有基准主要关注终点结果评估，或用模型辅助审查预先构造的轨迹，对风险从何处进入、如何传播提供的证据有限。为解决这一问题，我们提出 TraceProbe，一个基于执行的智能体安全诊断基准。TraceProbe 将智能体置于可执行沙箱场景中，根据规范化轨迹和结构化证据对终点违规与潜在规则违规评分，并重放已记录的工具动作以进行步骤级风险定位。基准包含 155 个场景，覆盖非对抗故障、内部权限受损和外部攻击三类风险来源。在 12 个当代大语言模型上，平均攻击成功率为 0.347，表明仍有显著残余风险，尤其是在内部权限受损时。分析还表明，终点安全的运行可能包含不安全的中间动作，智能体实际执行路径也可能偏离测试场景预设的危险路径。TraceProbe 及其发现支持更可操作的智能体安全评估：除攻击成功率或最终结果外，评估者还可询问哪里出了问题、问题发生在哪一步，以及可以在哪里干预。

</details>

<details>
<summary>现存问题</summary>

最终回复或最终状态看似安全，仍可能掩盖已发生的数据访问、泄漏或其他中间违规；预设攻击路径也不一定等于实际执行路径。

</details>

<details>
<summary>已有方法的不足</summary>

终点评分和静态轨迹裁判缺少与真实工具执行相连的证据。本文提供执行与重放对照，但人工构造的风险分布不能代表线上事件发生率，也未实现持久自进化闭环。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入为工具调用、参数、返回、最终状态和安全事件；规范化后关联结构化违规证据，在新沙箱按原样重放已记录动作，定位首次违规及受监控状态变化。主评估为 155 场景、12 模型、每场景 3 次运行；ASR 只针对带攻击标签的子集，不能用全部场景作分母。另一个组合场景回放实验共 360 次，其中 298 次精确一致、62 次仅安全语义一致，不能说全部逐位复现。重放不重新调用模型，也不删除动作构造反事实，故其定位证据不等于根因因果证明；提示提醒对照亦不是持久策略更新。

</details>

<details>
<summary>未来展望</summary>

作者指出，原生网页和桌面环境还需执行适配器、访问来源记录和状态差异检查。编辑推断：可将确认的违规轨迹封装成修复后的回归用例，但自动选择干预与持续改进的有效性仍无充分证据。

</details>

**原始来源：** [论文原始来源](https://aclanthology.org/2026.emnlp-main.1233/)

## 5. SkillMentor: LLM Agent Self-Evolution via Learning Blind-Spot Diagnosis

**中文译名：** SkillMentor：通过学习盲点诊断实现大语言模型智能体自进化

**方向：** Task D · 2026-10-28 · 诊断后自进化

**今日研究优先级：** #5

- **日期：** 2026-07-29（初稿）
- **状态：** arXiv v1 预印本；正式录用未核实
- **研究相关性：** 探索轨迹 → 能力差距诊断任务 → 失败条件化技能增改合并 → 重试筛选与持久技能库。
- **入选理由：** 历史高价值补充。把“发现值得修复的盲点”本身作为可训练策略，并明确区分 Mentor 参数更新与冻结执行者的技能积累。

### 一句话概述

针对智能体自进化通常默认失败已被发现的问题，SkillMentor 训练导师策略主动生成诊断任务，再把暴露的执行盲点转化为经过重试筛选的可复用技能。

<details>
<summary>论文摘要翻译</summary>

智能体自进化主要关注学习如何行动，却忽视了一项同样重要的能力：学习发现智能体不知道什么。现有方法通常假定失败发现过程已经给定，重点是识别失败后如何修复。我们提出，盲点诊断本身能否被学习？因此，我们将诊断作为独立于执行的智能体能力研究，并排除两种其他进步来源：执行者适应和人工监督。在这些约束下，性能不能通过执行者更新或带标注的例子改善，从而使所有改善都必须源于学得的诊断能力。我们提出 SkillMentor，通过强化学习训练 Mentor 策略，使其生成诊断任务、识别反复出现的失败模式，并整理为可复用的纠正技能。在 AppWorld 和 BFCLv3 上，SkillMentor 使执行者性能平均改善 44.2%。这些结果表明，盲点诊断是可学习的能力，可在不更新执行者权重、也不依赖人工整理数据的情况下实现自进化。

</details>

<details>
<summary>现存问题</summary>

反思器即使会总结失败，也可能持续挖掘已掌握或无法解决的任务；诊断样本是否真正暴露能力缺口影响后续技能价值。

</details>

<details>
<summary>已有方法的不足</summary>

既有经验整理与反思方法常接受现成任务或失败，再提取规则。本文与多种经验基线及未训练 Mentor 比较；不使用人工标注不等于不依赖强参考模型和评分信号。

</details>

<details>
<summary>当前方法为什么可行</summary>

探索轨迹及多样性缓冲区用于生成诊断任务；参考模型与冻结执行者的得分差筛选盲点。Mentor 读取失败轨迹、任务和已检索技能，提出 ADD/UPDATE/MERGE；格式合格且使同一执行者重试收益达到门槛的候选被保留，低效技能可删除。发现与整理奖励共同训练 Mentor，Markdown 技能库持久变化，执行者权重不变。AppWorld、BFCLv3 的基线、消融与跨执行者技能迁移支持这一机制；摘要的 44.2% 是相对 No Skill 的平均相对改善，不是增加 44.2 个百分点。候选验收使用来源失败任务，不能当作全局独立回归门。

</details>

<details>
<summary>未来展望</summary>

作者强调将诊断作为可学习策略继续研究。编辑推断：下一步应将来源任务修复与隔离任务泛化分别验收，并审计参考模型偏差及旧技能退化；现有证据不足以保证持续开放环境中的无退化进化。

</details>
