## 1. MASIF: Implicit Failures for Process Observability in Multi-Agent Systems

**中文译名：** MASIF：用隐式失败实现多智能体系统的过程可观测性

**方向：** Task D · 2026-10-24 · 过程观测与训练反馈

**今日研究优先级：** #1

- **日期：** 2026-10-19（arXiv 首发）
- **状态：** arXiv v1 预印本；未核实正式录用
- **研究相关性：** 逐步标记局部错误及其吸收方式，聚合为轨迹风险，并用于反事实重放和策略参数更新。
- **入选理由：** 近期首次收录；把成功轨迹中的错误纳入观测，并用重放对照与训练实验连接诊断和改进。

### 一句话概述

针对最终成败掩盖多智能体局部执行错误的问题，MASIF 标记错误及其吸收方式，并将这些过程信号用于轨迹选择、修复重放和策略训练。

<details>
<summary>论文摘要翻译</summary>

多智能体系统即使出现局部执行错误，也可能完成任务：这些错误可能被修正、绕过，或被继续传递而不单独决定任务结果。我们将其称为隐式失败（IF），并研究其作为超越最终任务结果的过程可观测信号。在九种多智能体系统—基准配置的 1,828 条轨迹中，54.3% 的成功轨迹和 75.2% 的失败轨迹含有 IF。我们建立错误类型和后续吸收机制的分类体系，并通过人工及跨模型标注审计提供支持。反事实重放进一步探究修复 IF 如何改变最终结果。为考察其实用价值，我们将基于 IF 的 best-of-N 轨迹选择与现有过程奖励模型比较，并提出 IF-GRPO：利用 IF 成本细化 GRPO 对成功轨迹的偏好。实验表明，IF-GRPO 在准确率和过程指标上取得部分收益，同时揭示任务表现、IF 数量与成本、以及按 token 归一化的 IF 密度之间的权衡。总体而言，IF 为理解多智能体系统如何得到结果提供补充的过程观测，包括错误恢复、传播及仅凭最终成败无法揭示的过程差异。

</details>

<details>
<summary>现存问题</summary>

成功并不意味着过程无误；局部错误被修复、绕过还是继续传播，会被最终成败标签压缩掉。

</details>

<details>
<summary>已有方法的不足</summary>

只定位导致最终失败的关键步骤会漏掉成功轨迹里的问题；纯结果奖励也难区分成功轨迹的过程质量。IF 标注本身仍有漏检和边界争议。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入任务与逐步轨迹，经 LLM 标注错误步骤、Agent、类型和吸收方式，形成 IF 记录及轨迹风险；再用于候选选择、局部替换重放和 GRPO 更新。训练只在成败混合组内调整成功轨迹的优势，持久改变策略参数。原始语料含 258 条成功、1,570 条失败轨迹，非单次处理规模证明；人工审计为 45 条。重放另取七种配置各 100 条轨迹，并含重生成数据；不能等同原语料。论文训练比较中六种配置准确率提高，三种每任务 IF 成本下降，存在反向变化，不能宣称全面改进。

</details>

<details>
<summary>未来展望</summary>

编辑推断：值得检验 IF 标注误差和长度归一化是否诱发奖励偏差，并加入冻结策略的跨任务回归集。现有证据不足以支持生产环境持续改进。

</details>

**原始来源：** [arXiv 原始论文](https://arxiv.org/abs/2610.25852)

## 2. Beyond Fault Localization: A Trajectory-Level Study of LLM Agents for Microservice Root Cause Analysis

**中文译名：** 超越故障定位：面向微服务根因分析的 LLM 智能体轨迹级研究

**方向：** Task D · 2026-10-24 · 轨迹数据处理

**今日研究优先级：** #2

- **日期：** 2026-08-21 首发；v2：2026-10-09（arXiv 日历日期）
- **状态：** arXiv v2 预印本；未核实正式录用
- **研究相关性：** 处理 RCA Agent 的推理—动作—结果轨迹，提取证据导航、SQL 意图和失败模式，再设计固定干预。
- **入选理由：** 历史高价值补充；提供批量轨迹分析到诊断规则验证的完整实例，明确区分 Agent 轨迹与被查询的微服务遥测。

### 一句话概述

针对最终定位正确仍可能缺乏证据支撑的问题，该研究将 RCA 智能体轨迹对齐故障传播路径，提取证据使用模式并据此构建诊断干预。

<details>
<summary>论文摘要翻译</summary>

自动化微服务根因分析通常通过最终答案是否定位故障源来评价，但值班站点可靠性工程师还需要故障背后的证据与推理，因此这种评价并不充分。诊断过程难以评估，因为智能体轨迹交织着自由形式的自然语言推理、异构工具调用及遥测结果。为评估 RCA 智能体如何以证据支撑诊断，我们提出轨迹分析方法，刻画证据导航与利用、面向 SRE 的诊断意图及反复出现的失败模式。核心认识是：故障传播路径可作为评估调查位置和证据使用方式的因果参照。我们在 RCABench 上分析十种框架—骨干配置产生的 5,000 条轨迹，覆盖两种骨干模型及九种框架。正确定位可能掩盖因果重建不足；成功调查利用已检索证据引导后续查询，覆盖更广的诊断意图并深入调查；失败调查则偏向无关服务或重复浅层查询，反复出现证据遗漏、误读及无依据推理。为检验这些模式能否指导改进，我们构建针对上述三类失败的轻量防御原型。在两个留出基准、两种骨干模型及六种诊断框架中，这些失败模式再次出现；原型减少其出现频率，并在所有测试配置上将 Acc@1 提高 3.5—35.1 个百分点，提示这些模式具有可迁移性与可操作性。研究支持从过程层面看待自动化 RCA：轨迹揭示诊断是否正确、是否有据可依以及如何改进。

</details>

<details>
<summary>现存问题</summary>

RCA 最终服务名正确，仍可能遗漏传播边、误读遥测或未验证关键假设；结果分数不足以指出具体改动目标。

</details>

<details>
<summary>已有方法的不足</summary>

仅比较定位准确率或直接阅读原始混合日志，难以区分未查询、误解已有证据与无依据推理。传播路径参照依赖领域标注，不能直接移用于任意 Agent。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入是 Agent 每轮 thought/action/result，外部微服务日志、指标和 trace 是其查询对象；归一化后对齐人工核验的传播图，标记导航与证据利用，分类 SQL 意图并编码失败。5,000 是总收集轨迹数；细粒度行为分析限于四类通用框架，意图单位为 92,501 个 SQL 动作，不能泛化为全量统一分析。由此人工设计 DiagGuard 的 Verifier/Grounder，固化为提示及工具规则；十四种留出配置验证，另对 1,368 条 RCA100 运行编码。属于诊断驱动的固定改进，未证明自动持续自进化。

</details>

<details>
<summary>未来展望</summary>

编辑推断：可借鉴其证据使用标签来分析其他工具 Agent，但需重新建立任务参照；作者指出系统覆盖、人工标注和部分基线组件不可用等限制。跨 GUI/Web 的有效性证据不足。

</details>

**原始来源：** [arXiv 原始论文](https://arxiv.org/abs/2608.21310)

## 3. Self-Evolving Coding Agents via Harness-Policy Optimization

**中文译名：** 通过运行框架与策略联合优化实现编码智能体自进化

**方向：** Task D · 2026-10-24 · 诊断后自进化

**今日研究优先级：** #3

- **日期：** 2026-10-16（arXiv 首发）
- **状态：** arXiv v1 预印本；官方代码库已核验；未核实正式录用
- **研究相关性：** 失败轨迹驱动提示与运行代码修改，随后训练策略权重，再用训练失败刷新下一轮任务集。
- **入选理由：** 历史高价值补充；更新对象同时包含 harness 和模型参数，具有交替优化、组件交叉组合与外部分布评测。

### 一句话概述

针对运行框架与策略各自优化后相互失配的问题，Self-HPO 交替利用失败轨迹修订框架和训练策略，并以新失败刷新下一轮优化任务。

<details>
<summary>论文摘要翻译</summary>

LLM 智能体在编码任务上展现潜力，其表现由策略模型及协调环境交互的运行框架共同决定。两者相互促进，只进化其中一部分并不理想：为某个检查点调优的框架可能无法针对更新后策略的失败模式，而策略学习又受固定框架所诱发轨迹的限制。为此，我们提出 Self-HPO，一种交替优化框架和策略的递归自改进方法，由持续变化的策略自身提出框架修改。每轮中，当前策略先分析自身失败并提出框架候选（H 步）；随后在选定框架下通过强化学习更新策略（P 步），训练发现的困难任务组成下一轮框架搜索集，使优化持续针对变化的失败模式。在三个编码基准上，Self-HPO 持续优于仅优化框架或策略的基线，使 Qwen3.5-35B-A3B 的平均解决率从 57.8% 提升至 64.8%，并将收益推广到分布外设置。进一步分析表明，两个优化组件分别与原始对应组件组合时仍保留收益，联合收益超过各自收益之和。相较基础智能体，Self-HPO 还改善 pass@1 可靠性并拓展 pass@k 能力边界。使用更强的外部模型（如 Opus 4.8）提出框架候选，可进一步提升同一框架的表现。

</details>

<details>
<summary>现存问题</summary>

策略变化会产生新失败，静态框架与固定搜索任务集可能失去针对性；框架也限制策略能采集到的训练轨迹。

</details>

<details>
<summary>已有方法的不足</summary>

仅训练权重或只搜索框架无法主动维持两者匹配；论文比较这两类基线，并对固定搜索集、SFT/RFT 与提案模型做消融。

</details>

<details>
<summary>当前方法为什么可行</summary>

失败执行轨迹→候选提示/可执行控制代码→同一搜索集评分并保留最佳框架；随后冻结框架，以可执行验证器提供二元奖励，通过 GRPO 与平衡采样更新权重。训练中从未解出的任务进入下轮搜索；代码和权重均持久保留。实验训练集为 2,484 题，两轮交替；测试为 SWE-Verified 500、Multilingual 300、Pro V2 642 题，主表是三次运行平均，不是三次取最好。交叉组合分析支持组件贡献，但已稳定解决题组仍有退化。

</details>

<details>
<summary>未来展望</summary>

编辑推断：应增加历史成功题的保留门槛及更长轮次的独立回归评测；目前两轮结果不能证明无限递归改进或普遍无退化。未做本地训练复现。

</details>

**原始来源：** [arXiv 原始论文](https://arxiv.org/abs/2610.22791)

## 4. No More Stale Feedback: Co-Evolving Critics for Open-World Agent Learning

**中文译名：** 告别过时反馈：面向开放世界智能体学习的协同进化批评模型

**方向：** Task D · 2026-10-24 · 诊断反馈与参数进化

**今日研究优先级：** #4

- **日期：** 2026-07（ACL 正式发表，月精度）；预印本首发 2026-01-11
- **状态：** ACL 2026 主会长文；官方论文集及最终 PDF 已核验
- **研究相关性：** 从当前轨迹生成诊断，按修订收益同步训练 critic 与执行策略，持久更新两套参数。
- **入选理由：** 历史高价值补充；正式发表，直接研究反馈随策略变化而失效的问题，并包含冻结 critic 和等采样预算对照。

### 一句话概述

针对策略学习过程中诊断反馈逐渐过时的问题，ECHO 通过诊断后轨迹修订和收益塑形，同步更新批评模型与执行策略。

<details>
<summary>论文摘要翻译</summary>

批评引导的强化学习通过自然语言反馈补充稀疏的结果奖励，已成为训练 LLM 智能体的一种有力范式。然而，现有方法通常依赖静态或离线批评模型，无法随策略进化而适应。在同策略强化学习中，智能体错误模式随时间变化，使固定批评模型逐渐过时，反馈效用不断下降。为解决这一问题，我们提出 ECHO（面向事后指导优化的进化批评模型），通过同步协同进化循环联合优化策略和批评模型。ECHO 使用级联 rollout：批评模型为初始轨迹生成多种诊断，再由策略进行修订，从而支持分组优势估计。针对学习平台期，我们采用感知饱和的收益塑形目标，奖励批评模型推动高表现轨迹的增量改善。通过双轨 GRPO 更新，ECHO 使批评反馈与变化中的策略保持同步。实验表明，ECHO 在开放世界环境中获得更稳定的训练和更高的长程任务成功表现。

</details>

<details>
<summary>现存问题</summary>

策略改进会改变错误分布；早期有效的宽泛建议可能无法处理后期细粒度缺陷，甚至引导错误修订。

</details>

<details>
<summary>已有方法的不足</summary>

冻结或脱离当前策略训练的 critic 难以持续适应；线性奖励差也可能低估接近满分时的小幅改善。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入任务、初始轨迹及外部评分，生成诊断组与对应修订轨迹组；策略按修订分数组内优势更新，critic 按饱和感知收益更新，持久改变双方参数。默认每题八条诊断及八条修订。论文在 WebShop、ALFWorld、SciWorld、DeepSearch 和两种模型上比较 GRPO、冻结 critic 等，并在两个环境做等采样预算的无批评重采样对照。各环境评分口径不同，不能都读作二元成功率；诊断遵循率排除了 UNCLEAR 样本，也不是因果根因准确率。

</details>

<details>
<summary>未来展望</summary>

作者提出未来合并奖励评估与批评生成；同时承认共享奖励源的噪声与偏差会同时误导双方。编辑推断：应加入独立评估器与冻结回归集，现有证据不足以排除共同迎合评分器。

</details>

**原始来源：** [ACL Anthology 正式论文](https://aclanthology.org/2026.acl-long.576/)

## 5. AgentDebugX: An Open-Source Toolkit for Failure Observability, Attribution, and Recovery in LLM Agents

**中文译名：** AgentDebugX：面向 LLM 智能体失败可观测、归因与恢复的开源工具包

**方向：** Task D · 2026-10-24 · 诊断证据与恢复

**今日研究优先级：** #5

- **日期：** 2026-07-21（arXiv 首发）
- **状态：** arXiv v1 预印本；官方仓库已核验；仓库所称 EMNLP Demo 尚无论文集确认
- **研究相关性：** 异构事件统一为保留来源的轨迹，形成结构化归因与修复指令，连接受控重跑和分支比较。
- **入选理由：** 历史高价值补充；有实质轨迹表示与归因—恢复实验，补足证据处理到执行验证的工程连接。

### 一句话概述

针对错误出现位置与致因步骤不一致的问题，AgentDebugX 将异构事件统一为可审计轨迹，通过多轮归因生成修复指令并连接受控重跑。

<details>
<summary>论文摘要翻译</summary>

LLM 智能体失败难以调试，因为错误显现的步骤往往并非引起错误的步骤。现有可观测工具能重放执行轨迹，却很少支持识别根因或将诊断转为恢复。我们提出开源调试框架 AgentDebugX，将调试组织为检测、归因、恢复和重跑的闭环。其核心 DeepDebug 通过全局轨迹理解、结构引导调查及交叉质询开展多轮根因诊断。在 Who&amp;When 基准上，DeepDebug 在两种测试的开放权重骨干上，均取得所比较方法中最高的严格归因准确率；在 qwen3.5-9b 上，Agent 与步骤同时精确命中的准确率为 28.8%，最强单轮基线为 21.7%。在 GAIA 上，DeepDebug 单次重跑修复 73 个失败任务中的 13 个，三种解耦自纠正基线修复 4—6 个，整体准确率由 55.8% 提升至 63.6%。AgentDebugX 通过 Python 库、CLI、网页控制台和可安装的智能体技能提供该流程，并提供可选择加入的 Error Hub，用于共享经过清理的失败—诊断—修复包，以及将其复用为调试记忆。

</details>

<details>
<summary>现存问题</summary>

错误症状可能晚于真正致因；框架各异的事件格式和与修复断开的诊断输出，阻碍证据追溯及验证。

</details>

<details>
<summary>已有方法的不足</summary>

单次全局阅读容易受下游症状影响，逐步扫描又可能丢失目标上下文；论文也发现托管模型上多轮归因并非总优于单轮。

</details>

<details>
<summary>当前方法为什么可行</summary>

输入 LLM/工具调用、handoff、GUI 等事件，归一化为含 Agent、步骤、父事件和原始输入输出的 AgentTrajectory；诊断另层保存，不改写原证据。DeepDebug 结合全局阅读、结构调查和质询，输出归因证据及重试指令，保存原始与修复分支。归因评测含 184 条 Who&amp;When 轨迹并提供任务参考答案；恢复在 GAIA 165 题中固定的 73 个失败题上各重跑一次，比较的是完整恢复方案，未隔离定位的单独贡献。Error Hub 和诊断记忆在实验中为空，故不构成持续自进化验证。

</details>
